Rent the loop, own the boundary.

The loop is any agent you already use. The gate sits in front of its tool calls, the floor runs it in a pane, the gateway sits behind its base URL. sprig is our own loop for when none of them fit, and it is the smallest thing that can hold the boundary.

part two

What holds

From the harness comparison and the cockpit research.

Auth decides, not language.Native tool use is a wire feature any language speaks. On a subscription, tools come from built-ins and MCP and the gate is a hook. On a key, you pass the tools yourself.
One gate interface, five transports.In-process, MCP bridge, hook, text, direct API. The boundary is the same object. Only the transport changes.
Every hook layer fails open, unless it chose not to.Hermes and OpenClaw block on error. pi's tool_call can return a reason. Everyone else lets the action through on a timeout. The gate assumes the worst.
A harness is a command and its args.Zed's protocol and JetBrains' registry agree. coppice's config is one line per harness, nothing more.
The transcript is a tree.An id and a parent id on every entry, a movable head, fork copies the path. pi and OpenHands have it. Claude Code stores it and cannot navigate it.

today

Proven live, on a subscription.

The table in the harness comparison is the whole story: five ways to drive a model, one boundary. The exposure freeze holds because four paths never need a key.

should be

Two more harnesses, one line each.

  • pi. coppice drives it as a pane over RPC, and an extension returns block and a reason on every tool call. Plan 04.
  • OpenCode. Headless over HTTP and SSE, gated by a plugin that can only throw. Plan 05.
  • Subagents as child rows. Claude Code's subagent hooks give the floor read-only children under the parent pane. They become real panes only when spawned through the floor.
