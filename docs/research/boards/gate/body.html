Allowed is not decided.

A model proposes an action. A verifier proves it stays inside an envelope before it runs. If the proof fails, the hook times out, or anything at all goes wrong, the action does not run.

envelope
What is allowedA checkable spec, generated by a model or inferred from evidence, reviewed by a person, registered per directory.
verifier
The proofZ3 in Python, mirrored in Rust, Go, TypeScript, and Lean, checked against each other on 11,450 cases.
hook
The tool-call boundaryPreToolUse in Claude Code, hooks.json in Codex. Exit 2 on any error, with a deadline under the host's timeout.

part two

What holds

From the cockpit research of 2026-08-27 and the multi-client rewrite. Each one is backed in those reports.

Fail closed inside the hook.Every harness hook layer lets the action proceed on timeout, crash, or bad JSON. Only an explicit exit 2 blocks. So the hook exits 2 on any internal error.
Intervene at the tool-call boundary.Steering text lands at the next boundary, not mid-action. The verdict rides in the tool result, never in the system prompt, so the cache prefix stays byte-stable.
The verdict carries its proof.Clause, proof id, counterexample. The operator sees why in checkable form, not a model's opinion.
Approve and remember mints a rule.Scoped once, session, project, or global. Proposed as an envelope edit. Never auto-applied.
Shadow before enforce.The gate watches first and reports what it would have denied. Enforce is a flag you turn on after reading that report.
Two implementations must both allow.The oracle always runs. A faster client may deny on its own. It may never allow what the oracle would not.

What ours is, and should be

Real screens from the CLI today, then the changes the floor work asks of the gate.

daisugi gate · today
$ daisugi gate --help
Call-time tool gate. Verify each live tool call against a registered
envelope. Shadow by default; --mode enforce denies.

  init       Generate and register a reviewable starter envelope
  check      Read one hook payload from stdin, emit the host's verdict
  register   Register the envelope the gate checks this session against
  disarm     Kill switch: the gate allows everything until re-armed
  arm        Remove the disarm marker
  status     Armed or disarmed, the verdict mode, the envelopes
  report     Summarize the shadow log: what enforce would have denied
  replay     Replay a captured session offline, nothing executes
  audit      Run the adversarial corpus, report both error rates
  serve      Run the resident gate in the foreground
  proposals  List recorded envelope-edit proposals

should be

Three changes the floor asks for.

  • Three tiers of allow. Silent inside the envelope, one key when undoable, type the pane name when permanent. The tier is a field on the verdict, so every porcelain shows the same shape.
  • The verdict on the roster row. The gate reports state to the floor as a source, beside hooks and screen manifests. A deny is what turns a row amber.
  • Verifier dispatch that fails loudly. Rust or Go when present, Python when not, and never a fallback to allow. Plan 11.

Nothing here moves the gate inside a porcelain. The foreman proposes. The envelope decides.
