# Omarchy as a home for openDaisugi

Date: 2026-09-23. Method: a multi-agent web search. Each claim was checked by three separate votes, and a claim stayed only if at least two votes kept it. Every claim below cites its sources.

## Question

Omarchy (DHH's opinionated Arch Linux + Hyprland setup, basecamp/omarchy) as a distribution target for openDaisugi, a local-first runtime-assurance gate for AI coding agents (Python today, with a Go terminal multiplexer "coppice"). Research: (1) What Omarchy is in 2026 — scope, governance, how packages/features are added (install scripts, bin/ scripts, menus, themes, AUR/pacman, "omarchy-*" commands), contribution process and what PRs get accepted or rejected, DHH/maintainers' stated taste and philosophy; (2) how AI coding agents / TUIs already ship in Omarchy (e.g. which agents or AI tools are preinstalled or offered, opencode/claude-code/crush, any "AI" menu), and any existing discussion about agent sandboxing, permissions or safety; (3) language/runtime preferences — does Omarchy prefer shell, Ruby, Go, Rust, single static binaries, pacman/AUR packages; is Python acceptable as a dependency; what would be needed to package openDaisugi (AUR PKGBUILD, a static binary) and whether a Rust or Go rewrite would matter; (4) concrete path: smallest acceptable contribution (e.g. an optional install entry, an AUR package, a menu item) vs. what would be rejected. Cite source URLs for every claim.

## Summary

Omarchy in September 2026 is a large bash codebase (about 459 omarchy-<group>-<verb> scripts in bin/, all with #!/bin/bash shebangs, plus a QML shell). Maintainers add features as scripts with metadata headers, grouped by prefixes such as install-, launch-, pkg- and agent-. Coding agents are now first-class. v4.0.0 (2026-08-14) added a configurable default agent from a curated list that grows over time (Claude Code, Codex, OpenCode, Crush, Pi, OMP, Grok, Copilot, Cursor CLI, Muse, OpenClaw, Hermes and others). Each agent is a lazy mise-managed stub, launched by a keybinding or menu entry, and most run in approval-bypass modes. Omarchy ships no sandbox, gate or permission layer. Its only safety steps are small: no trust for $HOME (the agent starts in ~/Work instead), Claude and Codex moved from full bypass to auto-review in v4.0.1, and 'omarchy reinstall configs' for rollback. A community thread that asked which agent actions are safe got no maintainer answer. For openDaisugi, the paths that need no PR to core are the cheapest: an AUR PKGBUILD that users install through Install > AUR, an 'omarchy-mise-install' wrapper once the tool is on PyPI or GitHub releases, or a third-party git plugin (but plugins are bar widgets only). Python is not banned, but it is not Omarchy's implementation language. So any contribution to core would have to be thin bash scripts that call an external package. The evidence shows maintainers accept mainstream agent integrations. It does not show whether they would accept a safety gate.

## Findings

### 1. Omarchy's own code is bash. Scripts use #!/bin/bash (never /usr/bin/env bash) and bash 5 conditionals. Features ship as about 459 scripts in bin/ named omarchy-<group>-<verb>, and each one has '# omarchy:summary=' and '# omarchy:args=' comment headers. The official group list is GROUP_DESCRIPTIONS in bin/omarchy. The families include install-, remove-, launch-, menu-, pkg-, plugin-, theme-set-, agent- and default-.

Confidence: high. Vote: 3-0 (claims 0, 1, 2 merged).

Evidence: AGENTS.md: 'Shebangs must use #!/bin/bash consistently (never #!/usr/bin/env bash)'; 'The authoritative command group list lives in bin/omarchy in GROUP_DESCRIPTIONS.' Verifier counted 459 bin/ entries on the default branch quattro (d3cfd53): 454 bash and 5 python3. The repo's language mix is Shell 3.1MB, QML 1.3MB and Python 134KB. The only other .py files are Nautilus extensions. Votes 3-0 on all three claims.

Sources:
- https://github.com/basecamp/omarchy/blob/dev/AGENTS.md
- https://github.com/basecamp/omarchy/tree/master/bin

### 2. Coding agents are a first-class feature. omarchy-default-agent picks from a fixed, curated list: pi, omp, opencode, ori, claude, codex, grok, openclaw, agy, hermes, copilot, crush, cursor-agent and muse. The choice is stored in ~/.config/omarchy/defaults/agent. Omarchy leaves it unset until the user picks one. Other interface points: Setup > Defaults > Agent in the menu, the Super+Shift+Ctrl+A keybinding, 'omarchy agent prompt', 'omarchy agent crash <pid>', and an Agents usage panel that 'omarchy agent usage-update' refreshes.

Confidence: high. Vote: 3-0 (claims 3, 7, 10 merged).

Evidence: Script header: '# Silent when unset rather than defaulting: Omarchy picks no agent for you'. An unknown value falls through to usage output and exit 1. The manual documents the keybinding, the menu path and the prompt, crash and usage-update commands. v4.0.0 (2026-08-14): 'Add a configurable default coding agent'. Votes 3-0.

Sources:
- https://github.com/basecamp/omarchy/tree/master/bin
- https://omarchy.org/manual/ai/
- https://github.com/omacom/omarchy/releases

### 3. Agents ship as lazy stubs, not as preinstalled binaries. Each is a small mise-managed stub in ~/.local/bin/ that downloads on first run. The generic tool 'omarchy-mise-install <package> [command-name]' wraps any CLI the same way. This gives openDaisugi a small route with no PR, but only after openDaisugi is published to a backend mise can fetch from, such as PyPI via pipx or GitHub releases.

Confidence: high. Vote: 3-0 (claims 5, 6 merged).

Evidence: Manual: 'tiny mise-managed stubs in ~/.local/bin/ ... Additional CLIs can wrap via omarchy-mise-install <package> [command-name]'. The stub runs 'mise use -g --quiet <package>' and then 'exec mise x <package> -- <bin>'. The package field can also be an npm:, github:, mise-registry or http: spec. Votes 3-0.

Sources:
- https://omarchy.org/manual/ai/
- https://github.com/basecamp/omarchy/tree/master/bin

### 4. The default posture is unattended agents with approval bypassed. There is no sandbox or gate. DHH's PR #6729 (merged 2026-08-12) launched every default agent with its permissions bypassed. v4.0.1 (2026-08-25, PR #7001) moved only Claude (to '--permission-mode auto') and Codex (to --approve-for-me with the workspace-write sandbox) to auto-review. Grok, OpenCode (--auto), Crush (--yolo), agy, cursor-agent (--yolo --trust) and Hermes (--yolo) still bypass approval. The manual warns that agents 'run unattended in their respective don't-stop-to-ask modes'.

Confidence: high. Vote: 3-0 (claims 11, 13 merged).

Evidence: PR #6729 body: 'the launcher now starts each one with permission prompts bypassed'. Release v4.0.1: 'Launch claude and codex agents with auto-review instead of full bypass'. The verifier read the current flags in bin/omarchy-agent. PR #6757 renamed omarchy-launch-agent to omarchy-agent, which is why a claim that named the old script was refuted. Votes 3-0.

Sources:
- https://github.com/basecamp/omarchy/pull/6729
- https://github.com/omacom/omarchy/releases
- https://omarchy.org/manual/ai/

### 5. The documented safety steps are small. Agents do not keep trust for $HOME, so a launch from home starts in ~/Work. The Omarchy Skill is experimental: users should run it in plan mode first and roll back with 'omarchy reinstall configs'. The manual names no sandbox, container, permission prompt or allow/deny list. Maintainers do respond to permission issues in small steps (the Claude/Codex auto-review change, and PR #8056 making docker-group membership opt-in). This is a real gap, but no source shows that maintainers want a gate.

Confidence: medium. Vote: 2-1 (claim 8, with context from claim 11).

Evidence: Manual: 'Agents refuse to remember trust for your home directory ... run in plan mode first ... omarchy reinstall configs'. The vote was split 2-1, and the claim covers only one manual page that changes often.

Sources:
- https://omarchy.org/manual/ai/
- https://github.com/omacom/omarchy/releases

### 6. The only public discussion of agent safety is unresolved. Issue #2370 (parnoldx, 2025-10-11) proposed omarchy-config-agent, which ran in 'yolo mode' with only diff, approve and rollback as safety. It had no rollback method chosen yet (btrfs snapshots or undo scripts were open ideas), and allow/disallow tool lists were only a later idea. It asked which actions are safe: window-manager config yes, package installs 'probably?', boot and kernel parameters 'scary?'. DHH closed it on 2026-02-01 and pointed to the default omarchy skill in OpenCode. He did not answer the safety questions.

Confidence: medium. Vote: 3-0 (claims 16, 17 merged).

Evidence: 'Permissions are in yolo mode right now. In production possibly more usage of Allow or Disallow Tools'; 'Or is show diff + require approval + rollback enough safety for everything?' The thread has two comments and neither is about safety. This is a single source that records one contributor's view, not policy. Votes 3-0.

Sources:
- https://github.com/omacom/omarchy/issues/2370

### 7. The project accepts new agent integrations from outside contributors. v4.0.3 (2026-09-08) added OpenClaw and Hermes (by @spencerbull and @smfworks), Cursor CLI (@cavanaug with @dhh), Muse Code and T3 Code. Every accepted item is a mainstream agent or desktop app. None is a safety or gate layer.

Confidence: high. Vote: 3-0 (claim 12).

Evidence: Release notes: 'Add OpenClaw as a desktop app and default coding agent ... Add Hermes Desktop and terminal-agent integration ... Add Cursor CLI ... Add Muse Code'. Hermes and OpenClaw have dedicated installers (omarchy-install-hermes-cli, omarchy-install-openclaw-cli). That is the shape a core openDaisugi entry would take. Votes 3-0.

Sources:
- https://github.com/omacom/omarchy/releases
- https://github.com/omacom/omarchy/releases/tag/v4.0.3

### 8. Distribution without a PR to core works today. Users install any Arch package with Install > Package (Super+Alt+Space) or 'omarchy pkg add', and any AUR package with Install > AUR. The manual says the AUR is 'not vetted by the Arch team' and compares it to RubyGems or npm. It does not forbid the AUR. An AUR PKGBUILD (Python with z3 and numpy, plus a Go coppice binary) is the most realistic first step, because official Arch repos need a Package Maintainer to adopt the package.

Confidence: high. Vote: 3-0 (claims 9, 14, 15 merged).

Evidence: Manual: 'You install a new Arch package by going to Install > Package in the Omarchy menu (Super + Alt + Space)'; 'You can do the same with AUR, just use Install > AUR'; 'the AUR isn't vetted by the Arch team'. A claim that gave the menu key as Super+Space was refuted 1-2. Votes 3-0 on the kept claims. The 'low-cost' part is a judgment.

Sources:
- https://omarchy.org/manual/other-packages/
- https://learn.omacom.io/2/the-omarchy-manual/66/other-packages

### 9. A third-party git plugin system exists (omarchy-plugin-add, -enable, -catalog and -validate). Plugins clone into ~/.config/omarchy/plugins, and the user must confirm unless --yes is passed. Plugins are only bar or bar-widget extensions for the QML omarchy-shell, and they run unsandboxed. The omarchy.* ID namespace is reserved for first-party plugins. openDaisugi could use this only for a status widget, for example gate or coppice attention state, and not to install itself.

Confidence: high. Vote: 3-0 (claim 4).

Evidence: '# omarchy:summary=Add a shell plugin from git ... PLUGINS_DIR=$HOME/.config/omarchy/plugins'. The script warns: 'Plugins run as arbitrary, unsandboxed code inside your long-lived omarchy-shell process'. The script is present in v4.0.2 to v4.0.4. Votes 3-0.

Sources:
- https://github.com/basecamp/omarchy/tree/master/bin

### 10. Language fit: Python is allowed at the edges (5 python3 scripts in bin/ and Nautilus extensions), so it is not a blocker for an external package. But Omarchy itself is bash, and agents come as single binaries or npm/GitHub releases through mise. A Go or Rust static binary would fit the mise github: backend and the AUR more cleanly than a Python app with z3 and numpy. The evidence does not show that a rewrite is required.

Confidence: medium. Vote: derived from claims 0, 2, 3, 6.

Evidence: This is an inference from the shebang counts, the languages API figures, and the agent_package specs (github:, npm:, http:). No source states a policy on Python dependencies.

Sources:
- https://github.com/basecamp/omarchy/blob/dev/AGENTS.md
- https://github.com/basecamp/omarchy/tree/master/bin
- https://omarchy.org/manual/ai/

## Caveats

Time sensitivity is high. Omarchy put out four releases between 2026-08-14 and 2026-09-15, and both the agent list and the launch flags changed within days (PR #6729, then #6757, then #7001). Present-tense statements about flags should be rechecked before anyone relies on them. Repo naming is inconsistent: basecamp/omarchy redirects to omacom/omarchy, the default branch is now 'quattro', and sources cite master and dev. Several claims about install internals were refuted 0-3: the base.sh manifest, omarchy-pkg-add as the required wrapper, migration rules, and the omarchy-launch-agent name. So how a package gets into Omarchy's preinstalled set is not established. The claim that OpenCode is the default agent was also refuted, because Omarchy now picks no default. Evidence on contribution taste (what PRs get rejected, DHH's stated philosophy) is thin. No rejected PR or written acceptance policy survived verification. The safety-discussion evidence rests on one closed issue with no maintainer engagement. The claim about the manual's safety content had a split 2-1 vote. The advice to prefer a Go/Rust binary is inference, not a sourced Omarchy policy.

## Openquestions

- Would maintainers accept a core PR that adds an optional gate (for example omarchy-install-daisugi, or a gated launch mode in omarchy-agent), given that they deliberately chose unattended bypass modes and moved only Claude and Codex to auto-review?
- What is the written or observed policy for rejecting PRs (new dependencies, Python tools, niche tools), and how does a package get into the preinstalled base set, now that the base.sh manifest claims were refuted?
- Can openDaisugi's gate hook into agents launched by omarchy-agent without changing their flags, for example through ~/.claude settings hooks or OpenCode plugins that survive 'omarchy reinstall configs'?
- Is a Go static build of coppice plus a slim Python gate (or a full Go gate) needed to fit mise's github: backend, or does a pipx/PyPI backend work reliably through omarchy-mise-install?
