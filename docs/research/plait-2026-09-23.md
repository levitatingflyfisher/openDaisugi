## What it is

Plait is one person's tool for running Claude Code sessions across many
repositories. It is a FastAPI server with SQLite and a React web page.
Sessions are real `claude` processes on PTYs, shown in xterm.js. The web
page is the main interface, and "open in VS Code" is the way out.

The author's words: "I fully expect Plait to be obsolete within 12 months."

Its units:

- **Worktop.** One repository, one git worktree, one branch, at most one
  PR, and many sessions. It is archived when its PR merges.
- **Slate.** A change across many repositories. An orchestrator session
  reads a read-only checkout of main for each repository, then creates
  one worktop per repository through an HTTP hook.
- **Tend.** A daemon polls each open worktop every 5 minutes, with
  backoff when nothing moves. When the branch is behind main, it merges.
  On a merge conflict, a failed CI run, or a new `@claude` PR comment
  from the author, it starts a Claude session to fix it. A PR gets a
  5-minute cooldown after activity, so reviewers can finish first.

## Mechanisms worth knowing

1. **Local files follow the worktree.** Untracked files under `.claude/`
   and `.vscode/` are copied into each new worktree. Each repository can
   also list globs of gitignored files, such as `.env`. A glob that
   matches nothing, or that matches a tracked file, is refused when the
   config is saved and fails worktree creation with rollback.
2. **Instructions in the worktree.** At creation, Plait writes
   `CLAUDE.local.md` into the worktree. Any session there gets the
   instructions, whether Plait started it or not.
3. **Sessions call back over HTTP.** A session reports `done`,
   `pr-created`, `branch-updated` and `ci-failure-expected`. The last one
   stops a failed CI run from starting a tend until the branch head
   moves.
4. **Auto-naming.** A haiku call through `claude -p` names a worktop from
   its commits and transcripts. The user can rename it. Clearing the name
   asks for a new one.
5. **Review a PR locally.** A Chrome extension adds "Review locally" to PR
   pages. It checks the PR head out into a throwaway worktree that can
   push back, opens it in VS Code, and starts a session primed with the
   diff. On issue pages it adds "Open in plait".
6. **Crash-safe transcript.** The transcript goes to the database every 2
   seconds, and the raw terminal state is kept on exit for replay.
7. **Guard rail.** Every session runs with
   `--dangerously-skip-permissions`. One PreToolUse hook denies
   `gh pr comment`, `gh issue comment` and `gh pr review`, because hooks
   still fire in that mode.

## Verdicts for coppice

- **Steal: local files follow the worktree.** Copy the untracked files
  under `.claude/` into a task's worktree, plus opt-in gitignored globs.
  Fail loudly on a glob that matches nothing or matches a tracked file.
- **Steal: the upstream watcher.** A policy plugin can watch a task's
  branch for behind-main, conflict, CI failure and new review comments,
  and open a pane to fix it. Unlike Plait, that pane runs under the
  gate, and its asks go to the task's foreman first. Keep the cooldown
  and the "failure expected until head moves" signal. Our `daisugi tend`
  already means distillation, so this needs another name.
- **Steal: auto-naming.** Name an unnamed task from its commits and
  transcripts with one small model call. Never rename a task the
  operator named.
- **Steal: review a PR locally.** A throwaway worktree of a PR head and a
  pane primed with the diff, from one command.
- **Watch: slates.** One orchestrator across many repositories, with
  read-only checkouts of main. Our tasks hold one repository each.
- **Watch: instructions written into the worktree.** A foreman or a task
  could write its brief to `CLAUDE.local.md`. Any pane in that worktree
  then reads it.
- **Avoid: skip-permissions with one narrow hook.** Plait's only guard
  is a denylist of three commands. Ours is the gate. The rule "never
  speak for the operator on GitHub" still belongs in our gate as a
  permanent ask.
