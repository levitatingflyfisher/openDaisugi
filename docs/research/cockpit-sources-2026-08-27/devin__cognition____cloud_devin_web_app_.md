# Devin (Cognition) — cloud Devin web app, Devin CLI ("Devin for Terminal"), Devin MCP server, DeepWiki/Ask Devin, Devin Review. Facts as of 2026-08-27.


## interactionModel
Two surfaces. (1) Cloud web app: each session is an isolated VM with a right-hand panel of tabs: Progress (unified log of shell commands, file edits, browser activity; click any step to jump to it), Shell (command history, toggle terminal read-only -> writable), Desktop (interactive browser for auth/CAPTCHA), Editor (VS Code-style IDE; "stop the session to take over"), and Side Chats (read-only questions that do not interrupt the main run). Gating is plan-level, not action-level: interactive planning (3/25/2025 'click "Wait for my approval" so that Devin waits for your feedback on its full plan'; 3/19/2026 'Devin shows you its plan before executing, and you can approve'). Screen recordings with annotations and auto-zoom are attached to messages as merge evidence. Supervision of many sessions is a sidebar list (pin, folders, archive-all, 'Start session in background' 6/24/2026, redesign 8/21/2026 with 'customizable nav tabs, grouping, richer filtering'), plus per-session t-shirt size XS-XL computed from ACU only (7/15/2026), Session Insights (Issue Timeline, Actionable Feedback, Knowledge Usage), and Devin Coach (8/14/2026) that flags wasteful prompts below the input box (admin setting: confirm-required / warn-only default / off). Modes switch mid-session via an agent toggle or Slack prefixes !ultra/!fast/!lite/!fusion/!swe/!normal. (2) CLI: a Claude-Code-shaped REPL with six permission modes (normal, accept-edits, smart, plan, bypass aka /yolo, autonomous which requires --sandbox), Shift+Tab cycles modes, read-only tools never prompt (v2026.4.9-0). The approval prompt offers allow once / for session / for project (.devin/config.json) / project-local / globally / edit the command first / ask for a plain-language rewrite. Rules use Read(src/**), Write(...), Exec(npm run), Fetch(url), mcp__server__tool; precedence deny > ask > allow > default prompt. A tray panel has Cloud agents and Subagents tabs (x kills the selected subagent). /btw opens a side chat in parallel; Ctrl+O opens the thinking trace; /handoff ships repo+branch+conversation+uncommitted diff to a cloud session.


## caching
Cloud Devin: not documented. Cost is metered in ACUs (VM time + inference + bandwidth, ~15 min of active work) so token-level cache behaviour is invisible to the operator; no statement about prefix stability. CLI is explicit: the Adaptive router page says 'Staying on the same model across turns in a conversation enables caching, which significantly reduces input token costs. Adaptive takes this into account when routing', with self-serve rates $0.50/M input, $2.00/M output, $0.10/M cached reads (through July 7 2026). Changelog v3000.5.20 (Aug 21 2026): 'Image-heavy sessions no longer invalidate the provider prompt cache on every request once the trailing-image cap is reached' and 'Long conversations are compacted earlier in the background'; v2026.4.30-0 added a post_compaction hook with the summary on stdin; v3000.3.22 stopped surfacing automatic compaction in scrollback. Fusion (June 29 2026): main and sidekick models each keep 'their own persistent, cached contexts' rather than one shared cache, and model switches are scheduled 'during context compaction, which would trigger a cache miss anyway'. SWE-1.7 (July 8 2026) is trained for 'self-compaction'. Per-step context re-send is avoided structurally: subagents run in their own context window and the parent only reads a summary; the SWE-grep Fast Context subagent returns 'a list of files with line ranges' (not summaries) to 'save on (valuable) agent tokens and avoid polluting the agent's context' after finding >60% of first-turn time was retrieval. /context shows context-window usage; /usage shows estimated credit/ACU for the session.


## extensions
CLI (project .devin/, user ~/.config/devin/): config.json + config.local.json (permissions, read_config_from), hooks.v1.json with eight events PreToolUse, PostToolUse, PermissionRequest, UserPromptSubmit, Stop, PostCompaction, SessionStart, SessionEnd (non-zero exit blocks; JSON {"decision":"block","reason":...}; PreToolUse may return updatedInput; UserPromptSubmit/SessionStart may inject additionalContext; per-hook timeout in seconds; hooks receive session_id and per-turn prompt_id), skills/<name>/SKILL.md (frontmatter name, description, allowed-tools, triggers user|model, model; '.agents skills standards' supported; invoked as /name or autonomously), agents/<name>.md subagent profiles (model, allowed-tools, max-nesting), AGENTS.md/AGENT.md/CLAUDE.md rules, automatic import of .cursor/rules, .windsurf/rules and .claude/ (commands, subagents, hooks). Plugins: .devin-plugin/plugin.json (only name required), sources github / git URL / local / git-subdir, contribute skills, rules, agents, hooks.json, mcpServers; requiredPlugins / optionalPlugins / forbiddenPlugins with deny-wins across enterprise/org/repo/user; `devin plugins install|update|list`. MCP: mcp_config.json, MCP prompts, config import from OpenCode/VS Code/Zed. Cloud: Playbooks (.devin.md, sections Overview / What's Needed From User / Procedure / Specifications / Advice / Forbidden Actions; !macro; versioned; community gallery; can pin a Devin mode and a structured-output JSON schema), Knowledge (trigger description + content + optional !macro, repo pinning, Devin-suggested from chat feedback, folders, retrieved 'when relevant, not all at once'), MCP marketplace (48+ servers, OAuth, personal vs org scope, Security Profiles GA 8/7/2026), Automations and Scheduled Sessions, Dynamic Workflows (Python SDK: register_workflow, agent(prompt, schema), pipeline, parallel), Outposts (self-hosted worker queues; atomic claim, 409 on race). Devin MCP server at https://mcp.devin.ai/mcp exposes devin_session_create/search/interact/events/gather, devin_playbook_manage, devin_knowledge_manage, devin_schedule_manage, plus read_wiki_structure/read_wiki_contents/ask_question.


## multiAgent
Cognition's public position moved from 'Don't Build Multi-Agents' (June 12 2025: share full traces not messages; actions carry implicit decisions; serial execution) to 'Multi-Agents: What's Actually Working' (April 22 2026): the single-writer principle ('writes stay single-threaded and the additional agents contribute intelligence rather than actions') with three patterns: Code-Review-Loop (a clean-context reviewer catches ~2 bugs per PR, 58% severe, and works better WITHOUT the coder's context because of 'context rot'), Smart Friend (only works when both models are frontier-level), and Map-Reduce-and-Manage (manager splits, children execute in their own VMs, manager synthesizes via an internal MCP; full context fork to children; unstructured swarms rejected). Shipped as Managed Devins (March 19 2026): the coordinator 'scopes the work, assigns each piece to a managed Devin, monitors progress, resolves any conflicts, and compiles the results'; each child has its own VM and session link; the parent can message, sleep, terminate, set an ACU limit per child, schedule check-in messages to itself, and 'read the full trajectories of its managed Devins'. CLI subagents: foreground (parent waits) or background (parallel); built-ins subagent_explore (read-only, SWE-1.6 fast) and subagent_general; a subagent 'does not inherit the parent's conversation history' and 'consume[s] cost independently'; interrupting the parent pauses them. Deterministic alternative: Dynamic Workflows orchestrate sessions from a Python script with structured-output schemas ('one run can consume far more ACUs than doing the same task in a single session'). Latent Space (May 28 2026): children get 'their own boxes not sharing machines, so there's very little room for conflict', and 'most practical use remains single Devin'.


## forkTimeTravel
- supported: yes (CLI, step-granular); partial (web, checkpoint-level, thinly documented). CLI /steps, /fork [step], /revert <step> since v2026.4.9-0; web 'Checkpoint and rewind' since 3/19/2026.
- ux: CLI: /steps lists conversation steps; /fork [step] 'Fork the current session to a new session. Optionally fork from a specific step' (defaults to latest step); /revert <step> 'Revert file changes from a specific step onwards and rewind the conversation' with an interactive searchable step picker (v2026.4.24-1); steps from before compaction remain visible and usable by /steps, /revert and /fork (v2026.5.5-0); an ACP revert can cancel an active turn before rewinding; /continue [id], /resume (picker), /ls --all, /rm-session <id>, /title. Files and conversation rewind together in one command. Web: release note 3/19/2026 says 'Checkpoint and rewind - Save progress at any point and return to it later' and (first extraction) 'Checkpoint your progress with named snapshots you can rewind and fork from ... Fork sessions from any checkpoint, branching work into parallel explorations'; no keys or menu path are documented and no dedicated doc page exists in the docs index. The web 'Start a New Session with This Prompt' (5/6/2026, replaced 'duplicate session') copies the prompt only, not state.
- dataModel: CLI: transcripts at ~/.local/share/devin/cli/transcripts/*.json in the ATIF-v1.4 trajectory schema (root: session_id, agent.model_name, steps[]; per step: step_id, metadata.committed_acu_cost (per step, not cumulative), metadata.metrics.input_tokens/output_tokens, created_at, generation_model, request_id) plus ~/.local/share/devin/cli/sessions.db for enrichment; profiles in ~/.config/devin/config.json. --export [PATH] writes ATIF after each turn (v2026.5.26-0, with telemetry and timing). Session ids are word-pairs like 'brisk-otter' / 'devin-abc123'. Parent/branch pointers for forks are NOT documented; the ATIF paths and field names come from a third-party usage-monitor doc, not Cognition docs. Web/VM: rollback rides on blockdiff (June 23 2025): a .bdiff file of CoW extents (FIEMAP) holding only blocks that differ from the base vm.img, ~200 ms for a 20 GB disk, 'incremental snapshots stacked on top of each other' for disk rollback and sleep/wake; machine snapshots (2024) are named start states with startup commands. How the web checkpoint pairs a VM snapshot with the conversation state is not documented.


## steal
- **Step is the unit of time travel: /steps enumerates, /fork [step] branches to a new session, /revert <step> rewinds files AND conversation in one command, and step ids survive compaction.** — daisugi's prompt tree needs one addressable id per turn that the journal, the gate verdicts and the workspace snapshot all key on; keeping pre-compaction steps addressable is exactly the trap most harnesses fall into. [https://docs.devin.ai/cli/reference/commands]
- **Per-step committed cost in the trajectory file (metadata.committed_acu_cost, input/output tokens, generation_model, request_id per step) with /usage, /context and /session-stats as live readouts.** — The cockpit's per-step budget column falls out of the journal for free if every step carries its own cost; no second ledger to reconcile. [https://github.com/DatekWireless/ai-usage-monitor/blob/main/docs/providers/devin.md]
- **Hook lifecycle with a first-class PermissionRequest event and PreToolUse that can return updatedInput; non-zero exit blocks; PostCompaction delivers the summary on stdin.** — daisugi's Z3 gate maps onto PermissionRequest/PreToolUse directly, and updatedInput lets the gate narrow an action instead of only denying it; PostCompaction is the hook a cache-aware cockpit needs to know the prefix just changed. [https://docs.devin.ai/cli/extensibility/hooks/lifecycle-hooks]
- **Approval prompt with scoped persistence (once / session / project / project-local / global) plus 'edit command before approving' and 'plain-language rewrite', backed by deny > ask > allow rule precedence.** — Turns each allow/deny into a reusable envelope refinement; the operator grows the envelope from the prompt instead of editing a policy file, and deny-wins precedence matches fail-closed. [https://docs.devin.ai/cli/reference/permissions]
- **Session Insights 'Knowledge Usage' tab that labels each retrieved item Useful or Misleading with an explanation, next to an Issue Timeline.** — The garden view should show per-run which pathway helped and which hurt; that is the feedback loop that lets pathways be pruned, not just counted. [https://docs.devin.ai/product-guides/session-insights]
- **devin_session_gather ('wait for multiple sessions to reach a settled state') plus deterministic Dynamic Workflows that fan results in through structured-output JSON schemas.** — Fan-in without an LLM manager keeps multi-agent overhead at zero tokens; a gather primitive is also the natural cockpit event for 'these N gated agents are all blocked or done'. [https://docs.devin.ai/work-with-devin/devin-mcp]
- **Fusion's cache rule: each model keeps its own persistent cached context, and model switches are scheduled at compaction boundaries where the cache is already lost; retrieval subagents return file+line ranges, not summaries.** — Concrete cache-aware routing law for daisugi: never swap model or prefix mid-run, only at a boundary you were going to pay for anyway; keep helper output out of the main prefix. [https://cognition.com/blog/devin-fusion]

## avoid
- **A composite opaque cost unit (ACU = VM time + inference + bandwidth), repriced four times in 18 months and dropped for self-serve in April 2026, with no refund on failed sessions.** — Operators cannot map it to anything they control; HN: 'ACU are entirely too opaque/confusing/complicated'. daisugi should meter what the operator can see (tokens, cache hits, gate verdicts) and keep one unit. [https://ailimit.watch/tools/devin/]
- **Features announced in release notes with no reference page: web 'Checkpoint and rewind' (3/19/2026) has no doc in the docs index, and the usage page says 'no hard per-session caps' while release notes announce 'Session ACU Hard Caps'.** — Fork/time-travel is a data-model contract; if it is only a changelog line, nobody can build on it. Ship the schema doc with the feature. [https://docs.devin.ai/release-notes/2026]
- **Autonomy with no stuck detector: Devin would 'work away for literally _days_ on a task where any human would admit they were stuck', and the review burden exceeded that of a competent human.** — A supervision cockpit needs a cheap 'no progress' signal per agent (repeated denies, same file churn) more than it needs richer logs; budget caps arrived only in 2026. [https://news.ycombinator.com/item?id=42734681]
- **LLM-manager fan-out as the default: subagents 'consume cost independently', nesting multiplies, and a workflow 'can consume far more ACUs than doing the same task in a single session'; Cognition itself says most practical use is still a single Devin.** — For daisugi keep orchestration deterministic and gate-driven; spawn only when the envelope proves the pieces are independent. [https://docs.devin.ai/cli/subagents]
- **Hiding automatic context compaction from the scrollback (v3000.3.22) while it is the event that invalidates the prompt cache and the moment Fusion swaps models.** — A cache-maximizing cockpit must show prefix resets as first-class events; hiding them for tidiness removes the one signal the operator needs to explain a cost spike. [https://docs.devin.ai/cli/changelog/stable]

## verification
- [confirmed] Devin CLI has /steps, /fork [step] ('Fork the current session to a new session. Optionally fork from a specific step') and /revert <step> ('Revert file changes from a specific step onwards and rewind the conversation'), plus --export [PATH] in ATIF format after each turn. — The cited page lists verbatim: '/steps' = 'List conversation steps (use with /fork and /revert)'; '/fork [step]' = 'Fork the current session to a new session. Optionally fork from a specific step (see /steps).'; '/revert <step>' = 'Revert file changes from a specific step onwards and rewind the conversation to before that step'; '--export [PATH]' = 'Export conversation to a file after each turn (ATIF format). Uses a default path if none is provided.' The CLI changelog (https://docs.devin.ai/cli/changelog/stable, latest v3000.6.2, 24 Aug 2026) dates these: v2026.4.17-0 (17 Apr 2026) 'Added /revert <step>', 'Added /steps', 'Added optional [step] argument to /fork', '--export flag for exporting conversation history in ATIF format'; v2026.4.24-1 '/revert with no arguments now opens an interactive searchable picker'; v2026.5.5-0 '/steps, /revert, and /fork now show and work with steps from before compaction'; v3000.5.20 (21 Aug 2026) 'Completed ask_user_question prompts now appear as /steps entries that you can revert to or fork from.' Design-relevant caveats (not contradictions): a fork is a NEW session with its own ID, not a branch inside one session tree; there are no /checkpoint, /rewind, /branch or /tree commands; ATIF is never expanded on the page and the --export default path is not stated; the page says nothing about whether /revert is reversible.
- [qualified] Devin CLI hooks fire on PreToolUse, PostToolUse, PermissionRequest, UserPromptSubmit, Stop, PostCompaction, SessionStart, SessionEnd; a non-zero exit blocks the action, PreToolUse can return updatedInput, and PostCompaction receives the compaction summary. — The cited lifecycle page documents exactly the eight events named. It states 'A hook can transparently rewrite the tool's input by printing hookSpecificOutput.updatedInput to stdout' (PreToolUse only), and PostCompaction's input has 'summary' = 'Summary text produced by the compactor (may be null if no summary was generated)'. The changelog (v3000.3.22, 29 Jul 2026) adds 'post_compaction hook event that fires after context compaction, with the compaction summary available on stdin' and 'SessionEnd lifecycle hooks now run when a session ends, with a reason matching Claude Code's vocabulary'. The exit-code part is contradicted by the hooks overview page (https://docs.devin.ai/cli/extensibility/hooks), whose Exit Codes table reads verbatim: '0 | Success — hook continues normally', '2 | Block — action is denied', 'Other | Error — logged but doesn't block'. (The same page also has a looser sentence 'can block the action by returning a non-zero exit code', but the table is the precise spec and the lifecycle page's only blocking example uses sys.exit(2).) Blocking is shown for PreToolUse (exit 2), PermissionRequest ({'decision': 'approve'}) and Stop ({'decision': 'block', 'reason': ...}); UserPromptSubmit/SessionStart/PostCompaction examples only inject additionalContext. Hook config lives in .devin/hooks.v1.json (or a 'hooks' key in .devin/config.json / .claude/settings.json); matchers are regex over tool_name; an optional 'timeout' (seconds) exists but timeout fail-open/closed behaviour is not documented. The permissions page (https://docs.devin.ai/cli/reference/permissions) defines Normal / Accept Edits / Smart / Bypass ('All tool calls are auto-approved without prompting') / Autonomous modes and never mentions hooks, so hook-vs-Bypass interaction is unverified. → corrected: Devin CLI hooks fire on PreToolUse, PostToolUse, PermissionRequest, UserPromptSubmit, Stop, PostCompaction, SessionStart, SessionEnd. Only exit code 2 blocks the action; any OTHER non-zero exit is 'Error — logged but doesn't block' (i.e. a crashing or timing-out gate hook fails OPEN). PreToolUse can rewrite tool input via hookSpecificOutput.updatedInput, and PostCompaction receives a 'summary' field that may be null. The docs do not state whether PermissionRequest/PreToolUse hooks still gate actions under the 'Bypass' permission mode, where 'All tool calls are auto-approved without prompting'.
- [confirmed] The Devin MCP server exposes devin_session_create (with per-session ACU limit), devin_session_search, devin_session_interact, devin_session_events (list/fetch/search events) and devin_session_gather ('Wait for multiple sessions to reach a settled state'). — The cited page lists, verbatim: devin_session_create = 'Create one or more Devin sessions. Each session can have a prompt, title, playbook, tags, and ACU limit'; devin_session_search = 'Search and filter sessions by tags, playbook, origin, schedule, user, or creation/update time'; devin_session_interact = 'Interact with a session — get status, send messages, sleep, terminate, archive, read messages and attachments, or manage tags'; devin_session_events = 'Inspect events within a session — list summaries, fetch full event details, or search event contents by text'; devin_session_gather = 'Wait for multiple sessions to reach a settled state (finished, errored, sleeping, or waiting) before returning'. The per-session ACU limit is corroborated by the REST API reference (https://docs.devin.ai/api-reference/sessions/create-a-new-devin-session): 'max_acu_limit (integer | null) — Maximum ACU limit, must be positive'. Additional context: the same server also exposes DeepWiki tools (read_wiki_structure, read_wiki_contents, ask_question, list_available_repos) plus devin_playbook_manage, devin_knowledge_manage, devin_schedule_manage and list_integrations; it is reached at https://mcp.devin.ai/mcp with a Bearer API key (service-user or cog_ personal token), the legacy SSE endpoint is deprecated, and no timeout/polling parameters are documented for devin_session_gather.
- [qualified] Fusion runs a frontier main agent and a cheaper sidekick that each keep 'their own persistent, cached contexts', and model switches happen 'during context compaction, which would trigger a cache miss anyway'. — The post, 'By The Cognition Team 06.29.26', says: 'The key idea behind our architecture is to run two parallel agents: one with a frontier model, the other with a more cost-effective "sidekick" model.' and 'Both are fully capable agents with their own toolsets and ability to gather & act on their own context.' It explicitly names 'the two techniques that make it all work: the "sidekick" approach and dynamic mid-session routing'. The exact quotes in the claim exist: 'In the sidekick setup, both the main model and sidekick model maintain their own persistent, cached contexts.' and 'We accomplish this by switching the model during context compaction, which would trigger a cache miss anyway.' But the second quote sits in the routing section: naive routing fails because 'Upon every call to the other model, the context for the task is not shared in a way that is cached, and you pay a very expensive price', and the fix is 'Each time we trigger compaction, we take it as an opportunity to evaluate the situation and switch the model that's in charge, effectively getting model switching "for free".' The post does not assign specific model names to main vs sidekick roles (it benchmarks against Fable 5, Opus 5, GPT-5.6, Kimi K3, Grok 4.5) and reports 'frontier and Fable 5-level performance at 60% lower cost' (FrontierCode: Fable 5 64.9 at $10.53 vs Devin Fusion 63.1 at $1.35) and '88% of their merged PRs were driven entirely by the automated Fusion router'. It adds: 'most cached inputs only have a 5-minute expiry. We encourage the reader to think about how to engineer around this.' → corrected: Devin Fusion (Cognition blog, 29 Jun 2026) combines TWO distinct techniques. (1) The 'sidekick' approach runs two parallel agents, 'one with a frontier model, the other with a more cost-effective sidekick model', each a full agent with its own tools, and 'both the main model and sidekick model maintain their own persistent, cached contexts'. (2) Separately, 'dynamic mid-session routing' changes which model is in charge of a single context, and to stay cache-efficient it does so only at compaction: 'Each time we trigger compaction, we take it as an opportunity to evaluate the situation and switch the model that's in charge', because the switch 'would trigger a cache miss anyway'. The compaction-time switch is the router, not a main-agent-to-sidekick handoff. The post also warns most cached inputs 'only have a 5-minute expiry'.

## unknowns

- CLI fork representation: no documented parent/branch pointer in the ATIF transcript or sessions.db; whether a fork copies the transcript file or references the parent is unknown. The ATIF-v1.4 schema's home (assumed Harbor/Terminal-Bench) could not be located; field names come from a third-party doc.
- Whether cloud Devin keeps a stable prompt prefix or uses provider prompt caching at all; the ACU-to-token mapping is not published.
- Current concurrency limit: April 2025 Core plan capped at 10 parallel sessions; the 2026 usage page says 'there are no concurrent session limits'; Managed Devins example spawns 10.
- Whether the interactive plan can be edited inline before approval or only approved/commented (docs say 'you can approve'; Devin 2.0 post says users can modify).
- The 'Devin's Slack Etiquette' post (Aug 2026) returned HTTP 429 three times and was not read.
- Exact semantics of 'ACP revert can cancel an active turn before rewinding' beyond the changelog line.
- Whether Side Chats or /btw answers are cached separately from the main prefix (i.e. whether they cost a cache miss).
