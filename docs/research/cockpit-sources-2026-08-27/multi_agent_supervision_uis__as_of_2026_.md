# Multi-agent supervision UIs, as of 2026-08: Claude Squad (tmux TUI), Conductor 0.82 (Mac app, closed source), Crystal (deprecated Feb 2026, replaced by Nimbalyst), Vibe Kanban (sunset 2026-04-10, local-only community edition), Warp Agent Management Panel / Oz, Claude Code v2.1.2xx (subagents, agent teams, agent view, dynamic workflows, desktop sessions), Codex 0.150 (app threads + worktrees, `codex agents`, `codex queue`, subagents, Guardian)


## interactionModel
Six distinct shapes exist. (1) Claude Squad: a list TUI over tmux + git worktrees. Keys: n new, N new-with-prompt, Enter/o attach, ctrl-q detach, tab preview/diff, c checkout (commit + Pause: worktree removed, branch kept), r resume, s commit+push, D kill. Status enum Running/Ready/Loading/Paused. `-y` starts a daemon that polls every instance and taps Enter whenever the agent shows a prompt; no cost display. (2) Conductor (Mac, Claude Code/Codex/Cursor/OpenCode): sidebar of workspaces, one git worktree + branch each; Cmd+N opens the Dispatcher (prompt box with a 'create more' toggle for repeated dispatch); Cmd+Shift+D diff viewer where inline comments become composer attachments sent back to the agent; 'Review' action; Checks tab (git status, CI, deployments, review comments, todos); sidebar rows show GitHub state (merged, failing CI, conflicts) on hover; per-turn checkpoints with a hover 'revert' icon; background tasks show a timer inside the transcript; archive to a History pane; REST API v0 exposes session state idle/working and POST /v0/sql over transcripts. (3) Crystal (archived v0.2.3 docs): Electron sidebar of sessions, one worktree each, statuses initializing/running/waiting/completed/error/stopped, desktop notification when a session is 'waiting', per-execution-round diff, run scripts, squash+rebase to main. (4) Vibe Kanban: kanban issues -> workspaces (branch + terminal + dev server) -> sessions (chat threads sharing files, not context). Four-panel layout; workspace sidebar shows Running / Idle / Needs Attention (raised-hand icon, pending approval) / Pinned; approval card with tick/cross per action (Codex first, Claude Code 'coming soon' in docs); Queue and Stop buttons; a context gauge (e.g. 27K of 200K) per session; inline diff comments are batched and sent as one message. (5) Warp: the Agent Management Panel lists interactive conversations and cloud runs with Working/Blocked/Canceled/Failed/Success, source, duration, and credit consumption; clicking a row opens the conversation locally or the shared cloud session; Agent Profiles set each capability (diffs, reads, plans, commands, MCP) to Agent Decides / Always Ask / Always Allow / Never with regex allow/deny lists where the denylist wins; Cmd+Shift+I 'Run Until Completion' bypasses the denylist by default; Interactive Code Review batches line-anchored comments into one pass; third-party CLIs (Claude Code, Codex, OpenCode) get a toolbelt, vertical tabs with metadata, and a notification plugin. (6) Claude Code: subagent/teammate panel below the prompt (Up/Down select, Enter open transcript and message, x stop, Esc); `/tasks` for background work; agent teams (experimental, CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1) in-process by default or tmux/iTerm2 split panes via teammateMode; teammate permission prompts bubble to the lead; plan approval is granted by the lead, not you; `claude agents` (research preview) groups background sessions Needs input -> Ready for review -> Working -> Completed, Space peeks and lets you answer a question or pick a numbered option without attaching, Enter attaches, Left detaches, Ctrl+X stops, dispatch line accepts @repo, @agent, `! cmd`, filters s:blocked / a:name / #PR; `/workflows` shows phases with agent counts and token totals, p pause, x stop, r restart. Desktop app: sidebar sessions, each in its own worktree, Cmd+click for a second pane, usage ring, OS notification when an unviewed session finishes, 'task chips' that spawn a new session. (7) Codex: app sidebar projects -> chats with 'needs approval' / 'done' indicators; each new chat picks Worktree or Local under the composer and can 'Hand off' between them; CLI `/agent` switches thread; `codex agents` dashboard (0.149.0, alt-a) searches, starts, renames, stops tasks; `codex queue --thread X --message` injects text into a running local or remote session; approvals untrusted / on-request / never plus granular policy; sandbox read-only / workspace-write / danger-full-access; optional Guardian auto-review routes approval requests through a reviewer agent that denies critical risk and escalates high risk; `/status` shows estimated thread credits or cost (0.148.0).


## caching
Claude Code documents the most. Requests are ordered static-first: system prompt + tool definitions, then CLAUDE.md/auto-memory, then conversation. Plan mode and skills append messages instead of changing the system prompt; MCP tools are deferred stubs by default so connecting a server appends rather than invalidates; compaction reuses the exact parent prefix and adds one summarization message; `/rewind` truncates back to a prefix that is still cached, so it is cheaper than `/compact`; the engineering blog says they 'alert on cache breaks and treat them as incidents'. Invalidators: model or effort switch, fast mode, non-deferred MCP changes, denying a whole tool, compaction, upgrade. Fork subagents inherit the parent's exact prefix and their first request reads the parent's cache; ordinary subagents, in-process teammates, workflows and compaction fall in the 'everything else' bucket with a 5-minute TTL by default (subagentPromptCacheTtl / CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL = 1h to extend; main conversation gets 1h on a subscription). Workflow fan-outs hold all but the first matching agent for up to CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS (5000 ms) so siblings read the first agent's cached prefix. Cache scope is per machine + directory, so worktrees of one repo miss each other's cache. Hit rate is visible via the statusline fields cache_read_input_tokens / cache_creation_input_tokens, `/usage` behavior flags, and OTel. Wake-ups (scheduled tasks, cross-session messages, goal check-ins) each re-send full context. Codex: the Responses API `prompt_cache_key` is the thread's session_id by default; for an Internal session source with a parent_thread_id it is '{source}:{parent_thread_id}', so internal child threads (e.g. Guardian review) share the parent's key; a test named api_key_subagent_uses_session_id_as_prompt_cache_key shows user subagents key on their own id; release notes mention evicting Guardian transcript entries 'in cacheable chunks', caching MCP tool catalogs, and starting cached MCP servers lazily for subagents. Claude Squad, Crystal, Conductor, Vibe Kanban: not documented; they wrap the vendor CLI/SDK per session and inherit its caching; none re-sends context itself. Warp: not documented.

Codex: AGENTS.md, skills, custom agents (name, description, developer_instructions, model, model_reasoning_effort, sandbox_mode, mcp_servers), [agents] config (enabled, default_subagent_model, max_concurrent_threads_per_session, interrupt_message), hooks (interrupt hooks added 0.150.0), plugins, MCP, an app-server API (thread/queue/add) that `codex queue` and the app use, execpolicy. Crystal: run scripts and a settings passthrough; Nimbalyst is 'extension-first'.


## multiAgent
Five coordination shapes. (a) N independent sessions, one worktree each, the human is the only coordinator: Claude Squad, Crystal, Conductor, Vibe Kanban, Claude desktop, Codex app. Cost is per-session; nothing is shared. (b) Lead + teammates with a shared task list (pending / in progress / completed, dependencies, file-locked claims) and JSON mailboxes: Claude Code agent teams. Teammates load CLAUDE.md/MCP/skills but not the lead's history; they are not worktree-isolated; docs advise 3-5 teammates and Sonnet, warn of ~7x token use in plan mode, and list limits: no resume of in-process teammates, task status lag, one team per session, no nested teams, lead fixed. Hooks TeammateIdle/TaskCreated/TaskCompleted can veto with exit 2. (c) Script-orchestrated fan-out: Claude dynamic workflows, up to 16 concurrent agents and 1,000 per run, subagents run in acceptEdits, resumable by replaying cached agent results in start order, 'Large workflow' warning above 25 agents or 1.5M projected tokens. (d) Parent + children exactly one level deep: Warp orchestration (local->local, local->cloud, cloud->cloud), pill bar of children above the agent view, Sub-agents tab in Oz, each child a separate run with its own credits. (e) Codex subagents: `/agent` to switch threads, roles default/worker/explorer, agents.max_concurrent_threads_per_session, IDE panel to stop or open threads, Guardian review threads distinguished from subagents, multi-agent V2 children reloaded through their parent, `@` mentions of other tasks (0.150.0). Cross-agent trust rules worth copying: Claude Code marks any message from another agent as not-from-the-user; it cannot answer a permission prompt, change settings, or run slash commands; auto-mode classifier treats relayed approvals as untrusted. Background subagent permission prompts surface in the main session and grants apply session-wide. Cross-session messaging runs over a per-session Unix socket with burst limits and loop throttling.


## forkTimeTravel
- supported: Partial across the set. Full conversation+code time travel with a tree: Claude Code (checkpoints, /rewind, /branch, /fork, fork subagents) and Codex (codex fork / codex exec fork with explicit parent links). Per-turn checkpoints plus a summary-only fork: Conductor. None: Claude Squad, Crystal (per-round diffs only), Vibe Kanban (new attempt = fresh), Warp (only cloud->local 'Fork to local').
- ux: Claude Code: every user prompt creates a checkpoint; `/rewind` or double-Esc on an empty prompt opens a list of prompts with actions Restore code and conversation / Restore conversation / Restore code / Summarize from here / Summarize up to here; the restored prompt is placed back in the input for editing and re-send; `/branch [name]` copies the conversation and switches to it, printing both session IDs; `claude --continue --fork-session` forks into a new process; `/fork` copies the session into a background session visible in `claude agents`; `/subtask <prompt>` starts a fork subagent that inherits the whole conversation; `/btw` answers then `f` forks the answer into a subagent; `--worktree "#1234"` starts from a PR head. Limits: bash-made file changes, background subagent edits, symlinked files and external edits are not restored; /rewind does not restore in-process teammates. Codex: `codex resume [--last|--all]`, `codex fork [--last]` (new chat from a previous session, original untouched), `codex exec fork <SESSION_ID> [PROMPT]`, TUI resume picker with archive/restore, resumed and forked threads restore their permission profile (0.149.0); Codex app worktree chats keep a snapshot before an old worktree is pruned so the chat can be reopened. Conductor: hover a message and click the revert icon; it 'permanently deletes all user and AI messages from the selected turn and later' and reverts files; 'Fork Workspaces' (0.25.6) creates a new workspace 'with the changes up to that fork point, and a summary of your chat'; Codex checkpoints landed in 0.44.0. Claude Squad: c checkout pauses (branch kept), r resumes; no conversation rewind. Vibe Kanban: 'Create New Attempt' with a different agent/profile/base branch; new sessions do not inherit history.
- dataModel: Claude Code: transcripts are JSONL at ~/.claude/projects/<cwd-slug>/<session-id>.jsonl. Observed locally (keys only, format declared internal and unstable by the docs): every message line carries uuid, parentUuid, sessionId, isSidechain, type (user | assistant | system | attachment | file-history-snapshot | permission-mode | queue-operation), cwd, gitBranch, version. Checkpoints are file-history-snapshot lines {messageId, timestamp, trackedFileBackups} pointing at backups in ~/.claude/file-history/<session-id>/<hash>@vN; the 100 most recent checkpoints keep snapshots, each file's first snapshot is kept as the VS Code diff baseline; retention follows cleanupPeriodDays (30 d). /branch copies the transcript to a new session id; the picker groups rows that share a session. Subagent transcripts: ~/.claude/projects/<project>/<sessionId>/subagents/agent-<agentId>.jsonl. Agent teams: ~/.claude/teams/session-<8 chars>/config.json (members with agent IDs, tmux pane IDs) and inboxes/<agent>.json; tasks in ~/.claude/tasks/<team>/ with file locking on claim. Agent view: ~/.claude/daemon/roster.json plus ~/.claude/jobs/<id>/state.json. Codex: ~/.codex/sessions/YYYY/MM/DD/rollout-YYYY-MM-DDThh-mm-ss-<uuid>.jsonl plus an archived-sessions subdir and a SQLite state db index (codex-rs/rollout/src/state_db.rs). The first line is SessionMeta {session_id, id: ThreadId, forked_from_id: Option<ThreadId>, forked_from_ordinal_exclusive: Option<u64> ('inherited from the logical fork parent, independent of history_base'), parent_thread_id (spawn parent), timestamp, cwd, originator, cli_version, source, thread_source, agent_nickname, agent_role} plus git info. Codex worktrees live in $CODEX_HOME/worktrees in detached-HEAD state; the newest 15 are kept, pinned/in-progress/permanent ones are protected. Conductor: 'Before each supported agent responds to a user message, Conductor captures the working branch state in a private Git ref'; stored locally, separate from the branch's history; a fork carries file state plus a chat summary, not the transcript. Claude Squad: ~/.claude-squad/state.json holds instances[] {title, path, branch, status, auto_yes, program, worktree{repo_path, worktree_path, session_name, branch_name, base_commit_sha, is_existing_branch}, diff_stats{added, removed, content}}. Crystal: ~/.crystal/crystal.db SQLite with projects, sessions(status, worktree_path, branch), session_outputs, conversation_messages, execution_diffs(execution_index), prompt_markers. Vibe Kanban: SQLite; tasks -> workspaces (renamed from task_attempts; parent_workspace_id links subtasks) -> sessions (executor) -> execution_processes; coding_agent_turns carry agent_session_id. Warp: each run has its own transcript and credit usage; on-disk format not documented.


## steal
- **Triage list grouped by state with 'Needs input' first, plus a peek pane that shows the exact question and lets you answer (or press a number for a multiple-choice option) without attaching to the session.** — This is exactly the gate cockpit loop: many agents, most working, a few blocked on allow/deny. Answering from the peek pane keeps the operator's locus of attention on the roster, not inside one transcript. The `claude agents --json` roster (state, waitingFor, sessionId) gives a machine-readable base for a custom cockpit. [https://code.claude.com/docs/en/agent-view]
- **Veto at lifecycle boundaries with a plain exit code: PreToolUse (block the call), TaskCompleted (refuse to mark done), TeammateIdle (send feedback and keep working), all exit 2 with stderr as the reason.** — Daisugi's gate should plug into the harness's own hook points rather than wrap the process. Exit-2-with-reason is a stable, harness-neutral contract and gives the 'deny + why' text for free. [https://code.claude.com/docs/en/agent-teams]
- **Per-turn snapshot into a private git ref, kept apart from branch history; restore truncates the conversation from that turn and reverts files; a fork = new workspace with the file state up to the fork point plus a chat summary.** — A cheap, git-native checkpoint that works for any agent CLI, with an honest 'fork carries a summary, not the transcript' choice. Pair it with Codex's SessionMeta pattern (forked_from_id + forked_from_ordinal_exclusive + parent_thread_id) for the prompt-tree data model. [https://www.conductor.build/docs/reference/checkpoints]
- **Prefix-sharing forks and staggered fan-out: a fork inherits the parent's exact prefix so its first request reads the parent's cache; when spawning N same-prefix siblings, hold all but the first (cap 5 s) until the first response begins, then release them together.** — Directly answers the caching goal. Forking from a checkpoint should be a cache hit, and N gated agents launched from one pathway should pay the prefix once. Also copy the operational rule: alert on cache breaks and treat them as incidents. [https://code.claude.com/docs/en/workflows]
- **Consent cannot be relayed: any message that arrives from another agent is labeled as not-from-the-user, cannot answer a permission prompt, cannot change settings, and slash commands inside it are inert; an agent denied an action cannot ask a sibling to do it.** — A fail-closed gate is only fail-closed if no agent can launder an approval through another agent. This is the trust law daisugi's multi-agent mode needs before anything else. [https://code.claude.com/docs/en/cross-session-messaging]
- **Per-step budget made visible as a drillable tree: phase -> agent -> prompt, recent tool calls, result, with token totals per node, plus an advisory 'Large workflow' banner when projected spend crosses a threshold (25 agents / 1.5M tokens) and pause/stop/restart keys on the node.** — Gives the operator a budget instrument that maps onto daisugi's per-step budget without blocking the run; the banner is advisory, the stop is one key away. [https://code.claude.com/docs/en/workflows]
- **Scriptable dispatch and steering from outside the UI: `codex queue --thread <id|name> --message` injects a message into a running session through the app-server API; `claude --bg` dispatches and `claude agents --json` reports state.** — Lets the cockpit be a thin view over a daemon and lets the garden or a test harness drive agents headlessly; Codex's `thread/queue/add` shows the minimal API (thread id, text) a supervision daemon needs. [https://github.com/openai/codex/pull/39092]

## avoid
- **One terminal pane per agent (tmux/iTerm2 split) as the default multi-agent view.** — Claude Code changed the default from 'auto' split panes to in-process in v2.1.179; split panes are unsupported in VS Code's terminal, Windows Terminal and Ghostty, and leave orphaned tmux sessions. The HN thread on agent teams reports pane and merge chaos. A roster with attach/peek scales; N panes do not. [https://code.claude.com/docs/en/agent-teams]
- **An auto-yes daemon that taps Enter on every prompt to keep agents moving (Claude Squad `-y`, Warp 'Run Until Completion' bypassing the denylist by default).** — It converts every approval into noise and defeats the gate; Claude Squad's daemon literally polls each tmux pane and presses Enter when a prompt appears. Daisugi should never ship a global bypass that is one flag away. [https://github.com/smtg-ai/claude-squad/blob/main/daemon/daemon.go]
- **Betting the product on humans planning and reviewing a fleet they cannot actually review.** — Vibe Kanban shut down on 2026-04-10 ('couldn't find a business model'); its own Show HN drew 'you're still sitting around waiting for Claude to merge conflicts' and Conductor's Show HN drew 'surprised people are running multiple agents, and are able to check their outputs diligently'. The gate exists because review does not scale; do not add a Kanban on top of unreviewable output. [https://www.vibekanban.com/blog/shutdown]
- **A rewind that looks total but is partial: Claude Code's checkpoints skip files changed by bash, by background subagents, by other sessions, and symlinked paths; in-process teammates are not restored by /rewind or /resume.** — Operators trust 'Restore code and conversation' literally. If daisugi offers time travel it must either snapshot at the git level (Conductor's approach) or show exactly what was not restored, as Claude Code now does with 'Restored the code, but skipped N files'. [https://code.claude.com/docs/en/checkpointing]
- **Over-broad OAuth scopes and default-on telemetry in a supervision tool.** — Vibe Kanban's launch thread pushed back on 'unlimited private access' GitHub OAuth and email/username telemetry enabled by default (fixed to opt-in after the thread); Conductor's thread flagged 'keys for the kingdom' without a privacy policy. A local-first gate must be structurally private. [https://news.ycombinator.com/item?id=44533004]

## loadBearingClaims
- Claude Code hooks can veto with exit code 2 at PreToolUse, TaskCreated, TaskCompleted and TeammateIdle; teammate permission prompts appear in the lead session; a message from another agent can never approve a permission prompt or relay a denied action. [https://code.claude.com/docs/en/agent-teams]
- `claude agents` groups background sessions by state (Needs input first), supports peek-and-reply without attaching, and `claude agents --json` exposes id, state (working/blocked/done/failed/stopped) and waitingFor per session. [https://code.claude.com/docs/en/agent-view]
- Codex rollout JSONL lives at ~/.codex/sessions/YYYY/MM/DD/rollout-<ts>-<uuid>.jsonl and its SessionMeta carries forked_from_id, forked_from_ordinal_exclusive and parent_thread_id; `codex fork` / `codex exec fork` create a new thread while leaving the source unchanged. [https://github.com/openai/codex/blob/main/codex-rs/protocol/src/protocol.rs]
- A Claude Code fork subagent inherits the parent's exact prefix and reads the parent's prompt cache on its first request; workflow fan-outs hold same-prefix siblings up to CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS (5000 ms) so they read the first agent's cached prefix; ordinary subagents get a separate cache with a 5-minute TTL unless subagentPromptCacheTtl is set to 1h. [https://code.claude.com/docs/en/workflows]
