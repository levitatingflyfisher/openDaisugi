# Hermes Agent (Nous Research) — v0.20.6, tag v2026.8.27 (2026-08-27), MIT, Python core (`run_agent.py` AIAgent) + React TUI/desktop; repo NousResearch/hermes-agent, 237k stars, 11.5k files


## interactionModel
One Python runtime (`AIAgent` in run_agent.py) behind four fronts: classic REPL CLI (`hermes`), TUI (`hermes --tui`; modal overlays for model picker, session picker, approval and clarify prompts; Ctrl+P command palette; `/agents` overlay), a desktop app (Sessions|Bots sidebar, Star Map, artifacts), and a messaging gateway (`hermes gateway`) to 25+ platforms, plus a localhost web dashboard (`hermes dashboard`, :9119) with Sessions/Analytics/Kanban/Skills/MCP pages and a REST API. Prompt surface: slash commands (case-insensitive, `/` autocomplete); every installed skill is a slash command (`/<skill>`, stack up to 5), skill bundles, user `quick_commands`; `!cmd` shell mode (no model call, no history entry, approvals still apply); `/prompt` in $EDITOR; `/steer <text>` injects a note after the next tool call without interrupting; busy-input modes interrupt|queue|steer; `/goal` (judge-driven Ralph loop, 20-turn budget), `/loop` (timer), `/background` (separate session). Approval/gating UX: a dangerous-command detector with `approvals.mode: smart|manual|off`; smart uses an auxiliary LLM to auto-approve low-risk, auto-deny dangerous, escalate uncertain; CLI prompt is `[o]nce | [s]ession | [a]lways | [d]eny` (deny default, 300s timeout); gateway answers yes/no or `/approve [session|always]`; `--yolo` / `/yolo` toggle with a persistent red banner and status-bar badge; a hardline blocklist and user `approvals.deny` globs sit below yolo; cron and one-shot `-q` default to deny; destructive slash commands (`/new`, `/undo`, `/clear`) open a 3-choice modal; memory and skill writes can be staged (`write_approval`) and reviewed with `/skills pending|diff|approve`. Budget/cost display: status bar `model │ 12.4K/200K │ [fill bar, color-coded] │ $0.06 │ 15m │ 🗜️N`; `/context` renders a 5x20 glyph grid (1 cell = 1% of window) plus a per-category token table (system prompt, tool definitions, skills index, MCP, subagents, memory, conversation), `/context all` adds per-skill and per-toolset cost; `/usage` per-category cost plus live provider account limits; `hermes insights` analytics; `--usage-file` JSON report for one-shot runs; `hermes prompt-size` reports the fixed prompt budget with no API call. Doctrine stated in the architecture doc: "every tool call is visible to the user via callbacks"; `/verbose` cycles off→new→all→verbose; `/focus` hides tool lines for display only.


## caching
Anthropic prompt caching in `agent/prompt_caching.py`, strategy "system_and_3": breakpoint 1 on the system prompt, breakpoints 2-4 a rolling window on the last three non-system messages; TTL 5m or 1h; auto-enabled for Claude on the native API and OpenRouter (and LiteLLM Claude on the OpenAI wire since v0.20.2). Stable-prefix discipline: the system prompt is built once per session in three ordered tiers, stable (SOUL identity, tool guidance, skills index, env/platform hints) → context (one project file: .hermes.md > AGENTS.md > CLAUDE.md > .cursorrules) → volatile (frozen MEMORY.md/USER.md snapshot, external memory block, timestamp/session line). Memory writes go to disk mid-session but the prompt is not rebuilt until a new session or a compaction. Plugins may register bounded `after_memory` prompt sections (4k chars each, 8k total) rendered once per session, frozen on compaction and restored from the persisted system prompt on resume. Everything dynamic is appended to the current user turn instead: `pre_llm_call` context, `HERMES_EPHEMERAL_SYSTEM_PROMPT`, prefill, gateway overlays, Honcho recall, Mixture-of-Agents advisor outputs, `/goal` continuation prompts. `/model`, provider fallback, credential-pool rotation and `/reload-mcp` are documented as cache-breaking; `/reload-mcp` asks first because tool schemas live in the prefix. Compression: default in-place compaction at 50% of the window (first 3 and last 20 turns kept; phase 1 clears old tool outputs with no LLM call; `tail_mode: lean` keeps a 2.5%-of-window tail and moves continuity into identifier-preserving digests, verbatim user messages and a `session_search` recovery pointer; self-reported 49K retained vs 162K on 500K-token sessions); gateway hygiene at 85%; micro-compaction exists but is off by default because it rewrites sent history every turn and breaks the cache. Per-step overhead controls: only a child's final summary re-enters the parent (`delegate_task`); Tool Search replaces MCP/plugin schemas with `tool_search/tool_describe/tool_call` bridge tools; skills load in three levels (index ~3k tokens → `skill_view` on demand); `execute_code` folds multi-step tool pipelines into one turn; `!cmd` is zero-cost. Cache-scope routing: `agent/prompt_cache_scope.py` derives the provider `prompt_cache_key` from the compression-lineage root so rotation never moves the bucket, while `/branch`, delegate and tool children get isolated scopes. The post-turn self-improvement review fork replays the warm cache on the main model, or a compact digest when routed to a cheaper aux model. Accounting: `cache_read_tokens`/`cache_write_tokens` per session and per (model, task) in `session_model_usage`; dashboard Analytics shows cache-hit %. Not documented: cross-agent prefix sharing or cache-aware model routing.

Hooks: Python plugin hooks (`pre_tool_call`, `post_tool_call`, `pre_llm_call`, `post_llm_call`, `pre_verify`, `on_session_*`, `subagent_start/stop`, `pre_approval_request`, `transform_*`, kanban observers); shell hooks declared in config.yaml with a JSON wire protocol, Claude Code/Cursor-compatible exit-2 block, `fail_closed: true` opt-in; gateway hooks (`HOOK.yaml` + `handler.py`). ## multiAgent
Four layers. (1) `delegate_task` (tools/delegate_tool.py): child AIAgent with a fresh conversation (only goal + context + project files; SOUL.md excluded), inherits the parent's toolsets and credentials and cannot widen them; flat by default (`max_spawn_depth` 1, `role="orchestrator"` opt-in, docs warn 3x3x3 = 27 leaves), max 3 concurrent; no wall-clock timeout by default but a stall monitor; top-level calls run in the background and return a handle; only the final summary re-enters the parent; optional per-child git worktree isolation; `/agents` overlay (live tree grouped by parent, per-branch cost/token/file rollups, kill/pause per child, post-hoc turn-by-turn step-through), `steer_subagent` / `interrupt_subagent` RPCs, per-task append-only live logs at `~/.hermes/cache/delegation/live/<id>/task-<n>.log` plus `manifest.json`; `/review` spawns an independent reviewer; a public SubagentLaunchRequest lifecycle API with serializable capability handles, fail-closed validation, 32k-char bounded results. (2) Kanban (`~/.hermes/kanban.db`): durable board shared by named profiles, each worker a full OS process with its own memory; columns triage→todo→ready→running→blocked→done; agents use a `kanban_*` toolset, humans use CLI/`/kanban`/dashboard (drag-drop, per-profile lanes, WebSocket live updates); an auto-decomposer routes triage cards to specialist profiles; heartbeat/reclaim, protocol-violation nudges with bounded retries; per-task model override and a "frontier orchestrator, inexpensive workers" cost strategy. (3) Bot Mode (desktop): profiles as named bots with routines and group chats; `hermes peer` bot-to-bot DMs across gateways; A2A v1.0. (4) Mixture-of-Agents presets: reference models plus an aggregator, advisor text appended at the tail so the main cache stays intact. Overhead: docs state children burn the large majority of tokens; `delegation.model` pins a cheap worker; no shared prefix across agents is documented.


## forkTimeTravel
- supported: partial — linear undo/retry plus copy-on-fork `/branch`; there is no in-place prompt-tree navigation (no walk up/down, no replay-from-node) in CLI/TUI; the desktop app adds edit-a-prior-prompt rewind and nests branches under parents in the sidebar.
- ux: `/branch [name]` (alias `/fork`) in CLI, TUI and gateway: copies the whole conversation into a new session, ends the old one with end_reason='branched', auto-titles `<title> #2` from the lineage. `/undo [N]` removes the last N exchanges (soft-delete, confirm modal), `/retry` resends the last message (hard transcript rewrite), `/rollback <N>` restores a filesystem checkpoint AND undoes the last chat turn (`/rollback diff N`, `/rollback N <file>`, `--all` to overwrite hand-edits), `/resume <name|id>` resolves the newest session in a title lineage, `/sessions` picker (TUI `/switch` live switcher, `/sessions new`), `/history`, `/save`, `/handoff <platform>` moves the live session to Telegram/Discord/etc., `/compress here [N]` lets the operator pick the compaction boundary. Desktop: sidebar groups branch children under their parent sorted by group recency (apps/desktop/src/lib/session-branch-tree.ts); editing or restoring an earlier prompt performs a truncating `prompt.submit` (rewind, then resubmit; the kept prefix is re-inserted as new rows). No key bindings exist for tree navigation.
- dataModel: SQLite `~/.hermes/state.db` (WAL, schema v23): tables sessions, messages, session_model_usage, messages_fts (+trigram, +cjk), state_meta, gateway_routing, compression_locks, async_delegations, schema_version. Session id = `YYYYMMDD_HHMMSS_<6hex>`. The only parent pointer is `sessions.parent_session_id` (FK), used for three child kinds: legacy compression rotation (parent `end_reason='compression'`), delegate subagents (`model_config.$._delegate_from`), and branches (`model_config.$._branched_from` = parent id, parent `end_reason='branched'`; `_BRANCH_CHILD_SQL` in hermes_state_common.py). Ancestors/descendants are walked with recursive CTEs; `_lineage_root_id` is exposed to the desktop. A branch is a full physical copy of message rows (`append_messages_batch`), not a shared prefix; there are no per-message parent links. Message rows carry `active` (soft-delete for `/undo`, kept for audit, hidden from prompt and search), `compacted` (default in-place compaction soft-archives pre-compaction turns under the same session id), `api_content` (byte-exact copy of what was sent to the API, for cache-stable replay on resume), `tool_calls`/reasoning JSON, `token_count`; sessions carry `rewind_count`, token/cache/cost counters. Goal state lives in `state_meta` key `goal:<session_id>`. Filesystem checkpoints are separate: one shared bare git repo `~/.hermes/checkpoints/store/` with `refs/hermes/<workdir-hash>` per project, one commit before each destructive tool at most once per directory per turn, an agent-write ledger of content hashes; opt-in (`--checkpoints`), default off, capped at 20 snapshots / 500 MB. Export: `hermes sessions export` to JSONL/HTML/Markdown/HF trace, `--lineage logical` merges a compression lineage; trajectories also saved as ShareGPT JSONL.


## steal
- **Typed verdict vocabulary for gate hooks, and timeout = deny: `pre_tool_call` returns `{action: block|approve|modify}`; `approve` escalates to the human gate; a hook that exceeds `plugins.hook_callback_timeout` blocks the tool instead of proceeding. Shell hooks accept Claude Code's exit-2 block.** — daisugi's verifier verdict should be an enumerated result (allow / deny / escalate / rewrite) that the cockpit can render and log, never veto-by-throw. Hermes' own RFC found OpenCode shipped a typed-but-dead `permission.ask` hook for 6+ months, so add a CI check that every declared hook has a live dispatch site. [https://hermes-agent.nousresearch.com/docs/user-guide/features/hooks and https://github.com/NousResearch/hermes-agent/blob/main/docs/rfcs/2026-07-plugin-architecture-lessons-pi-opencode.md]
- **Three-tier prompt (stable → context → volatile) with a frozen memory snapshot, bounded `after_memory` plugin sections frozen per session, all per-turn dynamics appended to the user-turn tail, and a provider cache scope keyed to the lineage root with fork children isolated (`agent/prompt_cache_scope.py`).** — A gate that emits a verdict every step must keep the envelope in the stable tier and put the verdict in the tool result or tail, or the prefix is rebuilt every step. Branch children need their own cache bucket so siblings do not poison each other. [https://hermes-agent.nousresearch.com/docs/developer-guide/prompt-assembly]
- **`/branch` = copy-on-fork with `parent_session_id` plus a `_branched_from` marker in `model_config` and `end_reason='branched'`; `/undo` = soft-delete (`active=0`) rows kept for audit; the desktop sidebar nests children under the parent sorted by group recency.** — A cheap, audit-preserving fork model on plain SQLite with recursive CTEs. daisugi can keep the markers and the soft-delete but replace the full copy with per-node parent pointers to get real tree navigation. [https://hermes-agent.nousresearch.com/docs/developer-guide/session-storage]
- **`/rollback`: one shared bare git shadow store, per-project refs, a checkpoint before each destructive tool at most once per directory per turn, an agent-write ledger of content hashes so hand-edits are preserved, and rollback also undoes the last chat turn.** — Gate-approved actions and filesystem state should rewind together. The content-hash ledger is the right way to tell agent writes from human writes when replaying or reverting a branch. [https://hermes-agent.nousresearch.com/docs/user-guide/checkpoints-and-rollback]
- **`/agents` overlay plus per-task live logs: live subagent tree grouped by parent, per-branch cost/token/files rollups, kill and pause per child, post-hoc turn-by-turn step-through, `stalling · no progress 450s` vs `active 3s ago`, append-only `task-<n>.log` + `manifest.json` readable from remote backends.** — This is the supervision cockpit for many agents. daisugi adds one column per node: proposed action, allow/deny, the proof reason, and remaining per-step budget. [https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation]
- **`hermes approvals suggest`: mine approval history from state.db into ranked allowlist proposals; never auto-applied; destructive classes never proposed; user `approvals.deny` globs and a hardline blocklist sit below `--yolo`.** — The envelope can be tightened or loosened from verdict history with the same three rules: propose only, explicit apply, never propose the irreversible. [https://hermes-agent.nousresearch.com/docs/user-guide/security]
- **Curator + `/journey`: per-skill usage telemetry (view/use/patch), active → stale → archived transitions, pins, cron-referenced skills protected, tar.gz snapshot before every pass, per-mutation audit ledger with single-entry rollback, dry-run, LLM consolidation off by default; `/journey` star-map timeline of learned skills and memories with a playback scrubber and edit/delete per node.** — This is the garden lifecycle daisugi needs: pathways growing, going stale, being merged, with reversibility built in and a time-scrubbed view of reuse. [https://hermes-agent.nousresearch.com/docs/user-guide/features/curator and https://hermes-agent.nousresearch.com/docs/user-guide/features/memory]

## avoid
- **Everything-in-one-repo sprawl and version-by-date churn: 11.5k files, 25+ messaging adapters, CLI + TUI + desktop + dashboard, ~1,300 commits per week, 36k open issues, 23k open PRs; releases are date tags whose curated notes 'will ship with v0.21.0'.** — An operator cannot audit what changed in the gate between two runs. daisugi needs a small surface and a changelog an operator can read before trusting a new build. [https://github.com/NousResearch/hermes-agent/releases and https://news.ycombinator.com/item?id=49424643]
- **Default bloat that costs context on every turn: users report >10k tokens just to list bundled skills after the setup wizard and describe it as 'debloating a fresh Windows install'; the fixes (`--no-skills`, `hermes skills opt-out`, `/context all`) are opt-out.** — The cockpit must start lean. Every default sits in the cached prefix and is paid on every step of every agent. [https://news.ycombinator.com/item?id=48586005]
- **Fail-open where a gate must fail closed: shell hooks default to fail-open (the docs admit this is 'wrong for security gates'), the `/goal` judge fails open on error, and filesystem checkpoints are off by default in v2 so `/rollback` is absent the first time it is needed.** — daisugi's law is fail-closed. Safety features shipped as opt-in defaults are not there when the operator needs them. [https://hermes-agent.nousresearch.com/docs/user-guide/features/hooks and https://hermes-agent.nousresearch.com/docs/user-guide/checkpoints-and-rollback]
- **`approvals.mode: smart` lets an auxiliary LLM auto-approve 'low-risk' dangerous commands and auto-deny others, and the human escalation is a four-key prompt that shows the command but not a checkable reason.** — A probabilistic judge is exactly what daisugi replaces with a proof. The cockpit should show the envelope clause that allowed or denied the action, not a model's opinion. [https://hermes-agent.nousresearch.com/docs/user-guide/security]
- **Trust erosion from defaults and governance (forum-sourced): HN users cite a Polymarket skill in the default set, an anime-girl default personality, a Reddit claim that default installs silently routed web search to a third-party vendor, and a plagiarism issue whose text maintainers edited to '.' before blocking commenters.** — For a runtime-assurance tool, silent third-party routing and opaque governance are disqualifying. daisugi should keep a WeatherGlass-style 'what leaves your machine' page and never edit its own record. [https://news.ycombinator.com/item?id=48586005 and https://news.ycombinator.com/item?id=48187581]

- [qualified] `pre_tool_call` hooks return typed `{action: block|approve|modify}`, `approve` escalates to the human gate, and a timed-out hook fails closed; shell hooks block with exit code 2 and are fail-open unless `fail_closed: true`. — Cited page (fetched 2026-08-27) supports each element: return shapes `{"action": "block", "message": ...}`, `{"action": "approve", "message": ..., "rule_key": ...}`, `{"action": "modify", "args": {...}}`; "`approve` escalates the call to the existing human-approval gate; `message` and `rule_key` are optional, and denial, timeout, or gate error fails closed"; "If a `pre_tool_call` callback exceeds `plugins.hook_callback_timeout` (or is still running from a previous timed-out fire), Hermes **fails closed**" (default 30s, 0 disables, max 600); "A `pre_tool_call` hook that exits with code **2** blocks the tool call even when its stdout carries no block JSON"; "By default shell hooks **fail open**: a spawn error, timeout, or unparseable stdout logs a warning and the action proceeds ... Shell hooks (also accepting Claude-Code `decision`/`reason`/`tool_input` shapes) block on exit code 2, but a shell hook's own spawn error, per-entry `timeout` (60s default, 300 max) or malformed stdout fails OPEN unless `fail_closed: true`, which is honored only on `pre_tool_call`. A shell hook whose `(event, command)` is not allowlisted (or `hooks_auto_accept: true`) is silently not registered in non-TTY runs, and script edits do not invalidate consent.
- [qualified] The system prompt is assembled stable → context → volatile, memory is a frozen per-session snapshot, Anthropic breakpoints are the system prompt plus the last three messages, and all dynamic context is appended to the user-turn tail to keep the prefix stable. — Cited page (fetched 2026-08-27) confirms tiers: "1. stable — identity (SOUL.md or fallback), tool/model guidance, skills prompt, environment hints, platform hints 2. context — caller-supplied system_message plus project context files 3. volatile — built-in memory snapshot (MEMORY.md), user profile snapshot (USER.md), external memory-provider block, timestamp/session/model/provider line ... joined as: stable → context → volatile" and memory: "Mid-session writes update disk state but do not mutate the already-built cached system prompt until a rebuild path runs (new session, or ... compression-triggered rebuild)" — frozen per build, not strictly per session. The 'all dynamic context to the user-turn tail' part is contradicted: the cited page puts the timestamp/session/model/provider line, memory/profile snapshots and (per source) the skills index and plugin sections INSIDE the cached system prompt's volatile tier (source: timestamp is "Date-only (not minute-precision) so the system prompt is byte-stable for the full day"); `ephemeral_system_prompt` is appended to the END of the system message at request time (agent/chat_completion_helpers.py: `effective_system = (effective_system + "\n\n" + agent.ephemeral_system_prompt)`); prefill messages are inserted right after the system message; only `pre_llm_call` plugin context and "later-turn Honcho/external recall injected into the current-turn user message" ride on the user turn. → corrected: The system prompt is built once per session (rebuilt on compaction/restore) as stable → context → volatile, and MEMORY.md/USER.md are frozen snapshots until such a rebuild. Anthropic caching in current source places 4 breakpoints: end of the stable tier (the cross-session static prefix), end of the full system prompt, and the last 2 cacheable non-system messages, falling back to system + last 3 when no static prefix is available (the layout the caching doc still describes); a tools-array variant spends one marker on the tools list. Dynamic context is split, not all on the user turn: the date-only timestamp/session/model line, memory snapshots, skills index and plugin sections live in the cached volatile tier; `ephemeral_system_prompt` is appended to the system message at request time; prefill goes after the system message; only `pre_llm_call` plugin context and later-turn external recall are appended to the current user message.
