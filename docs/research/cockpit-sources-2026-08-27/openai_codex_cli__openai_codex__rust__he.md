# OpenAI Codex CLI (openai/codex, Rust; HEAD 5ed334a 2026-08-27, release 0.150.x)


## interactionModel
Three operator surfaces share one Rust core. (1) The TUI (`codex`): a composer with a unified `@` mention menu (files, plugins, skills, and since 0.150.0 other Codex tasks), slash commands (from codex-rs/tui/src/slash_command.rs: /model /permissions /hooks /skills /review /new /resume /fork /side or /btw /compact /recap /plan /goal /agents /multi-agents /export /diff /status /usage /rollout /ps /stop /mcp /plugins /apps /memories /auto-review /experimental /elevate-sandbox /sandbox-read-root; no /undo exists any more), Esc-Esc backtrack, Ctrl+T transcript overlay, Ctrl+O copy. (2) `codex exec` non-interactive: `--json` event stream, `--output-schema <file>` for a typed final answer, `resume --last`. (3) `codex app-server`: JSON-RPC 2.0 over stdio, WebSocket (experimental) or a Unix socket, with a thread/turn/item model and server-initiated approval requests (`item/commandExecution/requestApproval`, `item/fileChange/requestApproval`, `item/permissions/requestApproval`, `mcpServer/elicitation/request`, `tool/requestUserInput`); the VS Code extension and the desktop app are clients of it. Gating: `approval_policy` is `untrusted` | `on-request` | `never` | a granular table (`sandbox_approval`, `rules`, `mcp_elicitations`, `request_permissions`, `skill_approval`); `sandbox_mode` is `read-only` | `workspace-write` (default) | `danger-full-access`; `--yolo` bypasses both. Sandboxes are Seatbelt on macOS, bwrap+seccomp on Linux, a native Windows sandbox; `.git`, `.agents`, `.codex` stay read-only; optional network proxy with per-domain allow/deny. `/permissions` switches mode mid-session and 0.150.0 added a keybinding to cycle modes. On an approval the operator's decision is one of `Approved`, `ApprovedForSession`, `ApprovedExecpolicyAmendment` (persist a rule so matching commands never ask again), `ApprovedMcpPolicyAmendment`, `NetworkPolicyAmendment`, `Denied`, `Abort` (protocol.rs ReviewDecision). Rules live in execpolicy files. Two automated layers sit before the human: hooks (`PermissionRequest` and `PreToolUse` can allow, deny, or rewrite input) and `approvals_reviewer = "auto_review"`, which routes approvals to a reviewer subagent (branded "Guardian" in source) that scores risk low/medium/high/critical; critical is always denied and there is no human fallback (issue #21975). Each tool action can also get a model-invisible `security_risk_score` line in the rollout.


## caching
Documented and visible in source. The Responses API gives exact-prefix KV reuse; Codex's loop keeps instructions, the tool list, and environment context byte-stable at the front and only appends (reasoning item, function call, function output per tool cycle), which the Bolin post frames as turning per-conversation cost from quadratic to linear (openai.com post, 403 to fetch; quoted via HN and propagated.ai). `prompt_cache_key` is the session id (thread id); internal subthreads such as auto-review use `"{source}:{parent_thread_id}"`; a `with_prompt_cache_key_override` exists in client.rs but is not exposed to users. Within one turn a WebSocket session reuses incremental payloads only when model, instructions, tools, reasoning, include, service_tier, prompt_cache_key and text are identical to the previous request. Request bodies are zstd-compressed (`features.enable_request_compression`). Compaction: automatic at `model_auto_compact_token_limit` with `model_auto_compact_token_limit_scope = total | body_after_prefix` (count only growth after the last compaction prefix); remote path is `/responses/compact` (v2 retains a 64,000-token message budget, since 0.150.1 images count toward it) returning an encrypted `compaction` carryover item; local fallback rebuilds initial context + summary + recent user messages up to 20,000 tokens. Compaction resets the cached prefix. Gaps on record: no `prompt_cache_breakpoint` emission, so independent sessions with a 9k-token identical startup prefix got 0% hits vs 98.6% with breakpoints (#35300, open); app-server sessions cannot share a stable key, ~54% hit rate (#21796, open); every spawned subagent has its own thread id and therefore a cold cache.


## extensions
Layered and mostly file-based. AGENTS.md (global `~/.codex/AGENTS.md`, per-directory from git root to cwd, 32 KiB combined cap; untrusted projects no longer supply project AGENTS.md since 0.150.0). Skills: `SKILL.md` with YAML frontmatter at `.agents/skills/<name>/`, `~/.agents/skills/`, `/etc/codex/skills/`, optional `scripts/`, `references/`, `assets/`, `agents/openai.yaml`. MCP servers in config.toml (`[mcp_servers.x]`, stdio and streamable HTTP, `codex mcp add`, `/mcp`). Plugins (marketplace launched March 2026 per secondary sources): `.codex-plugin/plugin.json` manifest plus `skills/`, `.mcp.json`, `.app.json` (connectors), `hooks/hooks.json`, `assets/`; marketplaces at `$REPO/.agents/plugins/marketplace.json` or `~/.agents/plugins/marketplace.json`; `/plugins` browser; remote catalog on by default; scaffolded by the built-in `@plugin-creator` skill. Agent Plugins 1.0.0 (2026-08-06, OpenAI/Microsoft/AWS/Cursor/Vercel) standardizes `plugin.json` + `skills/` + `mcp.json` and leaves hooks, commands, stores and security out of scope. Hooks (`features.hooks`, off by default; not on Windows): `~/.codex/hooks.json` or inline `[hooks]`, project `.codex/hooks.json`, plugin hooks; events PreToolUse, PermissionRequest, PostToolUse, PreCompact, PostCompact, UserPromptSubmit, Stop, SubagentStart, SubagentStop, SessionStart, SessionEnd, Interrupt (0.150.0); regex matchers on tool name; stdin JSON `{session_id, transcript_path, cwd, hook_event_name, permission_mode, model, turn_id}`; exit 2 + stderr or JSON `hookSpecificOutput.permissionDecision allow|deny` with `updatedInput`, `additionalContext`, `continue/stopReason`, `systemMessage`; hooks are trusted by hash via `/hooks`, managed hooks via `requirements.toml` with `allow_managed_hooks_only`; up to 8 concurrent, 600 s default timeout. Also execpolicy rule files, `notify` command, custom agent roles as TOML, connectors/apps, memories, goals.


## multiAgent
Built in and on by default (`features.multi_agent`, `agents.enabled`). The model gets tools `spawn_agent`, `wait_agent`, `send_input`, `resume_agent`, `close_agent` (core/src/tools/handlers/multi_agents). Config: `agents.max_concurrent_threads_per_session`, `default_subagent_model`, `default_subagent_reasoning_effort`, `interrupt_message`; roles as TOML in `~/.codex/agents/` or `.codex/agents/` with `name`, `description`, `developer_instructions` and optional model/sandbox/mcp overrides. Subagents inherit the parent's sandbox and approval mode, run as their own threads and rollout files (session_meta `parent_thread_id`, `agent_nickname`, `agent_role`, `subagent_history_start_ordinal`; `session_id` stays the root's), return summaries not raw output, and get `SubagentStart`/`SubagentStop` hooks. Operator view: `/agents` switches between all active agent sessions, `/multi-agents` between this session's subagents; the docs show Active/Done lists and let the operator steer or stop a subagent; 0.150.0 auto-titles terminal tasks and lets agents reference other tasks with `@`. Cost: docs state subagent workflows consume more tokens than single-agent runs; each subagent has a fresh thread id so no prefix reuse with the parent (client.rs prompt_cache_key). The optional rollout-trace records spawn, message, result and close edges between threads. Cloud tasks (`codex cloud`) and a `queue` command exist for background work.


## forkTimeTravel
- supported: partial. Conversation branching is real (Esc-Esc backtrack, /fork, /side, app-server thread/fork and thread/revert). File-state checkpoints do not exist in the CLI today: the /undo ghost-commit feature was removed and made a no-op on 2026-04-28 (PR #19481); the desktop turn-diff refs caused 100 GB+ bloat; /rewind requests (#11626, #12558) remain open.
- ux: With an empty composer, Esc primes backtrack; a second Esc opens the transcript overlay (also Ctrl+T) and highlights the most recent user message; Esc or Left steps to an earlier prompt, Right steps forward, Enter puts that prompt back in the composer and branches the thread before it (app_backtrack.rs). Code edits made after that point stay on disk; only the conversation is rewound. `/fork` clones the current chat into a new persistent thread; `/side` or `/btw` opens an ephemeral fork for a side question that does not pollute the main context; `/resume` opens a picker (filtered to cwd, `--all` to widen), `codex resume <uuid|name>|--last`, `codex fork <uuid>|--last`; `/rollout` prints the rollout path; `/export` writes markdown; `/compact` and `/recap` summarize. No redo. Known bugs: 0.147.0 paginated transcript desynced the UI from the persisted thread so backtrack failed with 'selected prompt was not found in the persisted thread' (#37421, closed); Ctrl+C while editing appended a thread_rolled_back marker (#31239).
- dataModel: Append-only JSONL under `$CODEX_HOME/sessions/YYYY/MM/DD/rollout-<YYYY-MM-DDTHH-MM-SS>-<thread_uuid>.jsonl` (archived copies under `archived_sessions/`). A reverted thread gets a new file `rollout-<ts>-<thread_id>_<rollout_id>.jsonl` while keeping the thread id (rollout_file_name.rs). Each line is `RolloutLine {timestamp, ordinal?, ...RolloutItem}` with a `type` tag in snake_case: session_meta | response_item | inter_agent_communication | inter_agent_communication_metadata | compacted | turn_context | world_state | security_risk_score | event_msg | realtime_item (history/src/lib.rs). Line 1 is session_meta: `session_id` (root of the session tree: forks keep the root's id), `id` (this thread), `forked_from_id`, `forked_from_ordinal_exclusive`, `parent_thread_id` (for subagents), `timestamp`, `cwd`, `originator`, `cli_version`, `source` (cli|vscode|exec|mcp|subagent|internal), `agent_nickname`/`agent_role`, `base_instructions`, `history_mode` legacy|paginated, `history_base {thread_id(=rollout id), ordinal}` = an exclusive prefix inherited from another rollout file, `subagent_history_start_ordinal`, plus `git` info. `turn_context` lines record per-turn cwd, approval_policy, approvals_reviewer, sandbox_policy and permission_profile. Fork = read the source rollout, truncate before the nth user message (ThreadRolledBack markers applied first), write a fresh thread id with `forked_from_id` set (thread_manager.rs fork_thread; app-server `thread/fork` takes `threadId`, `lastTurnId` inclusive or `beforeTurnId` exclusive, `path`, `ephemeral`). Rollback (deprecated `thread/rollback`) does not rewrite: it appends `event_msg {ThreadRolledBack {num_turns}}` and readers apply it. `thread/revert {threadId, beforeTurnId}` (paginated mode) replaces durable history with the prefix before a turn and emits `thread/reverted`; it explicitly does not touch files. A SQLite index sits beside the files: `state_5.sqlite`, `thread_history_1.sqlite`, `goals_1.sqlite`, `memories_1.sqlite`, `queue_1.sqlite`, `logs_2.sqlite` (state/src/sqlite.rs). `history.jsonl` is a separate prompt history (`history.persistence`, `history.max_bytes`). Opt-in `CODEX_ROLLOUT_TRACE_ROOT` writes a bundle (manifest.json, trace.jsonl, payloads/*.json) that an offline reducer turns into a state.json graph.


## steal
- **One append-only JSONL per thread whose first line carries the tree: session_id (root), forked_from_id, forked_from_ordinal_exclusive, parent_thread_id, history_base {rollout_id, ordinal}. Fork copies a prefix into a new file; revert keeps the thread id and mints a new rollout_id in the filename.** — Gives daisugi a prompt-tree that is greppable with jq, survives crashes, and lets a garden view walk parent links without a database; the rollout_id trick makes reverts non-destructive. [https://github.com/openai/codex/blob/main/codex-rs/protocol/src/protocol.rs]
- **Rewind by appending a marker (event_msg ThreadRolledBack {num_turns}) that readers apply, instead of rewriting history.** — Time-travel stays auditable and reversible; the gate's log never loses a proposed action that was later rolled back. [https://github.com/openai/codex/blob/main/codex-rs/core/src/thread_rollout_truncation.rs]
- **Persist the gate's inputs and verdicts inside the transcript as model-invisible lines: turn_context (approval_policy, sandbox_policy, permission_profile per turn) and security_risk_score (scores keyed per tool call, never shown to the model).** — The cockpit's allow/deny + why for every step is then reconstructible from the same file as the conversation, and replay of a branch replays the envelope that was in force. [https://github.com/openai/codex/blob/main/codex-rs/protocol/src/security_risk.rs]
- **Approval decisions that mint durable rules: ApprovedExecpolicyAmendment, ApprovedMcpPolicyAmendment, NetworkPolicyAmendment, ApprovedForSession, next to plain Approved/Denied/Abort.** — 'Approve and remember' is exactly the growth event for daisugi's garden: an operator verdict that widens the envelope becomes a stored pathway, with session-scoped and permanent variants. [https://github.com/openai/codex/blob/main/codex-rs/protocol/src/protocol.rs]
- **Reviewer-as-separate-agent (approvals_reviewer = auto_review) that returns a structured risk level and rationale, with critical always denied and the rationale surfaced to the human on deny.** — Maps to a Z3 gate plus an LLM envelope author: keep the two roles separate, show the reason, and add the human fallback Codex users are asking for. [https://learn.chatgpt.com/docs/agent-approvals-security]
- **Rollout-trace: observe first, interpret later. Hot path writes ordered raw events plus payload references; an offline reducer builds the graph (which request produced which tool call, which spawn produced which child thread).** — The garden view (pathways growing, reuse, tokens saved) can be computed from a cheap raw spine without slowing the gated loop. [https://github.com/openai/codex/blob/main/codex-rs/rollout-trace/README.md]
- **Headless core behind JSON-RPC (thread/turn/item) with server-initiated approval requests and thread/fork, thread/revert as protocol methods; TUI, IDE and desktop are all clients.** — Lets daisugi run one gate process and attach many cockpits (terminal, web) to many agents; approvals become messages a supervising UI can queue and batch. [https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md]

## avoid
- **Storing checkpoints inside the user's .git (ghost commits, refs/codex/turn-diffs tree refs).** — One 5.7 GB project grew 102 GB of orphan objects; tree-pointing refs broke libgit2 clients; the /undo feature was removed and made a no-op on 2026-04-28. [https://github.com/openai/codex/issues/29388]
- **Shipping conversation rewind without file rewind and calling it done.** — Esc backtrack leaves code changes on disk; users keep filing /rewind requests and call Codex 'the first agent' without undo. If daisugi offers time-travel it must snapshot the workspace too. [https://github.com/openai/codex/issues/11626]
- **Binding the prompt cache key to the thread id with no client-controlled key or explicit breakpoint.** — Identical 9k-token startup prefixes across sessions got 0% cache hits (98.6% with breakpoints); app-server fleets sit at ~54%. For many gated agents sharing one envelope prefix this is the whole token bill. [https://github.com/openai/codex/issues/35300]
- **An automated approver that can deny or abort with no path back to the human.** — Operators must re-prompt the agent to retry; a fail-closed gate still needs an override lane with the rationale attached. [https://github.com/openai/codex/issues/21975]
- **Letting the UI's view of history drift from the durable file (paginated transcript vs persisted thread).** — 0.147.0 showed prompts that did not exist in the rollout, so branching failed; the cockpit must render from the same store the fork reads. [https://github.com/openai/codex/issues/37421]

- Codex CLI has no file-state undo or checkpoint today: ghost-commit /undo was removed and made a no-op that reports the feature unavailable (merged 2026-04-28), and no /undo exists in the TUI slash-command enum. [https://github.com/openai/codex/pull/19481]

[https://github.com/openai/codex/blob/main/codex-rs/protocol/src/protocol.rs]

[https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/src/protocol/v2/thread.rs]

(#40511)"; PR #40511 merged 2026-08-25; protocol.rs `HookEventName` now ends with `Interrupt`. Caveat: interrupt.command.output.schema.json allows only `systemMessage`, so Interrupt hooks are observe-only (1s default / 3s max timeout per the PR), and the hooks docs page did not yet list Interrupt on 2026-08-27. → corrected: PreToolUse hooks can deny or rewrite a tool call (permissionDecision allow|deny, permissionDecisionReason, updatedInput only with allow); PermissionRequest hooks can only allow/deny (updatedInput/updatedPermissions/interrupt make the hook fail closed). Hooks are ON by default since 0.4x (PR #19012, 2026-04-23; feature key `hooks`, Stage::Stable, default_enabled: true; disable with `[features] hooks = false`). Non-managed hooks must be trusted per definition hash via /hooks (statuses Managed/Untrusted/Trusted/Modified; managed hooks skip review). Interrupt hooks shipped in rust-v0.150.0 (2026-08-26, PR #40511) but are observe-only: their output schema accepts only systemMessage.
