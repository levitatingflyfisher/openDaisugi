# pi coding agent (Mario Zechner / badlogic; repo moved badlogic/pi-mono -> earendil-works/pi in Apr 2026; npm @earendil-works/pi-coding-agent; changelog at 0.84.3, 2026-08-24) and oh-my-pi (Can Boluk / can1357; `omp`; fork of pi with "the IDE wired in")


## interactionModel
Terminal TUI built on pi-tui (differential rendering, no flicker). The operator types in an editor at the bottom; Enter while the agent is running queues a "steering" message (injected at the next tool boundary), Alt+Enter queues a "follow-up" for after the turn; Escape aborts, Escape twice opens /tree (setting `doubleEscapeAction: "tree"`); Ctrl+L model picker, Shift+Tab cycles thinking level, Ctrl+O / Ctrl+T collapse tool output / thinking, Ctrl+X copies the last assistant message. Slash commands (/resume /new /session /name /tree /fork /clone /compact /model /settings /export /import), `/skill:name`, `/template` prompt expansion, and `!cmd` shell passthrough. Four run modes: interactive; `pi -p "..."` print; `pi --mode rpc` (strict LF-delimited JSONL over stdin/stdout; extension dialogs are relayed to the client as `extension_ui_request` {select|confirm|input|editor} and answered with `extension_ui_response`); and an in-process SDK (`createAgentSession`, `SessionManager.inMemory()`, `session.prompt/steer/followUp/abort`). Approval/gating: pi core ships NONE. The README lists "permission popups" among things pi deliberately does not have; a gate is an extension `tool_call` handler that returns `{block: true, reason, terminate}` and may call `ctx.ui.confirm(...)`. The only built-in gate is project trust (`defaultProjectTrust: "ask"`) before loading project-local extensions/skills. oh-my-pi adds a tiered approval system (`tools.approvalMode`: `always-ask` | `write` | `yolo`, default `yolo`; tiers read/write/exec; per-tool `allow|prompt|deny`; `--yolo`, `--approval-mode` flags), a `/btw` ephemeral side-question overlay that never touches session history, and an Agent Hub (Alt+A) for supervising subagents.


## caching
Documented and partly in source. pi-ai (packages/ai/src/api/anthropic-messages.ts) stamps `cache_control: {type:'ephemeral'}` on exactly three positions: the system-prompt text block(s), the LAST tool definition (`index === tools.length - 1`), and the last content block (text/image/tool_result) of the final user message. It does not mark the last assistant `tool_use` block; the community `pi-better-messages-cache` extension adds that second breakpoint (README: 'Pi 0.80.6 does not add the assistant marker, but does cache the system prompt, latest tool definition, and latest user block'). A `cacheRetention` option exists; in the Anthropic adapter `retention === 'long' && compat.supportsLongCacheRetention` maps to `ttl: '1h'`, otherwise the default 5-minute ephemeral cache is used (issue #967, Jan 2026, asked for this). For OpenAI-compatible providers pi sends `prompt_cache_key` plus session-affinity headers (`sessionAffinityFormat: 'openai' | 'openai-nosession' | 'openrouter'`), `prompt_cache_retention: '24h'` where `supportsLongPromptCacheRetention`, and OpenAI-compatible proxies can opt into Anthropic-style markers with `cacheControlFormat: 'anthropic'`. Stable prefix: pi's system prompt + tool definitions are under ~1,000 tokens and fixed at session start, so the prefix is naturally stable; but pi DID break its own cache for months: issue #1873 (0.56.2, Mar 2026) found a per-second timestamp in the system prompt made 'the system prompt effectively unique on every request'; 0.80.4 (2026-07-09) 'fixed system prompt cache invalidation across dates by removing the current date from the default prompt' and added `showCacheMissNotices` (transcript notice on significant cache misses). 0.80.7 (2026-07-14) added 'cache-friendly dynamic tool loading': extension tools that become active after a tool result have their definitions appended at the point they appear, 'preserving the cached prompt prefix'. 0.82.0 (2026-07-24): compaction and branch-summary requests 'use fresh routing session IDs with prompt caching disabled where supported' so one-off summaries do not pollute the session's cache. Usage reports `cacheRead`/`cacheWrite` tokens and cost. Per-step re-send: pi does NOT avoid it; every turn resends the whole active path (root→leaf after compaction). Savings come from cache hits on that stable prefix, auto-compaction (`compaction.reserveTokens` 16384, `keepRecentTokens` 20000, never cut at a tool result), branch summaries, and /tree pruning. The `pi-cache-optimizer` package (2.8.6, 2026-08-23) reorders stable system-prompt content before dynamic context, compresses the skills XML listing, adds OpenAI cache keys for sessions without one, warns about proxies lacking session affinity, and shows hit stats in the footer. oh-my-pi: pins a `providerPromptCacheKey` per session and seeds it on full forks from the source header; tool-result pruning waits until either the suffix is small (~8k) or the session has idled past the provider cache lifetime; handoff generation reuses the live system prompt + tool array + real history to keep the cache prefix; `/fresh` resets provider stream state without touching the transcript.


## extensions
Extensions are TypeScript modules, hot-reloaded, discovered at `~/.pi/agent/extensions/*.ts`, `~/.pi/agent/extensions/*/index.ts`, `.pi/extensions/...`, plus `settings.json` `extensions[]` and `packages[]`. API: `pi.registerTool({name, description, parameters (TypeBox), execute(toolCallId, params, signal, onUpdate, ctx), promptSnippet, promptGuidelines})`, `registerCommand`, `registerShortcut`, `registerFlag`, `registerProvider`. Events: `session_start {reason: startup|reload|new|resume|fork}`, `session_before_switch`, `session_before_fork`, `session_before_tree` (can return a custom summary/label), `session_before_compact` (can return `{compaction:{summary, firstKeptEntryId}}`), `session_compact`, `session_compact_failed` (0.84.3), `session_shutdown`, `session_info_changed`; `before_agent_start` (inject messages / modify system prompt), `agent_start/end/settled`, `turn_start/end`; `tool_call` (mutable `event.input`; return `{block:true, reason?, terminate?}`), `tool_result` (mutate before the LLM sees it), `tool_execution_start/update/end`; `message_start/update/end`, `input` (intercept before template/skill expansion), `context` (modify messages before the request), `before_provider_headers`, `before_provider_request`, `after_provider_response`, `model_select`, `thinking_level_select`, `project_trust`, `resources_discover`, `user_bash`. UI from any handler: `ctx.ui.select/confirm/input/editor/notify/setStatus/setWidget/custom`. Messaging: `pi.sendMessage(msg, {deliverAs: 'steer'|'followUp'|'nextTurn', triggerTurn})`, `pi.sendUserMessage`, `pi.appendEntry(customType, data)` (persisted, invisible to the LLM), `pi.setSessionName`, `pi.setLabel`. Packages: `pi install npm:@foo/pi-tools | git:github.com/user/repo | https://...`; `pi list / update --all / remove / config`; manifest = package.json with `keywords:["pi-package"]` and `pi: {extensions:[], skills:[], prompts:[], themes:[]}`; public catalog at pi.dev/packages (e.g. pi-agent-extensions: 17 extensions + 4 themes; @smoose/pi-themes; pi-cache-optimizer; @ayulab/pi-rewind; @tintinweb/pi-subagents). README warning: 'Pi packages run with full system access. Extensions execute arbitrary code.' Skills follow the Agent Skills standard (SKILL.md), invoked with `/skill:name` or auto-loaded, from `~/.pi/agent/skills/`, `~/.agents/skills/`, `.pi/skills/`, `.agents/skills/` or packages (a `badlogic/pi-skills` repo is Claude Code/Codex compatible). Prompt templates: Markdown with `{{var}}` in `~/.pi/agent/prompts/`, `.pi/prompts/`. Themes: JSON in `~/.pi/agent/themes/`, hot-reload. No MCP built in (Zechner's 'What if you don't need MCP at all?'; OpenClaw uses mcporter as a CLI bridge). Telemetry: `pi-telemetry` package. oh-my-pi keeps the same extension API ('same tool API, same slash-command registry', `/reload-plugins`) and adds built-in MCP (mcp-config.md), hooks.md, a marketplace/plugin manager, compatibility with Cursor MDC / .clinerules / AGENTS.md / Copilot applyTo, 31 built-in tools and ~80k lines of Rust natives (self-reported in its README).


## multiAgent
pi core: none built in, by design. Zechner: sub-agents are 'a black box within a black box'; spawn new pi sessions via bash for observability; on HN (thread 46844822): 'There are lots of ways of doing subagents. It mostly depends on your workflow. That's why pi doesn't ship with anything built in. It's pretty simple to write an extension to do that.' The official `examples/extensions/subagent` extension: agents are Markdown files with YAML frontmatter (name, description, tools, optional model) in `~/.pi/agent/agents/*.md` or `.pi/agents/*.md`; 'Each subagent runs in a separate `pi` process' with a fresh context (inherits the parent's model + thinking level if unspecified); chain mode passes `{previous}` and stops at the first failure; parallel mode runs up to 8 tasks, 4 concurrent, streaming '2/3 done, 1 running'; 'Returns each completed task's final output to the parent model, capped at 50 KB per task'; per-agent usage line 'turns ↑input ↓output RcacheRead WcacheWrite $cost ctx:contextTokens model'. Token overhead therefore = each child pays its own (small) prefix and its own turns; the parent pays only the returned text. Community: `@tintinweb/pi-subagents` (used by Wiegold for 'fanning out independent read-heavy work'), SmolVM 'parallel pi agents in a sandbox'. RPC mode lets any language drive N pi processes and receive `extension_ui_request` approvals. oh-my-pi: `task` tool fans out subagents 'in parallel, optionally workspace-isolated' (git worktrees), returns 'a schema-validated object the parent reads directly. No prose to parse'; `orchestrate`/`workflowz` magic keywords; Agent Hub (Alt+A, also Ctrl+S) shows a roster with status running|idle|parked|aborted, parent link, model, cost, active/elapsed time, request count, tool-call count, tokens and context-window use; Enter focuses an agent's session (transcript/editor then belong to it, messages persist to the subagent's own JSONL), `r` revives parked agents, `x` kills, `t` flat/hierarchical, Tab inspector. Subagents run headless with `tools.approvalMode: yolo`; a user's per-tool `deny` still blocks and `prompt` REJECTS the call because headless agents cannot show a dialog. Also live session sharing via relay (collab.md) and `/share` (E2E-encrypted gzipped snapshot, AES-256-GCM, secret redaction on by default).


## forkTimeTravel
- supported: yes — pi has a full in-file session tree: /tree moves a leaf pointer to any earlier entry and continues from there; /fork and /clone copy history into new session files; oh-my-pi keeps the same model and adds /branch, model-callable checkpoint/rewind, and /btw-to-branch promotion.
- ux: pi: `/tree` (or Esc Esc) opens a navigator over the whole file. Keys per pi.dev docs: ↑/↓ move, ←/→ page, Ctrl+←/→ or Alt+←/→ fold/jump between branch segments, Ctrl+O cycles filter mode (default → no-tools → user-only → labeled-only → all; default set by `treeFilterMode`), Shift+L set/clear a label, Shift+T toggle timestamps, Enter select, Esc cancel, Ctrl+X copy selected message. Selecting a USER message sets the leaf to that entry's parentId and prefills the editor with its text (edit-and-resubmit = new branch). Selecting an assistant/tool entry sets the leaf there with an empty editor. Selecting the current leaf closes with no change. On branch switch pi offers: no summary / summarize the abandoned branch / custom summary instructions (`branchSummary.skipPrompt`); the summary is appended near the new leaf. `/fork` = new session file from an earlier user message (`pi --fork <path|id>` from CLI); `/clone` = duplicate the active branch into a new file at the current position; `/resume`, `pi -c`, `pi -r` switch files; `/export`/`/import` JSONL. Since 0.82.1 (2026-07-25) tree navigation during an active response aborts and persists the outgoing turn instead of leaving dangling tool calls. Extensions get `ctx.fork(entryId, {position: 'before'|'at'})`, `ctx.navigateTree(targetId, {summarize, customInstructions})`, `pi.setLabel(entryId, label)`, and cancellable `session_before_fork` / `session_before_tree` events. Over RPC only `fork`, `clone`, `get_fork_messages`, `get_tree`, `get_entries {since}` exist; no leaf-move command is documented. IMPORTANT: /tree is conversation-only. Files are not rewound (StackToHeap: '/tree is not code undo'). The community `@ayulab/pi-rewind` extension (0.4.6, Jul 2026) takes git snapshots per turn and offers /rewind with three scopes (code+conversation, conversation only, code only) plus `ayu.rewind.restoreOnTree: never|ask|always`. oh-my-pi: same /tree, plus `/branch` (new file from a selected user message), Shift+Enter = summarize without the prompt, Alt+D/T/U/L/A jump straight to a filter mode, fuzzy AND search in the tree, `/clear` writes a `reset_boundary` entry, and two model-callable tools when `checkpoint.enabled=true` (default false): `checkpoint` records the current entry id + goal; `rewind` branches the tree back at that point, appends a `branch_summary` for the abandoned exploration and injects a hidden `rewind-report` message; if the model tries to yield inside an open checkpoint it is warned 'You MUST call rewind with your investigation findings before yielding.' Issue #2781 (closed by PR #2894) added a single-key `f` to promote a /btw answer into a persisted branch.
- dataModel: One JSONL file per session at `~/.pi/agent/sessions/--<encoded-cwd>--/<timestamp>_<uuid>.jsonl` (oh-my-pi: `~/.omp/agent/sessions/<encoded-cwd>/...`, prefixed by a fixed 256-byte `type:"title"` slot). Line 1 is the header: `{"type":"session","version":3,"id":"<uuid>","timestamp":"<ISO>","cwd":"/path","parentSession"?:"/path/to/source.jsonl"}` (v1/v2 auto-migrate on load). Every other line extends `SessionEntryBase {type, id: string /* 8-char hex */, parentId: string|null, timestamp}`. Entry types: `message` (an AgentMessage; in context), `model_change`, `thinking_level_change`, `compaction` (`summary`, `tokensBefore`, either `firstKeptEntryId` or a materialized `retainedTail: AgentMessage[]` that acts as a self-contained checkpoint, optional `usage`), `branch_summary` (`fromId` = the abandoned entry, `summary`; in context), `custom` (extension state, NOT sent to the LLM), `custom_message` (extension-injected, in context), `label` (bookmark on an entry id; append-only, `label: undefined` clears), `session_info` (display name). Semantics (oh-my-pi session.md, identical model upstream): 'append-only tree + mutable leaf pointer: every append creates exactly one new entry whose parentId is the current leafId; the new entry becomes the new leafId; branch(entryId) moves only leafId; existing entries remain unchanged.' Context sent to the model = the path root→leaf, with a compaction entry replacing everything before `firstKeptEntryId` (or standing alone when it has `retainedTail`) and branch summaries inlined. `/fork` and `/clone` write a NEW file whose header carries `parentSession` and whose body is the copied entries (`SessionManager.forkFrom(sourcePath, targetCwd)`); `/tree` never creates a file. Extensions read `ctx.sessionManager.getEntries()` (whole file), `getBranch()` (root→leaf), `buildContextEntries()`, `getLeafId()`. Extension runtime state is NOT rewound on /tree; the colelawrence gist distinguishes 'branch-local' reconstruction (replay getBranch) from 'session-global' ledgers (getEntries) and notes getEntries ledgers do not survive a /fork into a new file. oh-my-pi adds `service_tier_change` and `reset_boundary` entries and stores a `providerPromptCacheKey` in the header that full forks inherit.


## steal
- **Append-only JSONL tree with 8-char `id`/`parentId` per entry and a movable leaf pointer; `branch_summary` entries written when you leave a branch; `/fork` and `/clone` are file copies carrying `parentSession` in the header; `custom` entries persist extension state invisibly to the model.** — This is exactly the prompt-tree daisugi needs: branch, rewind, replay and checkpoint with zero history rewriting, one file per session, and a clean split between what the model sees (message/compaction/branch_summary/custom_message) and what the cockpit records (custom/label). Gate verdicts and pathway-reuse events fit as `custom` entries on the same tree. [https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/session-format.md]
- **The `tool_call` hook contract: handler gets mutable `event.input` and returns `{block: true, reason?, terminate?}`; `terminate` suppresses the automatic follow-up LLM call when every call in the batch was blocked; `tool_result` can rewrite what the model sees.** — daisugi's Z3 gate is this shape. The `reason` string is what the model and the operator both read; `terminate` avoids paying for a wasted turn after a deny; `tool_result` rewriting is where a 'denied, here is the envelope' message goes. [https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md]
- **RPC mode: strict LF-delimited JSONL over stdio; approval dialogs cross the wire as typed `extension_ui_request` {select|confirm|input|editor} answered by `extension_ui_response`; `get_entries {since}` gives durable cursors; `get_tree` returns the tree.** — A cockpit for many gated agents can attach to each one over stdio, render every gate decision as a typed request, and tail each session with a cursor instead of re-reading files. Tree snapshots come for free. [https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc.md]
- **Cache hygiene shipped as features, not folklore: remove the date from the system prompt (0.80.4), append late-loaded tool definitions where they first appear instead of at the top (0.80.7 'cache-friendly dynamic tool loading'), run compaction/branch summaries under a fresh routing id with cache writes disabled (0.82.0), and surface misses with `showCacheMissNotices` plus `cacheRead`/`cacheWrite` in every usage line.** — daisugi's per-step gate must never touch the cached prefix; put gate output at the tail, never in the system prompt; and the garden should be able to prove 'tokens saved' from cacheRead numbers rather than estimates. [https://github.com/earendil-works/pi/blob/main/packages/coding-agent/CHANGELOG.md]
- **oh-my-pi's model-callable `checkpoint` + `rewind` pair: mark a point, explore, then `rewind` branches the tree back, writes a `branch_summary`, injects a hidden `rewind-report`, and a developer warning says 'You MUST call rewind with your investigation findings before yielding.'** — Pathway distillation for the garden is the same move: the concise report IS the reusable pathway, and the exploratory tokens are pruned from the live path while staying in the file for audit. [https://github.com/can1357/oh-my-pi/blob/main/docs/tools/rewind.md]
- **Agent Hub roster: per-agent status (running/idle/parked/aborted), parent link, model, cost, tokens, request and tool-call counts, context-window use; Enter to focus and steer, `x` kill, `r` revive, `t` tree/flat; approval tiers read/write/exec with per-tool allow/prompt/deny, and headless subagents where `prompt` means reject.** — This is the supervision cockpit shape daisugi wants, and the 'headless prompt = deny' rule is the fail-closed policy for unattended agents stated as one line of config. [https://github.com/can1357/oh-my-pi/blob/main/docs/agent-hub.md]
- **Separate conversation time-travel from file time-travel and make the scope explicit: pi-rewind's /rewind offers 'code and conversation' / 'conversation only' / 'code only', with `restoreOnTree: never|ask|always` when the user moves in /tree.** — pi's own docs warn '/tree is not code undo'. daisugi's rewind must say which of the three it is doing, or operators will replay a branch against a filesystem from another branch. [https://pi.dev/packages/@ayulab/pi-rewind]

## avoid
- **No permission system in core, YOLO by default (oh-my-pi keeps `yolo` as the default approval mode too).** — Users report the agent 'autonomously searching the author's home directory' and 'installing a skill globally without confirmation'; HN: 'Approval should be mandatory for any non-read tool call.' A gate that is an optional extension is a gate most people do not have. daisugi must be fail-closed out of the box. [https://thomas-wiegold.com/blog/pi-coding-agent/]
- **Volatile content in the stable prefix: a per-second timestamp in the system prompt made every request a cache miss from at least 0.56.2 (Mar 2026) until 0.80.4 (Jul 2026).** — One line of dynamic text silently forfeited the whole caching story for months, and a third-party package (pi-cache-optimizer) had to be written to reorder the prompt. Put a cache-miss counter in the UI from day one. [https://github.com/badlogic/pi-mono/issues/1873]
- **Time-travel that rewinds only the transcript: /tree does not touch files, and extension runtime state (module variables, widgets, caches) 'are not automatically rewound when the user uses /tree'; docs also drifted from source (`session_switch` vs `session_start`).** — Operators branch the conversation and the world does not follow. For daisugi the envelope and gate ledger must be reconstructed from the branch, or verified facts from an abandoned branch leak into the new one. [https://gist.github.com/colelawrence/b9b5ebc48abef6ceba8cf5fb91117db5]
- **Extensions and packages execute with full system access; `pi install git:...` runs arbitrary TypeScript in-process with the user's permissions.** — The thing that can block a tool call is itself unsandboxed code. If the gate runs in the same process as third-party extensions, any extension can remove it. [https://github.com/earendil-works/pi/blob/main/packages/coding-agent/README.md]
- **Refusing platform conventions and closing the issue: `~/.pi` ignores XDG_CONFIG_HOME and mixes cache with config; the report was closed 'will not be changed, period' and reached HN with 56 points and users announcing they were moving to other agents.** — Cheap to get right, expensive in goodwill when refused. daisugi should honour XDG from the start (it is also a stated workshop CLI convention). [https://news.ycombinator.com/item?id=49328206]

- [qualified] RPC mode is LF-delimited JSONL over stdio with `fork`, `clone`, `get_tree`, `get_entries {since}` and relayed `extension_ui_request`/`extension_ui_response` dialogs, but no command to move the leaf inside the tree. — rpc.md (raw, main) §Framing: "RPC mode uses strict JSONL semantics with LF (\n) as the only record delimiter... There is no built-in RPC command that moves the leaf in place; in-place navigation exists only in the extension API (`ctx.navigateTree`) and can be surfaced to RPC clients through an extension-registered `/command` sent via `prompt`.
