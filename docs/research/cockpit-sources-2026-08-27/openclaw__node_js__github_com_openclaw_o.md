# OpenClaw (Node.js; github.com/openclaw/openclaw). Name history per Wikipedia and the author's blog: Warelay (Nov 24 2025) -> Clawdis/Clawdbot -> Moltbot (Jan 27 2026, after an Anthropic trademark objection) -> OpenClaw (Jan 30 2026). Creator Peter Steinberger; OpenClaw Foundation (non-profit) since Feb 14 2026. GitHub on 2026-08-27: ~387.8k stars, ~81.4k forks, ~83.5k commits; README says MIT (GitHub API reports the license text as NOASSERTION). Stable line v2026.7.1 (2026-07-13); betas v2026.8.1-beta.2 (2026-08-15) and beta.3 (2026-08-24). Facts below are from the docs on `main` as of 2026-08-27 unless dated.


## interactionModel
ONE ALWAYS-ON GATEWAY. A single long-lived Gateway process per host (default 127.0.0.1:18789; auth mandatory; refuses non-loopback bind without auth) owns session rows, transcripts, active runs, approvals and channel connections. Every UI is a WebSocket client projecting Gateway-owned state: Control UI (Vite+Lit SPA served at the Gateway URL), TUI (`openclaw tui`), macOS/iOS/Android/watch apps, and chat channels (Telegram + WebChat bundled; Discord, Slack, WhatsApp, Signal, iMessage, Matrix, Teams etc. as plugins). Protocol: first frame `connect` -> `hello-ok` snapshot; `req/res` methods (`agent`, `chat.send`, `sessions.*`, `approval.*`, `exec.approval.*`); server-push events `agent`, `session.message`, `session.operation`, `session.tool`, `sessions.changed`, `exec.approval.requested/resolved`, `plugin.approval.requested/resolved`, `session.approval`, `presence`, `tick`, `health`. The `agent` RPC acks immediately with `{runId, acceptedAt}` and streams three lanes (assistant / tool / lifecycle). There is also an OpenAI-compatible HTTP surface (`/v1/chat/completions`, `/v1/responses`; models listed as `openclaw/<agentId>`).

PROMPT SURFACE. Chat-channel-first. The same slash commands work in chat, TUI and Control UI: `/new [model]`, `/reset`, `/compact [guidance]`, `/steer <msg>` (inject into the active run), `/btw` (side question outside context), `/queue steer|followup|collect|interrupt`, `/stop`, `/model`, `/thinking`, `/elevated`, `/exec host=.. security=..`, `/approve <id> allow-once|allow-always|deny`, `/skill <name>`, `/learn` (draft a reviewable skill from the conversation), `/status`, `/usage tokens|full|cost`, `/context list|map|json`, `/tools`, `/subagents list|log|info`, `/export-trajectory`. `$skill` references in the composer (max 8 per message). Default queue mode is `steer`: a prompt arriving mid-run is injected at the next tool-launch or model boundary; a running tool finishes, unstarted sequential calls get a synthetic result `Skipped due to queued user message.` so the transcript stays paired.

CONTROL UI (the cockpit). Chat pane streams tool calls as kind-aware rows (shell commands with terminal output; edit/write calls with bounded inline diffs and +added/-removed stats); consecutive calls collapse into "Ran 13 commands, read 6 files, edited 9 files" with the newest running call naming the group header. A "session rail" shows the model's latest safe preamble as the headline; a small utility model (`agents.defaults.utilityModel`) can replace it with a digest, plan progress, PRs, elapsed time and a read-only companion thread ("ask in side chat" without interrupting the run); the rail auto-expands once when a run is stuck or needs input. Sessions/Threads page: pin, group, rename, fork, archive, unread state, running indicators, multiple resizable Chat panes that survive reload. Unified side panel per Chat pane: Terminal (host PTY in the workspace, Ctrl+backtick), Browser (the Gateway-driven browser, annotate pages), Files, Tasks, Review, Side chat. Session diff panel (per-file, unified/split). PR chips above the composer. Usage page (session-derived tokens and estimated cost kept separate from provider-reported plan/quota/billing; 7/30/90-day charts; share by provider/model/agent/channel). Approvals History (30-day record of exec, plugin and system-agent decisions with resolver attribution and source-session links). Activity Inspector (deep-link audit viewer: execution identity, grants, lineage, decision receipts; needs `operator.read`). Worktrees page, Workboard (kanban), Automations (cron/heartbeat), Plugins/Skills (ClawHub store + Skill Workshop proposals), Devices.

TUI. `openclaw tui [target]` (gateway-backed) or `--local`. Header (URL, agent/session), chat log with tool cards (args + results), status line, footer (agent/session/model, token counts), input with autocomplete. Keys: Enter send, Shift+Enter newline, Ctrl+P session picker, Ctrl+G agent picker, Ctrl+L model picker, Ctrl+O toggle tool output, Ctrl+T toggle thinking, Esc abort, Ctrl+D exit. Plugin approval gates still prompt in the terminal in local mode; nothing is silently auto-approved.

APPROVAL / GATING UX. Layered, evaluated in order: (1) creator-role `sandbox: "required"` (fail-closed, cannot be escaped); (2) sandbox mode off|non-main|all; (3) tool availability `tools.profile`, `tools.allow/deny` ("deny always wins"); (4) sandbox tool policy (second gate); (5) elevated eligibility; (6) exec approvals; (7) plugin approvals. Exec approvals: `tools.exec.mode` deny|allowlist|ask|auto (auto routes allowlist misses through an LLM "auto reviewer" before human fallback)|full; `ask` off|on-miss|always; `askFallback` when no UI is reachable or the prompt times out defaults to `deny`. Gateway broadcasts `exec.approval.requested`; operators resolve from Control UI, macOS app, `openclaw approvals pending|resolve <id> <decision>`, or `/approve` in chat. `allow-always` entries bind to exact argv and cwd and expire after 30 days. For `host=node` the request must carry a canonical `systemRunPlan` (argv/cwd/rawCommand/session); any mutation between prepare and the approved `system.run` is rejected. Session permission modes: `read-only`, `guarded` (human reviews after allowlist fast path), `workspace` (LLM review with human fallback), `full` (admin only). Plugin gates: `before_tool_call` returns `requireApproval {title, description, severity, allowedDecisions, timeoutMs default 120s cap 600s}`; unresolved approvals always deny. Operator scopes: operator.read/write/admin/pairing/approvals/questions/talk; named roles with agent allowlists, foreign-session access (none/view/suggest/write) and scope ceilings.


## caching
Documented in detail (docs/reference/prompt-caching). PREFIX STABILITY: the system prompt is split at an internal cache-prefix boundary into a stable prefix (tool definitions, skills metadata, workspace/bootstrap files, ordered to stay byte-identical) and a volatile suffix (timestamps, per-turn metadata); prompt fingerprints are normalized (whitespace, line endings, hook-added context, capability ordering); applies to Anthropic, OpenAI, Google and CLI transports. Bundled MCP tool catalogs are sorted deterministically (server, then tool) so `listTools()` order cannot bust the prefix. Skills are snapshotted at session start into a compact XML block and reused every turn (refreshed only on SKILL.md change or new node), bounded by `skills.limits.maxSkillsPromptChars`. Old image blocks beyond the 3 most recent turns are replaced with a text marker. KNOBS: `cacheRetention: none|short|long` merged global -> per-model -> per-agent; Anthropic short = 5-min ephemeral, long = `cache_control {ttl: "1h"}`; OpenAI gets `prompt_cache_key` (auto on api.openai.com; proxies need `compat.supportsPromptCacheKey`) and `prompt_cache_retention: "24h"` for long; Gemini gets a managed `cachedContents` resource (300s/3600s); OpenRouter Anthropic routes get injected cache_control. `contextPruning.mode: "cache-ttl"` prunes only tool results, only after the TTL elapses, and resets the TTL clock only when it actually changed content (so nearby requests keep hitting cache); the Anthropic plugin auto-sets 1h TTL + 30-min heartbeat for OAuth/token auth. Heartbeat keep-warm: `agents.defaults.heartbeat.every: "55m"` (default 30m, or 1h with Anthropic OAuth). Usage is normalized into `cacheRead`/`cacheWrite` and shown in `/usage`, `/status`, `sessions.usage(.timeseries|.logs)`, the Control UI Usage page; `diagnostics.cacheTrace` writes JSONL snapshots (`session:loaded`, `prompt:before`, `stream:context`, `session:after`). A live cache regression gate has hard floors for Anthropic and watch-only floors for OpenAI. Claude Code CLI backend: OpenClaw passes `--exclude-dynamic-system-prompt-sections` (Claude Code >= 2.1.98) and requires >= 90% reuse in a Docker test lane; `cacheRetention` has no effect there. ORCHESTRATION OVERHEAD: sub-agents get isolated context by default; `context: "fork"` is documented as doubling token cost; a parent branch over a fixed 100K-token cap makes the child start isolated instead; `sessions_history` is bounded (80 KB, 4000 chars/block, redacted); completion is push-based ("announce" with compact token stats) and `sessions_yield` is preferred over polling; compaction keeps `keepRecentTokens` 20000 and is tool-pair aware; bootstrap files capped at 20k/60k chars. NOT DOCUMENTED: cache-aware routing (choosing an agent/model/provider because it holds a warm cache) and prefix sharing across sibling sessions.


## extensions
SKILLS: `SKILL.md` with frontmatter `name`, `description`, `user-invocable`, `disable-model-invocation`, `command-dispatch: "tool"`, `command-tool`, and a `metadata.openclaw` block (`os`, `requires.bins|anyBins|env|config`, `primaryEnv`, `always`, `install`). Six load tiers, highest first: `<workspace>/skills` > `<workspace>/.agents/skills` > `~/.agents/skills` > `<state>/skills` (managed) > bundled > `skills.load.extraDirs` + plugin skills. Per-agent allowlists (`agents.entries.*.skills`, non-empty list is final). ClawHub registry: `openclaw skills install @owner/slug` (also `git:`, `skills-sh:`, local), `openclaw skills verify --card` (trust envelope), `security.installPolicy` pre-install hook. Skill Workshop = the distillation loop: `/learn` or "next time / remember to" phrasing drafts one reviewable proposal; skills created by agents stay PENDING review (never active immediately); `openclaw skills workshop list|inspect|evaluate|apply|reject|quarantine`; `skill_proposal_evaluate` plugin hook (120s, attributed outcomes); `openclaw skills curator status` reports live usage and review outcomes; 2026.7.1 added auto-retiring unused skills from context, pinning, archive restore and overlap detection. PLUGINS: `openclaw.plugin.json` manifest + Plugin SDK (`definePluginEntry`, `api.on`, `api.registerHook`, `registerCompactionProvider`); a plugin can register channels, tools, model providers, hooks, CLI commands, agent harnesses (bundled `codex`, opt-in `copilot`), context engines (`plugins.slots.contextEngine`, e.g. `lossless-claw`), memory backends; native plugins run IN-PROCESS with the Gateway (not sandboxed); "compatible bundles" map Claude/Codex/Cursor plugin layouts into the inventory; install from ClawHub, npm, git, local path. HOOKS (three separate systems): (1) typed plugin hooks via `api.on(...)`: `before_model_resolve`, `before_prompt_build`, `before_agent_run` (gate), `before_agent_reply` (claim), `before_tool_call` (modify/gate/requireApproval, `matcher` by canonical tool id), `after_tool_call`, `tool_result_persist` and `before_message_write` (sync), `message_sending`, `agent_end`, `before/after_compaction`, `subagent_spawned/ended/progress`, `cron_changed`, `before_install`; per-handler timeouts; `before_agent_run`, `before_tool_call`, `before_install` FAIL CLOSED on error/timeout (15s), others log and continue. (2) internal hooks: a directory with `HOOK.md` + `handler.js` in `~/.openclaw/hooks/`, colon events (`command:new`, `command:reset`, `session:compact:before|after`, `agent:bootstrap`, `gateway:startup`, `message:received`, ...), observe-only, cannot block. (3) HTTP webhooks. MCP: `/mcp` config, sandboxed MCP servers pass a second allow gate; CLI backends get Gateway tools through a loopback MCP bridge; `openclaw attach <target>` gives an external coding harness a temporary session-scoped MCP grant. Policy plugin: `policy.jsonc` conformance checked by `doctor --lint` with attestation hash (not runtime enforcement).


## multiAgent
Agents are isolated personas: own workspace (`AGENTS.md`, `SOUL.md`, `USER.md`), own `agentDir` with auth profiles and SQLite store, optional per-agent model/tools/sandbox/skills. `bindings` route inbound messages by channel/account/peer/guild/team with a 9-level most-specific-wins order; session keys `agent:<agentId>:<rest>`. Concurrency: a lane-aware FIFO queue serializes one run per session (`session:<key>` lane) and caps global parallelism via `agents.defaults.maxConcurrent` (`main` lane = min(16, max(8, CPUs)); `subagent` lane default 8); transcript writes carry `expectedWriterRunId` so superseded runs cannot write. SUB-AGENTS: `sessions_spawn` (non-blocking; returns run id + Control UI `sessionUrl`; params `task`, `taskName`, `agentId`, `model`, `thinking`, `context: isolated|fork`, `visible`, `thread`, `sandbox: "require"`, `runTimeoutSeconds`, `cleanup`), `sessions_yield` (end turn, wait for children), `subagents list|log|info|cancel`, `sessions_history` (bounded, redacted), `sessions_list`. Depth `maxSpawnDepth` 1 (default) to 5; `maxChildrenPerAgent` 5 (1-20); leaf sub-agents lose all session/orchestration tools, depth-1 orchestrators get spawn/list/history when depth >= 2. Results are push-based (announce to the requester's channel with status + compact token stats; retried up to 30 min; blocked results kept 7 days). Sub-agents get only `AGENTS.md` context. External harnesses run through ACP (`runtime: "acp"`, e.g. Codex, `acpx`). Cross-agent messaging needs explicit `tools.agentToAgent`. Approvals raised by a child are projected to every ancestor session (`session.approval`, audience = BFS over controller/requester/parent, cap 64). Workboard plugin: kanban cards (triage..done) dispatched into subagent worker runs, optionally in managed worktrees. `sessions.dispatch/move/reclaim` can place a session on a paired device or cloud worker. Codex supervision lists/branches/archives native Codex threads; Claude Code sessions can open via `claude --resume` in the panel terminal. Fleet (experimental): `openclaw fleet create <tenant>` provisions isolated per-tenant cells (containers, own Gateway/state/port) for hostile multi-tenancy. Guidance doc "parallel specialist lanes" treats parallelism as a scarce-resource problem: lane contracts first, coordinator agent last.


## forkTimeTravel
- supported: Yes (partial): rewind, fork and branch-switch exist on `main` in the Control UI and Gateway RPC; rewind moves chat context only (files/tool side effects are not reverted), is disabled while the agent is working, and is rejected for sessions owned by an external harness (Codex/Claude Code). No replay-from-checkpoint of tool effects; no TUI keybinding for rewind/branch is documented. Release notes for v2026.7.1 mention 'transcript forking' in session lists but contain zero 'rewind' entries, so rewind may be post-2026.7.1.
- ux: Control UI chat: every persisted user-message bubble has a hover rewind button (confirm popover with 'Don't ask again') plus right-click 'Rewind to here' and 'Fork from here'. Rewind 'repoints the session to the state just before that message and returns its text to the composer for edit and resend' (`sessions.rewind`, needs `operator.admin`). Fork 'creates a new session from the active-path prefix before the message, opens it, and seeds its composer with the same text' (`sessions.fork`, `operator.write`). When the store holds multiple branches, the chat title bar shows a branch menu listing each branch's latest message, message count and recency; selecting an inactive branch switches the session back to that preserved path (`sessions.branches.list` read; `sessions.branches.switch` admin; selecting the active branch is a typed no-op error). Sessions page rows also offer fork. Programmatic: `sessions.create { parentSessionKey, fork: true }` (refused while the parent has an active run; child inherits model unless overridden; marked `forkedFromParent` with fresh token counters). Sub-agents: `sessions_spawn context: "fork"` branches the requester transcript (doubles token cost); thread-bound spawns default to fork. Codex supervision: 'branch' from a native Codex thread creates a snapshot fork. Filesystem time-travel is separate: managed worktrees snapshot to `refs/openclaw/snapshots/<id>` on removal, restorable for 30 days via `openclaw worktrees restore`.
- dataModel: Per-agent SQLite `~/.openclaw/agents/<agentId>/agent/openclaw-agent.sqlite` (schema v17; tables incl. `sessions`, `transcripts`, `memory_indexes`). Layer 1: session rows `sessionKey -> SessionEntry` with `sessionId` (current transcript identity), `sessionStartedAt`, `lastInteractionAt`, `updatedAt`, `archivedAt`, `pinnedAt`, `lastReadAt`, toggles (thinkingLevel, elevatedLevel...), model overrides, token counters (`inputTokens`, `outputTokens`, `totalTokens`, `contextTokens`), `compactionCount`, `memoryFlushAt`. Layer 2: transcript events, append-only and TREE-STRUCTURED: first entry `type: "session"` with `id`, `cwd`, `timestamp`, optional `parentSession`; then entries with `id` + `parentId`. Entry types: `message` (user/assistant/toolResult), `custom_message` (enters model context), `custom` (extension state, not in context), `compaction` (persisted summary with `firstKeptEntryId` and `tokensBefore`), `branch_summary` ('persisted summary when navigating a tree branch'). Rewind/branch-switch repoints the head; pre-rewind entries stay in the append-only store. Compaction no longer writes separate `.checkpoint.*.jsonl` files (legacy ones still readable). Session keys: `agent:<agentId>:<rest>` (`agent:main:main`, `agent:<id>:subagent:<uuid>`, `cron:<jobId>`, `hook:<uuid>`); Control UI short links `/chat/<agentId>/<slug>-<shortId>`. Session-state change log: `session_state_events` (state version = highest sequence number; 30-day/50k-row retention) with `session_watch_cursors` seeded at spawn for parent->child. Global control-plane DB `~/.openclaw/state/openclaw.sqlite` (schema v13): `operator_approvals` (approval_id, kind exec|plugin, status pending|allowed|denied|expired|cancelled, presentation_json, source_session_key, audience_session_keys_json, runtime_epoch, expires_at_ms, resolver_*), `subagent_runs`, `skill_workshop_proposals`, `cron_jobs`, `agent_databases`. Legacy JSONL transcripts under `~/.openclaw/agents/<agentId>/sessions/` (+ `sessions.json`) are migrated by `openclaw doctor --fix`; deleted sessions keep a `.jsonl.deleted.<timestamp>` archive. `openclaw sessions export-trajectory` writes a JSONL trajectory bundle; `openclaw sessions tail --follow` streams redacted trajectory events. Incognito sessions live only in process memory.


## steal
- **Durable approval object with first-answer-wins compare-and-set and strictly fail-closed terminal states: pending -> allowed|denied|expired|cancelled; timeout=expired/deny, no route=deny, malformed verdict=deny, run abort=cancelled; Gateway restart bumps a runtime epoch and atomically cancels older pending rows so their deep-link URL still explains what happened; each approval has a stable `/approve/{approvalId}` route and a fixed-size `resolution_ref` for transports with short callback IDs.** — daisugi's gate needs one authority for allow/deny across TUI, web and chat; OpenClaw's design doc spells out the races and restart cases a Z3-backed gate will hit too, and the audit row doubles as the 'why' record the cockpit shows. [https://docs.openclaw.ai/refactor/operator-approvals]
- **Ancestor audience projection: when a child session raises a gate, the request and its terminal event are delivered to the source session AND every orchestrator ancestor (breadth-first over controller/requester/parent edges, de-duplicated, capped at 64); clients opt in with `sessions.messages.subscribe { includeApprovals: true }` and get a replay of up to 1,000 pending approvals on reconnect.** — A cockpit supervising many gated agents must see every proposal from every depth in one stream and must recover its pending list after a reconnect without polling. [https://docs.openclaw.ai/gateway/protocol]
- **Append-only transcript tree (`id` + `parentId`, `branch_summary` entries) where rewind only repoints the head, fork creates a new session from the active-path prefix, and a title-bar branch menu lists branches by latest message/count/recency; rewind puts the original text back in the composer for edit-and-resend; both are disabled while a run is active.** — This is exactly the branch/rewind/replay tree daisugi wants, already field-tested; the 'disabled while running' rule and the 'transcript-only, files not reverted' caveat are the two decisions to make explicitly (daisugi can pair rewind with a worktree snapshot). [https://docs.openclaw.ai/web/control-ui]
- **Stable-prefix / volatile-suffix system-prompt boundary plus deterministic tool-catalog ordering, `cacheRetention` merged global -> model -> agent, TTL-aware tool-result pruning that only resets the clock when it changes content, heartbeat keep-warm, and `cacheRead`/`cacheWrite` counters in every status surface with a live regression floor test.** — daisugi's gate context and garden pathways are exactly the kind of content that must sit above the boundary; the counters are what the garden view needs to show 'tokens saved' honestly. [https://docs.openclaw.ai/reference/prompt-caching]
- **Approvals bound to a canonical execution plan: `allow-always` entries bind to exact argv + cwd and expire after 30 days; node execution requires a `systemRunPlan` and the Gateway rejects the run if command/cwd/agent/session changed between approval and execution; approval tokenization is TLA+-modeled against replay.** — A verifier that proves 'this action is inside the envelope' must guarantee the executed action equals the proven one; OpenClaw's plan-binding is the runtime half of that guarantee. [https://docs.openclaw.ai/tools/exec-approvals]
- **Tool-activity rows that collapse into 'Ran 13 commands, read 6 files, edited 9 files' with the newest running call as the group header, plus a session rail whose headline is the model's safe preamble, optionally upgraded by a small utility model, that auto-expands only when a run is stuck or needs input, and a read-only companion side chat that never interrupts the run.** — For a many-agent cockpit this is the density/attention model: quiet by default, one line per agent, expand on exception; the utility-model digest is a cheap way to summarize what each gated agent is proposing. [https://docs.openclaw.ai/web/control-ui]
- **Skill Workshop: agent-drafted skills always land as PENDING proposals (never active without review), `/learn` turns a conversation/file/URL into one proposal, evaluator hooks produce attributed outcomes, `curator status` tracks live usage, and long-running agents auto-retire unused skills, pin important ones, and flag overlaps.** — This is the closest shipped analogue to daisugi's garden: distillation with a review gate, usage tracking, and pruning over time. [https://docs.openclaw.ai/tools/skills]

## avoid
- **Three different hook systems (typed plugin hooks via `api.on`, internal HOOK.md hooks with colon event names, HTTP webhooks) with different blocking semantics; registering a typed name like `before_tool_call` through the wrong API only warns and is never invoked, and the catalog 'is the registration API, not a promise that every runtime emits every hook' (e.g. `before_agent_run` is not a Codex gate).** — A gate that silently does not fire is the worst failure mode for runtime assurance; daisugi should have one hook contract with one fail-closed rule and refuse unknown names. [https://docs.openclaw.ai/plugins/hooks]
- **Authority split across code paths: CVE-2026-33579 was a scope-ceiling bypass because the `/pair approve` plugin command path did not pass `callerScopes` to the core check after an earlier advisory hardened only the RPC path; the operator-approvals refactor exists precisely because approval authority was 'process-local' and duplicated across the embedded broker and node policy.** — Any second path to 'allow' (CLI, chat command, plugin) must call the same verifier; daisugi should have exactly one allow function and test that every surface routes through it. [https://news.ycombinator.com/item?id=47628608]
- **Surface sprawl and churn: 40+ channels, 35+ providers, ~300 docs pages, five names in three months, an 83k-commit repo whose protocol reference already omits shipped RPCs (`sessions.rewind`, `sessions.fork`, `sessions.branches.*` exist in code and the Control UI doc but not in the protocol page); HN complaints about a 1.2 GB install, 13-second CLI startup and unreviewed generated code.** — Docs drift and startup weight erode trust in exactly the tool that is supposed to be the trust layer; daisugi's operator surface should stay small and its RPC list generated from the code. [https://news.ycombinator.com/item?id=46820783]
- **Sandbox off by default, native plugins in-process and unsandboxed, third-party skills 'treat as untrusted code; read before enabling', and an always-on chat agent that can run up large bills (HN reports of $560 over a weekend); mitigations exist but are opt-in.** — Safe defaults are the product for an assurance layer: daisugi should ship fail-closed and budget-capped by default and make 'full' an explicit admin exception, as OpenClaw's newer permission modes do. [https://docs.openclaw.ai/gateway/sandboxing]
- **Rewind that reverts chat context only: 'files and other tool side effects are not reverted', while worktree snapshots exist as a separate, unlinked mechanism.** — For a coding cockpit a rewind that leaves the working tree ahead of the transcript is a correctness trap; tie transcript checkpoints to worktree snapshots or label the divergence loudly. [https://docs.openclaw.ai/web/control-ui]

## loadBearingClaims
- OpenClaw's Control UI has per-message 'Rewind to here' and 'Fork from here' actions backed by `sessions.rewind` (operator.admin) and `sessions.fork` (operator.write), and a title-bar branch menu backed by `sessions.branches.list` / `sessions.branches.switch`; rewind moves chat context only and is disabled while the agent is working. [https://docs.openclaw.ai/web/control-ui]
- Transcripts are stored per agent in SQLite as an append-only tree (entries have `id` + `parentId`; `compaction` and `branch_summary` entry types), and operator forks are created with `sessions.create { parentSessionKey, fork: true }`, refused while the parent has an active run. [https://docs.openclaw.ai/reference/session-management-compaction]
- Plugin `before_tool_call` hooks can block, rewrite params, or return `requireApproval`; unresolved approvals always deny, and a handler error or 15-second timeout fails closed (blocks the tool call). [https://docs.openclaw.ai/plugins/hooks]
- OpenClaw keeps a stable-prefix / volatile-suffix cache boundary in the system prompt, exposes `cacheRetention` (none|short|long) merged global -> model -> agent, prunes tool results only after the cache TTL, and normalizes provider usage into `cacheRead`/`cacheWrite`. [https://docs.openclaw.ai/reference/prompt-caching]
