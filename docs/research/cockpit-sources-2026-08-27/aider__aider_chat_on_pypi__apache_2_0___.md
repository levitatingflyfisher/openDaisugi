# Aider (aider-chat on PyPI, Apache-2.0). Latest stable v0.86.2, tagged 2026-02-12 (previous: v0.86.1 2025-08-13, v0.86.0 2025-08-09). HISTORY.md has an unreleased "main branch" section (Claude 4.5/4.6/4.7 aliases, Gemini 3 preview). Community fork aider-ce / cecli exists because upstream "has been painfully slow in receiving updates". Facts below are from the upstream docs and source at github.com/Aider-AI/aider main as of 2026-08.


## interactionModel
Single-operator terminal REPL (prompt_toolkit) in one git repo. The operator curates context by hand: /add puts files in the editable set, /read-only (or --read) adds reference files, /drop removes, /reset drops all files and clears history, /clear clears only history, /tokens prints a per-item token and cost breakdown. Four chat modes: code (edits), ask (no edits), architect (main model proposes in prose, a cheaper editor model turns the proposal into edits), help. Mode is set per message with a /code /ask /architect prefix or made sticky with /chat-mode; the prompt shows the mode as '>', 'ask>', 'architect>'. Since v0.79 /context asks the LLM which files a request needs. Approval/gating UX: io.confirm_ask offers '(Y)es/(N)o', adds '(A)ll/(S)kip all' when a prompt belongs to a group, and '(D)on't ask again' when allow_never=True; --yes-always auto-answers. Gates fire when the LLM mentions a file not in chat ('Add file to the chat?'), when it proposes shell commands ('Run shell command?' with explicit_yes_required=True), and when a URL is pasted. Edits themselves are NOT gated: aider applies search/replace blocks directly and auto-commits, and architect proposals auto-apply by default since v0.81 (--auto-accept-architect default True). After each reply aider prints one budget line: 'Tokens: X sent[, Y cache write][, Z cache hit], A received. Cost: $B message, $C session.' Lint runs automatically after edits (--auto-lint True), tests only with --auto-test; failures feed a reflection loop capped at max_reflections=3. Other surfaces: --watch-files (an 'AI!' or 'AI?' comment in any file triggers a code or ask turn from the IDE), --copy-paste and /copy-context for web-chat LLMs, an experimental --browser Streamlit UI, /voice, --message/--message-file for one-shot scripting. Secondary reviewers praise staying in the loop with small diffs (Sinchenko 2026) but complain about 'lots of manually /add and /remove files' (slinkp 2025).


## caching
Documented and readable in source. Aider re-sends the whole prompt every turn (no server-side session), so it fights re-send cost three ways. (1) Stable prefix ordering: ChatChunks.all_messages() sends system + examples + readonly_files + repo + done + chat_files + cur + reminder, i.e. the least-changing content first (docs list the cached items as 'the system prompt, read only files added with --read or /read-only, the repository map, the editable files that have been added to the chat'). With --cache-prompts and a model whose ModelSettings has cache_control: true (Anthropic Sonnet/Haiku; DeepSeek caches_by_default), add_cache_control_headers() marks three ephemeral breakpoints: on examples (else system), on repo (else readonly_files), and on chat_files. cacheable_messages() returns everything up to the last marker. (2) Keepalive: --cache-keepalive-pings N (default 0) starts one daemon thread that re-sends cacheable_messages() with max_tokens=1 every 5*60-5 seconds (env AIDER_CACHE_KEEPALIVE_DELAY), up to N times after each user message; docs: 'Aider will ping up to N times over a period of N*5 minutes after each message you send.' Added v0.51.0 (2024-08-20). (3) Context minimization: only hand-picked files are sent; the repo map is capped at --map-tokens (default 1k, times --map-multiplier-no-files=2 when no files are in chat, bounded by context window minus padding); --map-refresh auto only reuses the cached map when computing it took >1s, 'files' refreshes on file-set change, 'manual' pins the map (v0.51 note: 'Repo map recomputes less often in large/mono repos or when caching enabled'); chat history is summarized by the weak model when it exceeds max_chat_history_tokens (ChatSummary keeps the tail verbatim, summarizes the head, recurses up to depth 3); conventions files are loaded read-only 'and cached if prompt caching is enabled'; diff edit formats keep outputs small. Costing: cache write billed at 1.25x, hit at 0.10x, shown in the per-message 'cache write / cache hit' fields. Caveats: 'caching statistics and costs are not available when streaming responses' (use --no-stream; v0.80 warns when both are set); a repo-map change or any edited chat file moves the third breakpoint, and users report 'more caching writes than reads' (#2492) and 'caching does not seem to be working' (#4676), both without maintainer resolution. Orchestration overhead is low by construction: one model call per turn, plus a weak-model call for the commit message and summaries, plus a second editor-model call in architect mode.


## extensions
No plugin system, no tool/function calling, no MCP, no skills, no hooks in upstream aider as of v0.86.2. Edits travel as text edit formats (whole, diff = search/replace blocks, diff-fenced, udiff, editor-diff, editor-whole, patch), chosen per model. Extension points that do exist: conventions files loaded via --read / 'read:' in .aider.conf.yml (the closest thing to a skill; there is a community conventions repo); .aider.model.settings.yml ModelSettings (edit_format, cache_control, caches_by_default, use_repo_map, editor_model_name, editor_edit_format, extra_params passed to litellm, reasoning_tag, system_prompt_prefix, send_undo_reply, lazy, overeager); .aider.model.metadata.json; --alias; --lint-cmd / --test-cmd per language; /run and ! for arbitrary shell with output into chat; /web scraping (Playwright extra); /voice; --watch-files for IDE comments; --copy-paste for web LLMs; /load command scripts; help mode RAG over its own docs ([help] extra); a Python API (Coder.create, coder.run) that is 'not officially supported or documented, and could change'. MCP history: issue #3314 (2025-02-20) unanswered; PR #3672 closed; PR #3937 'Add MCP Support with LiteLLM' (labeled priority, 86 thumbs-up) closed unmerged 2025-11-25 with no maintainer comment; commenters call the project 'maintenance mode'. Third-party: aider-ce/cecli fork adds MCP servers, an 'agent mode' with explicit tool calling and RAG, a skills system, session management, context compaction, TUI options; mcpm-aider bridges MCP via /run. Marketing pages (Warp, VIPS Learn) that claim aider MCP configs should be treated as fabricated for upstream.


## multiAgent
None. Aider is a single agent in a single repo: FAQ says 'Currently aider can only work with one repo at a time.' There are no subagents, no orchestration primitives, no shared state between processes, and no per-agent budgets. The only multi-model structure is inside one turn: architect model proposes, editor model applies (2024-09-26 blog: best score 85% with o1-preview + DeepSeek whole, 'quite slow'; o1-preview + Sonnet diff 82.7% is 'entirely practical'); the weak model writes commit messages and history summaries. Running several aiders in parallel is a community pattern using git worktrees, not a feature. The aider-ce fork advertises an agent mode but not subagents (not verified).


## forkTimeTravel
- supported: partial: linear code rollback via git only. No conversation tree, branching, checkpoint names, or replay; chat turns cannot be rewound or edited (open issues #3607 and #2219 with no maintainer reply).
- ux: /undo = 'Undo the last git commit if it was done by aider'. It restores each file changed in that commit with `git checkout HEAD~1 -- path` then `git reset --soft HEAD~1`, prints 'Removed: <hash> <msg>' and 'Now at: <hash> <msg>'. It refuses when: the commit is not in this session's aider_commit_hashes ('The last commit was not made by aider in this chat session.'), the commit has more than one parent, a changed file has uncommitted changes, a file was not in the previous commit, or the commit was already pushed to origin. Repeated /undo walks back one aider commit at a time (v0.43 'Multiple /undo support'; v0.27 limited it to files of the last commit). /undo does not rewind the chat: history stays, and if the model's send_undo_reply is set aider only sends prompts.undo_command_reply telling the LLM the edit was reverted. /diff shows the diff since the last user message (commit_before_message hashes). /clear wipes history; /drop or /reset wipe files. /save <file> writes a slash-command script (/drop, then /add and /read-only lines) that rebuilds the FILE SET, not the messages; /load replays such a script. --restore-chat-history reloads the previous session's markdown log, summarizing the head if it exceeds the history budget. Branching a line of work means the operator runs /git checkout -b themselves; --no-auto-commits disables /undo entirely.
- dataModel: No session graph, no message ids, no parent pointers. In-memory per process: done_messages (older turns, possibly replaced by a weak-model summary), cur_messages (current turn), abs_fnames and abs_read_only_fnames (sets), aider_commit_hashes (set of hashes made this session; never pruned on undo), commit_before_message (list of HEADs for /diff), last_aider_commit_hash, aider_edited_files. On disk: (1) git commits, one per applied edit plus a 'dirty commit' of pre-existing changes before each edit; author/committer names get an '(aider)' suffix, or since v0.83 a Co-authored-by trailer (--attribute-co-authored-by default True); commit messages by the weak model in Conventional Commits style; pre-commit hooks skipped unless --git-commit-verify. (2) .aider.chat.history.md, an append-only markdown log: session header '# aider chat started at <time>', user turns as '#### ' lines, tool output as '> ' blockquotes, assistant text as plain lines; utils.split_chat_history_markdown parses it back with those prefixes and drops tool lines unless include_tool=True. (3) .aider.input.history (prompt_toolkit FileHistory of typed input). (4) optional .aider.llm.history raw request log (--llm-history-file; one user reports 45MB). (5) .aider.tags.cache.v{N}/ diskcache keyed by file path storing {mtime, tags}. (6) /save files = plain text slash-command scripts. Git's own DAG is the only parent-link structure; snapshots are commits.


## steal
- **One git commit per agent step, with a bounded /undo that refuses unsafe cases (not this session's commit, pushed to origin, merge commit, dirty file, file absent in parent).** — Gives daisugi a physical checkpoint per allowed action for free, and a rollback that is a git operation with explicit refusal reasons the cockpit can display instead of a fuzzy chat-level undo. [https://raw.githubusercontent.com/Aider-AI/aider/main/aider/commands.py]
- **A single per-turn budget line after every model reply: 'Tokens: X sent, Y cache write, Z cache hit, A received. Cost: $B message, $C session.'** — This is the per-step budget cell of a supervision cockpit; showing cache write vs hit per step is what makes cache-aware routing auditable across many agents. [https://raw.githubusercontent.com/Aider-AI/aider/main/aider/coders/base_coder.py]
- **Fixed prompt layering (system, examples, read-only files, repo map, history, chat files, current) with three cache_control breakpoints, plus a keepalive thread that re-sends only the cacheable prefix with max_tokens=1 every ~5 minutes.** — The same ordering keeps an envelope, a garden pathway set, and the repo map as a warm shared prefix across gated agents; the keepalive keeps the prefix alive while an operator deliberates on an allow/deny. [https://aider.chat/docs/usage/caching.html]
- **Confirmation prompts with group semantics: (Y)es/(N)o/(A)ll/(S)kip all/(D)on't ask again, and explicit_yes_required for shell commands so a blanket 'all' cannot approve them.** — Supervising many agents needs batch allow/deny with scoped 'don't ask again', while keeping the riskiest class (shell) out of blanket approvals; this maps directly onto gate verdict UX. [https://raw.githubusercontent.com/Aider-AI/aider/main/aider/io.py]
- **Token-budgeted repo map: tree-sitter tags, PageRank on a file graph personalized to files in chat (x50 edge weight) and identifiers named in the prompt (x10), binary-searched to fit --map-tokens, doubled when no files are in chat, cached by mtime on disk.** — The garden view needs a budgeted, relevance-ranked map of pathways and skills; the personalization-by-mention trick lets an operator steer what is loaded without hand-curating files. [https://aider.chat/docs/repomap.html]
- **/save writes a human-readable slash-command script that reconstructs context; /copy-context exports the exact assembled prompt as markdown.** — Cheap, diffable, replayable checkpoint format; daisugi checkpoints could be command scripts plus an export of the exact envelope the verifier saw. [https://aider.chat/docs/usage/commands.html]
- **Architect/editor split: a reasoning model proposes in prose, a cheap editor model turns it into edits, with --auto-accept-architect as the switch between them.** — It already separates 'decided' from 'applied'; daisugi's gate belongs exactly at that hand-off, and the flag shows the operator-visible toggle to keep. [https://aider.chat/2024/09/26/architect.html]

## avoid
- **/undo rewinds code but not the conversation; chat history has no ids, no edit, no branch, and requests for message-level control (#3607, #2219) sit unanswered.** — A time-travel cockpit must rewind code, envelope, and conversation together; git-only undo leaves the model believing edits exist that the operator removed. [https://github.com/Aider-AI/aider/issues/3607]
- **Edits are applied and committed before the operator sees them; architect mode auto-accepts by default since v0.81, and users found even architect mode 'automatically made the change'.** — A fail-closed gate cannot be opt-in review after the fact; put the approval before apply, not before commit. [https://news.ycombinator.com/item?id=44037295]
- **Cache statistics are hidden under the default streaming mode; operators must run --no-stream to learn whether caching works, and 'caching not working' / 'more writes than reads' issues go unresolved.** — Observability of prefix reuse must not depend on transport mode; show cache write/hit per step regardless of streaming or operators will assume the cache is broken. [https://github.com/aider-ai/aider/issues/4676]
- **Auto-commit granularity does not match the step the operator sees: multi-step work lands in one commit, messages read like inner monologue, and aider commits before linting, so users do 'commit gardening'.** — If a checkpoint per step is the promise, each gated action must be its own commit and validation must run before the commit that the operator will roll back to. [https://slinkp.com/programming-with-aider-20250725.html]
- **Integration demand routed into long-lived PRs with no maintainer decision: MCP PR #3937 (priority label, 86 thumbs-up) closed unmerged after months with no comment, driving a community fork.** — An extension surface needs an explicit accept/reject path; silence forks the ecosystem and splits the garden of shared skills. [https://github.com/Aider-AI/aider/pull/3937]

## loadBearingClaims
- Aider's only rewind is /undo, which reverts the last aider-made git commit of this session with `git checkout HEAD~1 -- file` + `git reset --soft HEAD~1`, refuses if pushed/merge/dirty/not-this-session, and does not rewind or branch the conversation. [https://raw.githubusercontent.com/Aider-AI/aider/main/aider/commands.py]
- With --cache-prompts aider sends a fixed layering (system, examples, read-only files, repo map, history, chat files, current) with three cache_control breakpoints, and --cache-keepalive-pings N re-sends the cacheable prefix with max_tokens=1 up to N times at ~5-minute intervals. [https://aider.chat/docs/usage/caching.html]
- The repo map is a PageRank over a tree-sitter symbol graph, personalized to files in chat and identifiers mentioned in the prompt, binary-searched to fit --map-tokens (default 1k, x2 when no files are in chat). [https://aider.chat/docs/repomap.html]
- Upstream aider (v0.86.2, 2026-02-12) has no MCP, tool calling, plugin, hook, or subagent system; the MCP PR #3937 was closed unmerged on 2025-11-25, and MCP lives only in the aider-ce fork. [https://github.com/Aider-AI/aider/pull/3937]

## verification
- [qualified] Aider's only rewind is /undo, which reverts the last aider-made git commit of this session with `git checkout HEAD~1 -- file` + `git reset --soft HEAD~1`, refuses if pushed/merge/dirty/not-this-session, and does not rewind or branch the conversation. — Source (commands.py main, raw_cmd_undo lines 560-655) confirms the mechanics: refuses when `last_commit_hash not in self.coder.aider_commit_hashes` ("The last commit was not made by aider in this chat session."), when `len(last_commit.parents) > 1` ("more than 1 parent, can't undo"), when any changed file `is_dirty(path=fname)` ("Please stash them before undoing"), and when `local_head == remote_head` for origin/<current_branch> ("already been pushed to the origin"). It then runs `repo.git.checkout("HEAD~1", file_path)` per changed file and `repo.git.reset("--soft", "HEAD~1")`. Two more refusals the claim omits: first commit in repo, and a changed file not present in the previous commit ("Cannot undo safely"). It does NOT touch done_messages/cur_messages, but it is not conversation-neutral: if `main_model.send_undo_reply` it returns prompts.undo_command_reply, which is appended to the chat as a user turn ("I did `git reset --hard HEAD~1` to discard the last edits. Please wait for further instructions..."). Also `/clear` ("Clear the chat history": done_messages=[], cur_messages=[]) and `/reset` (drop all files + clear history) exist, so /undo is not the only conversation-state operation; there is no rewind-to-point, branch, checkpoint or fork command (grep for rewind/branch/checkpoint/fork finds none). Official docs (aider.chat/docs/git.html) only say "/undo will undo and discard the last change." and say nothing about rewinding the chat. GitPython emits `git checkout HEAD~1 <file>` (no `--`), functionally the same. → corrected: Aider's only git rewind is /undo: it reverts the most recent commit only if that commit's hash is in this chat session's aider_commit_hashes, has one parent, none of its changed files are dirty in the worktree, and local HEAD != origin/<branch>; it also refuses on the first commit or if a changed file is absent from HEAD~1. It does `git checkout HEAD~1 <file>` per changed file then `git reset --soft HEAD~1`. It does not rewind or branch the conversation; instead it appends a synthetic user message telling the model the edits were reverted (when send_undo_reply is set). The only other conversation-state controls are /clear and /reset (full wipe), not point-in-time rewind.

- [qualified] The repo map is a PageRank over a tree-sitter symbol graph, personalized to files in chat and identifiers mentioned in the prompt, binary-searched to fit --map-tokens (default 1k, x2 when no files are in chat). — aider/repomap.py (main): imports `from tree_sitter import Query` and grep_ast's tree-sitter language pack; get_ranked_tags() builds `G = nx.MultiDiGraph()` and calls `nx.pagerank(G, weight="weight", personalization=..., dangling=...)`. Nodes are FILES (rel_fname), and each edge is referencer-file -> definer-file labelled with the identifier, weighted by sqrt(num_refs) times multipliers: x10 if `ident in mentioned_idents`, x10 for long snake/kebab/camel names, x50 if the referencer is a chat file, x0.1 for _private or >5 definers. Personalization vector: chat files get `100/len(fnames)`, files in mentioned_fnames get the same (max, no double count), and files whose path components intersect mentioned_idents get it added once. get_ranked_tags_map_uncached(): binary search over the number of ranked tags with lower_bound/upper_bound, starting at `middle = min(max_map_tokens // 25, num_tags)`, accepting the largest tree <= budget and exiting early when within 15% (`ok_err = 0.15`). Defaults: args.py `--map-tokens` default None; main.py 964-965 falls back to `main_model.get_repo_map_tokens()`, which is 1024 floor scaled to max_input_tokens/8 clamped to [1024, 4096] (models.py 782-789), so a 200k-context model defaults to 4096, not 1k. `--map-multiplier-no-files` default 2 (RepoMap class default is 8 but main passes the arg); get_repo_map applies it only when no chat files AND max_context_window is known, capped at `max_context_window - 4096`. The cited docs page says "analyzing the full repo map using a graph ranking algorithm... where each source file is a node and edges connect files which have dependencies", "--map-tokens switch, which defaults to 1k tokens", and that it "does expand the repo map significantly... when no files have been added"; it does not name PageRank, tree-sitter, binary search, or personalization (tree-sitter is named in the 2023-10-22 blog post). --map-refresh default auto. → corrected: The repo map ranks FILES with networkx PageRank over a multi-digraph whose nodes are files and whose edges are tree-sitter-extracted identifier references (referencer -> definer), personalized toward files in chat, files named in the prompt, and files whose path matches a mentioned identifier, with edge weights boosted x10 for mentioned identifiers and x50 for references from chat files. The rendered map is fit to the token budget by a binary search over the number of ranked tags (15% tolerance). The budget is --map-tokens; docs say it defaults to 1k, but the CLI default is None, which resolves to max(1024, min(4096, max_input_tokens/8)), i.e. 1k-4k depending on the model. With no files in chat the budget is multiplied by --map-multiplier-no-files (default 2), capped at context window minus 4096.
