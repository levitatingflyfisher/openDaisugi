# OpenHands (formerly OpenDevin). As of 2026-08 it is three layers: (1) OpenHands/software-agent-sdk (V1; v1.44.0 released 2026-08-27) = openhands-sdk + openhands-tools + openhands-agent-server (REST/WebSocket server that runs many conversations on one host); (2) OpenHands/OpenHands is now 'Agent Canvas' (npm @openhands/agent-canvas 1.15.0, 85.3k stars), a browser control center that connects to one or more Agent Servers and can also drive Claude Code / Codex / Gemini CLI over ACP; (3) OpenHands-CLI. The V0 Python app (AgentController + EventStream + RecallAction microagents) is legacy; the V0→V1 split happened Nov 2025 (SDK announcement 2025-11-12). Most pre-2026 blog material describes V0.


## interactionModel
Operator surfaces. Agent Canvas GUI: a chat panel plus Changes / VS Code / Terminal / App / Browser tabs per conversation; a conversations sidebar; 'Branch from here' on message hover; Settings > Verification (Enable Critic, Iterative Refinement threshold 0.6, max 3 retries), Settings > Condenser, Customize > Skills (/add-skill <github-url>) and Customize > MCP Servers with health states ('Reachable', 'Credential check failed'); an Automate view whose runs carry status PENDING/RUNNING/COMPLETED/FAILED/CANCELLED/SKIPPED and an Activity Log showing LLM cost in USD to four decimals with CSV/JSON export. Canvas can flip between several Agent Servers; each server 'runs multiple agents on a single machine'. The docs do not show a multi-agent supervision dashboard, per-step budget meters, or a branch tree view. CLI: slash commands /help /new /history /confirm /condense /skills /feedback /exit; Ctrl+P command palette; Esc pauses; flags --always-approve, --llm-approve, --headless --json, --resume [id] / --last. Default is 'always ask for confirmation'. Gating (SDK): ConfirmationPolicy = AlwaysConfirm | NeverConfirm | ConfirmRisky(threshold=HIGH, confirm_unknown=True). SecurityAnalyzer: LLMSecurityAnalyzer adds a required `security_risk` (LOW/MEDIUM/HIGH/UNKNOWN) argument to every tool schema so the model rates its own action inline; PatternSecurityAnalyzer (rm -rf, eval, curl|sh), PolicyRailSecurityAnalyzer (composed threats), EnsembleSecurityAnalyzer (max of members); NoOpSecurityAnalyzer returns UNKNOWN which ConfirmRisky treats as needing confirmation (fail-closed by policy, not by proof). Optional Jinja2 `security_policy_filename` embeds org risk rules in the system prompt. Flow: agent emits ActionEvent → analyzer → policy → execution_status WAITING_FOR_CONFIRMATION → operator approves by calling conversation.run() or rejects with reject_pending_actions(reason) which appends a UserRejectObservation the model sees next step. Over HTTP: POST /api/conversations/{id}/events/respond_to_confirmation {accept: bool, reason}; /run; /pause (waits for the in-flight LLM call) vs /interrupt (cancels it); /confirmation_policy; /security_analyzer; /condense; /ask_agent (sidebar question answered without disturbing the run); /goal, /goal/stop, /goal/resume; /fork; /navigate. Live view: WebSocket /sockets/events/{conversation_id} with resend_mode=all|since + after_timestamp. Hooks: PreToolUse, UserPromptSubmit and Stop are blocking; exit code 2 or JSON {"decision":"deny","reason"} denies; evaluator types command / prompt (one LLM call) / agent (sub-agent loop with tool allowlist). Critic: a hosted verifier runs after finish/message, posts a 0-1 success-likelihood score plus issue labels under the evaluated message in the timeline.


## caching
Documented in code, not in the docs pages. Every step re-sends the full active branch: Agent.step calls prepare_llm_messages(state.view, condenser, llm) so there is no server-side session; the saving comes from provider prefix caching plus condensation. Anthropic-only explicit caching: LLM.caching_prompt defaults True, LLM.is_caching_prompt_active() gates on a hard-coded PROMPT_CACHE_MODELS allowlist (claude-* only) in llm/utils/model_features.py. _apply_prompt_caching places exactly two breakpoints: (1) the system message is two content blocks, block 0 = Agent.static_system_message (template only, byte-identical for every agent regardless of AgentContext; a regression test test_prompt_caching_cross_conversation.py fails if any dynamic content leaks in) marked cache_control ephemeral; block 1 = dynamic_context (repo context, skills, secrets, datetime, user suffix) deliberately unmarked, 'to enable cross-conversation cache sharing'; (2) the last user or tool message content block is marked so the cached prefix extends every turn. Tool-role markers are hoisted to message level (litellm issue 6422). Gemini is excluded on purpose: 'explicit cache_control markers freeze its cache at the static prefix and disable Google's implicit caching on the growing body (~6-14x cost)'. OpenAI: prompt_cache_key and prompt_cache_retention fields; Responses-API replays echo function_call ids verbatim 'so replays stay byte-identical and OpenAI's prefix cache keeps matching'. On a provider 'prompt cache too small' error the call retries with caching off. Condenser: LLMSummarizingCondenser (code defaults max_size=240 events, keep_first=2, optional max_tokens now capped by the agent's context limit since v1.43; docs pages say 120/4). Condensation is itself an event {forgotten_event_ids, summary, summary_offset}; the view drops forgotten events and inserts a CondensationSummaryEvent, so the cached prefix survives keep_first and is invalidated once per condensation. Manual /condense endpoint and CondensationRequest on context-window errors. Metrics per LLM usage_id record cache_read_tokens, cache_write_tokens, per_turn_token, context_window and a cache-hit ratio, and ConversationStats aggregates them (v1.40 added LLM cost reporting). No cache-aware routing; no documented prefix-hash diagnostics. Multi-agent overhead is bounded by isolation rather than caching: sub-agents have their own event logs and return only a result observation, and ask_oracle/ask_agent are stateless one-shot calls.


## extensions
Skills (renamed from microagents): Markdown + YAML frontmatter; preferred location .agents/skills/<name>/SKILL.md, legacy .openhands/skills/ and .openhands/microagents/, user-level ~/.agents/skills/, public registry OpenHands/extensions; precedence project > user > public. Trigger kinds: always-on (AGENTS.md / trigger None → system prompt), keyword (`triggers:` list, matched against user messages only, content joins AgentContext in the system prompt), task (keyword + user inputs), path rules (glob; injected once per conversation as an <EXTRA_INFO> block in the tool ObservationEvent's extended_content, tracked in ConversationState.activated_path_rules, excluded from the <available_skills> catalogue so zero baseline cost), and named skills with progressive disclosure (name+description up front, body on invoke). Plugins: plugin.json bundling skills, hooks/hooks.json, .mcp.json, agents (.agents/agents/*.md with name, description with <example> tags, tools, model 'inherit', skills, max_iteration_per_run, permission_mode always_confirm|never_confirm|confirm_risky, hooks, mcp_servers, color) and slash commands; marketplaces addressed as plugin@marketplace; conversation.load_plugin() and POST /load_plugin. Hooks: six events (PreToolUse*, PostToolUse, UserPromptSubmit*, Stop*, SessionStart, SessionEnd; * = blocking), matchers by tool name, three evaluator types (command shell script, prompt = one LLM call, agent = sub-agent loop with optional tool allowlist), JSON decision contract {"decision":"allow"|"deny","reason"}, only exit code 2 blocks. MCP: native, with dynamically advertised tools, settings CRUD endpoints and per-server enable/disable (v1.39-1.43). ACP: ACPAgent spawns Claude Code / Codex / Gemini CLI over JSON-RPC stdio; permission requests are auto-granted; usage read from PromptResponse.usage and UsageUpdate; if the ACP session store is wiped the SDK resumes by rendering its own event log as a bootstrap transcript ('<<RESUMED CONVERSATION>>'). Observability: Laminar / OpenTelemetry spans, LLMCompletionLogEvent streams per-call logs to clients, Prometheus not built in. Extras: ask_oracle tool (stateless second opinion from a stronger saved LLM profile named 'oracle'), switch_llm, Critic verifier, canvas extensions manifest (v1.41), structured output (v1.42).


## multiAgent
Two SDK mechanisms, both blocking. DelegateTool: `spawn` creates sub-agent conversations (max_children default 5) and `delegate` sends tasks to all of them in parallel Python threads and thread.join()s until every one finishes, returning one DelegateObservation. TaskToolSet (`task` tool, the CLI's replacement for DelegateTool): sequential, blocks the parent, returns TaskObservation with task_id like task_00000001 which can be passed back as `resume` to continue a persisted sub-conversation; sub-agent types come from factory registration or file-based .agents/agents/*.md; `subagent_type` selects one; model 'inherit' shares the parent LLM; the workspace is shared; max_iteration_per_run cascades definition → parent (Conversation default 500). Sub-agents keep their own event logs so their exploration never enters the parent's context (the parent only sees the result text). When a sub-agent hits WAITING_FOR_CONFIRMATION the tool invokes a ConfirmationHandler callback so gating propagates. The agent-server persists parent_conversation_id and derives sub_conversation_ids so Agent Canvas can rebuild the parent/child tree after reload. Non-blocking background delegation (task ids, check_status, get_output, stop) is an open issue since 2026-02-13 (#2047). V0's AgentDelegateAction-based delegation hung on pending RecallAction and the bug was closed 'not planned' (#8187). Goal loop: a second judge LLM audits the transcript after FinishAction → {score, complete, missing}; re-prompts with `missing` until complete or max_iterations (default 10) → status complete|capped. Automations server dispatches scheduled/webhook/event runs to the Agent Server; when the backend hits its concurrency limit runs are SKIPPED. Canvas can run OpenHands, Claude Code, Codex, Gemini side by side as separate conversations but offers no cross-agent orchestration view.


## forkTimeTravel
- supported: yes (partial UI). SDK-level conversation tree with fork-from-event and in-place HEAD navigation landed 2026-07-02 (PR #3922, HTTP in #3923); Agent Canvas exposes only 'Branch from here' (fork), no rewind-in-place, no tree view, no keyboard shortcuts; CLI has no fork/rewind/replay commands.
- ux: SDK: conversation.fork(from_event_id=..., agent=..., title=..., tags=..., reset_metrics=True) returns a new LocalConversation that shares the same working directory (workspace is NOT snapshotted) and starts idle; conversation.navigate_to(event_id | None) moves HEAD inside the same conversation ('appending after navigating creates a sibling; abandoned events stay in the log but drop out of state.view'). HTTP: POST /api/conversations/{id}/fork {id,title,tags,reset_metrics,from_event_id}; POST /api/conversations/{id}/navigate {event_id}. Agent Canvas: hover a user or assistant message → 'Branch from here' → a new conversation opens with history through that point; for a user message the text is pre-filled in the composer for editing; the original stays in the sidebar; 'branches can be branched again'; requires a local agent-server backend that supports forks. No documented shortcut keys, no diff between branches, no checkpoint naming. Replay: V0 had config `replay_trajectory_path` (re-executes non-user actions from an exported trajectory.json, then hands over to the live agent; PR #6215, Jan 2025) and a web-app replay behind a feature flag; the V1 SDK's own skill file says 'CLI: No replay/export commands'. A separate trajectory-visualizer web app does linear playback of exported trajectory JSON with arrow-key navigation.
- dataModel: Per conversation: workspace/conversations/<conversation-uuid>/base_state.json (agent config, execution_status, stats, secrets, agent_state, leaf_event_id, head_is_empty) plus events/event-{idx:05d}-{event_id}.json (one JSON file per event, index zero-padded to at least 5 digits, event ids uuid4). Every Event is a frozen Pydantic model with id, timestamp (ISO), source (user|agent|environment) and parent_id ('Events sharing a parent_id are sibling branches'; None = root or legacy event; sentinel ROOT_PARENT_ID marks an explicit root created later). Storage stays linear and append-only; the tree is logical: EventLog.path_to_root(leaf), children_of, get_by_id. ConversationState.leaf_event_id is the movable HEAD, persisted by autosave into base_state.json. The LLM context is View.from_events(path_to_root(HEAD)) with Condensation events applied; the view is maintained incrementally O(k) on append and rebuilt once on a branch switch. Legacy events without parent_id resolve to index-1 (zero migration). Fork lineage is persisted on the server's StoredConversation and shown on ConversationInfo as forked_from_conversation_id, forked_from_event_id, leaf_event_id; separately parent_conversation_id and derived sub_conversation_ids link sub-agent conversations (PR #4188, cycle-checked). fork(from_event_id) deep-copies only path_to_root(event) into a new conversation dir and sets HEAD there; fork() with no event copies the whole log. Stats reset on fork by default. ActionEvents persist thinking/reasoning blocks so replays stay byte-identical.


## steal
- **Logical event tree over a linear append-only log: every event carries parent_id, the conversation has a movable HEAD (leaf_event_id), context = path_to_root(HEAD), fork(from_event_id) copies one branch, navigate_to(event_id) rewinds in place; legacy events fall back to index-1 so there is zero migration.** — Gives daisugi branch/rewind/replay over the prompt tree while every abandoned branch stays on disk for the audit trail, and it fits the existing journal shape (append-only files) without a new store. [https://github.com/OpenHands/software-agent-sdk/pull/3922]
- **Two-block system prompt: block 0 is a byte-identical static template marked for caching and guarded by a regression test; block 1 carries all per-conversation context unmarked; a second cache breakpoint rides the last user/tool message.** — A cockpit supervising many gated agents can share one cached static prefix across the whole fleet; the regression test is the cheap way to keep dynamic content (dates, hostnames, budgets) from silently breaking the prefix. [https://github.com/OpenHands/software-agent-sdk/blob/main/tests/sdk/llm/test_prompt_caching_cross_conversation.py]
- **Condensation as an event ({forgotten_event_ids, summary, summary_offset}) applied at view time, with keep_first protecting the prefix and a manual /condense endpoint.** — The garden and cockpit can show exactly what an agent forgot and when, the store stays immutable, and the cache prefix is invalidated once per condensation instead of every step. [https://docs.openhands.dev/sdk/arch/condenser]
- **Deny-with-reason becomes an observation: reject_pending_actions(reason) appends a UserRejectObservation the model sees next step; the risk signal is an ensemble (deterministic pattern analyzers + policy rails + optional LLM self-rating) taking the max, and UNKNOWN is treated as risky.** — daisugi's Z3 verdict should be fed back as the 'why' the agent reads, and a cheap self-rating column beside the proof is useful display data as long as it never gates. [https://docs.openhands.dev/sdk/guides/security]
- **Hook decision contract: PreToolUse/UserPromptSubmit/Stop are blocking; exit code 2 or JSON {"decision":"deny","reason"} denies; evaluator kinds command / prompt / agent with a tool allowlist.** — This is the direct mount point for daisugi's gate inside OpenHands (one PreToolUse command hook), and a proven shape for daisugi's own plugin hooks. [https://docs.openhands.dev/sdk/guides/hooks]
- **Path-triggered rules injected once per conversation into the tool observation, excluded from the skill catalogue, tracked in activated_path_rules.** — Garden pathways can attach to files deterministically at zero baseline prompt cost, and the once-per-conversation tracking is what the 'reuse' counter in the garden view needs. [https://docs.openhands.dev/sdk/arch/skill]
- **Per-usage_id metrics with cache_read/cache_write/per_turn tokens and cost, /interrupt (cancel in-flight) distinct from /pause (finish the call), and /ask_agent for a sidebar question that does not disturb the run; Critic posts a 0-1 success score under each finish.** — These are the per-step budget, cache-hit and 'what are you doing' affordances the supervision cockpit needs, and the score-under-the-message placement is a clean way to surface verdicts in a timeline. [https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-agent-server/openhands/agent_server/conversation_router.py]

## avoid
- **Blocking delegation: DelegateTool thread.join()s until every sub-agent finishes and TaskToolSet runs sub-agents one at a time; a background mode with task ids has been an open request since Feb 2026.** — A cockpit for many agents cannot be built on a parent that stalls; daisugi should make sub-agent runs first-class conversations with status polling from day one. [https://github.com/OpenHands/software-agent-sdk/issues/2047]
- **Fork shares the working directory ('Workspace: Shared (same working directory)'); branches from an earlier prompt run against a filesystem that already contains the later branch's edits.** — Time travel over the prompt tree without a workspace snapshot produces branches that are not reproducible; daisugi should pair a fork with a git worktree or snapshot id. [https://docs.openhands.dev/sdk/guides/convo-fork]
- **Security risk supplied by the policed model: a required security_risk argument is injected into every tool schema, so models that do not emit it break tool calling and a mismatch crashed the CLI ('LLM provided a security_risk but no security analyzer is configured').** — The gate must not depend on the agent's cooperation or on schema changes the model may ignore; keep self-ratings advisory and out of the tool contract. [https://github.com/OpenHands/OpenHands/issues/11309]
- **Skill-location and trigger churn: three generations of directories (.openhands/microagents → .openhands/skills → .agents/skills), keyword triggers on user messages only, and the maintainers' own simplification proposal went stale.** — Garden pathways need one stable on-disk contract and a trigger rule that also sees agent output; do not ship a format you plan to rename. [https://github.com/OpenHands/OpenHands/issues/7547]
- **Caps instead of budgets and docs that drift from code: max_iteration_per_run defaults to 500, condenser defaults are 240/2 in code but 120/4 in docs, Gemini caching was silently off, and reviewers report loops burning tokens before stuck detection fires.** — daisugi's per-step budget should be an envelope term the verifier checks, surfaced in the cockpit, with defaults read from one source of truth. [https://dev.to/truongpx396/openhands-deep-dive-build-your-own-guide-1al0]

Evaluator types table: `command` (default), `prompt` (one LLM completion, no tools), `agent` (short-lived sub-agent, optional tool allowlist); source config.py:39-44 `class HookType(StrEnum): COMMAND, PROMPT, AGENT`. Source confirms the deny paths (hooks/executor.py:557-588): `blocked=result.returncode == 2`, then stdout JSON `decision == "deny"` sets `blocked = True` and `continue: false` also sets `blocked = True` — so JSON deny blocks a command hook even with exit 0, which is stronger than the docs' 'only exit code 2 blocks' wording. Important caveats for a fail-closed design: prompt/agent hooks with a missing or unparseable decision default to ALLOW (executor.py:431-439: 'returned an invalid decision ... defaulting to allow'); async hooks in PreToolUse cannot block (manager.py:80-84 warning 'Async hooks in PreToolUse cannot block tool execution'); PostToolUse results are only logged/emitted, never block (conversation_hooks.py:178-242); a Stop deny returns additionalContext/reason as feedback and the agent keeps running (conversation_hooks.py:354-388); hooks run in order and stop at the first block (`execute_all(..., stop_on_block=True)`). → corrected: Of six hook events (PreToolUse, PostToolUse, UserPromptSubmit, Stop, SessionStart, SessionEnd) only PreToolUse, UserPromptSubmit and Stop can block. A command hook blocks on exit code 2, or on stdout JSON {"decision":"deny"} or {"continue":false} regardless of exit code; exit 1 and other non-zero codes are non-blocking errors. Prompt and agent hooks block only by returning {"decision":"deny","reason":...}; a missing or invalid decision defaults to allow (fail-open), and async PreToolUse hooks cannot block. Evaluator types are command (default), prompt, and agent. A Stop deny keeps the agent running with the reason/additionalContext fed back.
