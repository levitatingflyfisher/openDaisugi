# Claude Code (Anthropic CLI), v2.1.247 as of 2026-08-27


## interactionModel
Terminal TUI, one live conversation per process. Prompt box takes plain text, `/` skills and built-in commands, `@` file/agent mentions, `!` shell mode; messages typed while Claude works are queued (Up takes them back). Approval UX is per tool call: Shift+Tab cycles permission modes (Manual default, acceptEdits, plan, auto = a background classifier that blocks risky actions and is the starting mode on Pro/Max/Team, dontAsk, bypassPermissions). Allow/deny rules live in settings.json; PreToolUse hooks can deny (exit 2) or return JSON `permissionDecision: allow|deny|ask` with `permissionDecisionReason` and a rewritten `updatedInput`; a PermissionRequest hook can answer prompts. Esc interrupts; Esc Esc on an empty input opens the rewind menu. Supervision surfaces: (1) the agent panel under the prompt lists subagents/teammates (Up/Down select, Enter opens its transcript and lets you type to it, Esc interrupts it, x stops it); (2) `/tasks` shows running shells and subagents with model + effort per subagent (v2.1.243); (3) `/workflows` shows a fan-out run as phases with agent counts, token totals and elapsed time, with keys p pause, x stop, r restart, s save-as-command; (4) `claude agents` (agent view, research preview) is one screen for all background sessions grouped Needs input / Working / Completed, with a peek panel (Space) that shows the exact question a blocked session is waiting on and lets you reply inline; `claude agents --json` exposes `state` and `waitingFor` (`permission prompt`, `input needed`, `sandbox request`, ...). Permission prompts for teammates bubble to the lead's terminal; from agent view you answer a permission prompt by typing a reply or attaching, there is no one-key approve. Ctrl+O toggles a transcript viewer; `/context` and `/usage` show what fills context and cache read/write tokens; `/btw` asks a tool-less side question outside history; a statusline script can read `current_usage.cache_read_input_tokens` live.


## caching
Documented in detail. Every turn re-sends the full context ('Claude Code sends your full conversation with every request'); savings come only from prefix caching, never from omitting context. Request order is fixed so the stable part comes first: (1) system prompt = core instructions + tool definitions + output style (changes only on tool-set change or upgrade), (2) project context = CLAUDE.md, auto memory, unscoped rules (reloaded on /clear, /compact, restart), (3) conversation. Rules that keep the prefix byte-stable: all tools stay in every request (plan mode is EnterPlanMode/ExitPlanMode tools, not a tool swap); MCP tools are sent as `defer_loading` stubs and fetched via ToolSearch so a server connecting/disconnecting only appends; skills, commands and plan-mode instructions are injected as user messages; file changes are announced with an appended `<\system-reminder>` rather than an edit; CLAUDE.md and output-style edits do not apply until restart precisely so they cannot break the prefix; `/rewind` truncates to an already-cached prefix; `/recap` appends rather than replaces. Invalidators: `/model`, `/effort`, fast-mode header, prefix-loaded MCP tools changing, plugins that add MCP servers, denying a whole built-in tool, `/compact`, upgrading. Compaction itself is 'a fork of a cached call': same prefix plus a summarization instruction, so it reads the cache while warm. Forks and `/subtask` share the parent's cache; ordinary subagents build their own. Workflow fan-outs hold all but the first sibling until its response starts (cap `CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS`=5000) so siblings read one prefix. TTL: 1 hour for the main conversation on a subscription within plan usage, 5 minutes for subagents/teammates/workflows and for API-key or usage-credit billing; `promptCacheTtl` / `subagentPromptCacheTtl` (`5m`|`1h`, v2.1.242+), `ENABLE_PROMPT_CACHING_1H`, `FORCE_PROMPT_CACHING_5M`. Cache key includes cwd, platform, memory paths and the git-status snapshot, so it is per machine and directory; `--exclude-dynamic-system-prompt-sections` moves those into the first user message for cross-user reuse. Anthropic's own rule: 'We alert on cache breaks and treat them as incidents.' Measurement: `/usage` shows cache read vs cache write tokens and flags 'cache misses' behavior; statusline gets `cache_creation_input_tokens`/`cache_read_input_tokens`; OpenTelemetry exports them. Context management beyond caching: auto-compact clears old tool outputs first, then summarizes (Sonnet 5 default window = full 1M as of 2.1.247); it stops with a 'thrashing' error if a single output refills context; `/context` shows the breakdown; the 'resume from summary' dialog appears on Pro/Max when a >100k-token session is resumed after ~1h. Multi-agent overhead is not hidden: teams ~7x tokens in plan mode; subagents cost a full separate context each.


## extensions
Layered, file-based, mostly Markdown-with-frontmatter, merged by precedence. CLAUDE.md (always loaded, additive across levels; keep <200 lines) and `.claude/rules/*.md` (optionally `paths:`-scoped). Skills = `SKILL.md` in `~/.claude/skills`, `.claude/skills`, plugins or synced from claude.ai; custom commands were merged into skills; frontmatter: `name`, `description`, `argument-hint`, `disable-model-invocation`, `user-invocable`, `allowed-tools` (turn-scoped grant), `model`, `effort`, `context: fork` (+ `agent`, `background`), `hooks`, `paths`; body uses `$ARGUMENTS`/`$0`; descriptions are in every request, bodies load on use. Subagents = `.claude/agents/*.md` (or `--agents` JSON, managed settings, plugins): `tools`/`disallowedTools`, `model`, `permissionMode`, `maxTurns`, `skills` (preloaded), `mcpServers`, `hooks`, `memory` scope, `background`, `effort`, `isolation: worktree`, `initialPrompt`. Hooks (settings.json, plugins, skill/agent frontmatter): events include SessionStart/End, Setup, UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, PostToolBatch, PermissionRequest, PermissionDenied, Stop, SubagentStart/Stop, TeammateIdle, TaskCreated/Completed, PreCompact/PostCompact, FileChanged, ConfigChange, WorktreeCreate/Remove, Elicitation; handler types command / http / mcp_tool / prompt (LLM judge) / agent (subagent verifier); matchers by tool name or regex plus `if: "Bash(rm *)"` conditions; exit 0 = allow (JSON on stdout parsed), exit 2 = block with stderr fed back, other = non-blocking; payload carries `session_id`, `transcript_path`, `cwd`, `permission_mode`, `tool_name`, `tool_input`, `tool_use_id`, `agent_id`, `agent_type`; hooks also run inside subagents. MCP: scopes local > project > user, tools named `mcp__<server>__<tool>`, deferred by tool search, `alwaysLoad` opt-out. Plugins bundle skills, agents, hooks, MCP servers, workflows, LSP servers and themes, namespaced `/plugin:skill`, distributed via marketplaces. Dynamic workflows: JS scripts (`agent()`, `pipeline()`, `args`) that Claude writes, saved to `.claude/workflows/` as `/name` commands; 16 concurrent agents, 1,000 per run. Precedence: skills managed > user > project; agents managed > CLI > project > user > plugin; MCP local > project > user; hooks merge. `--bare` skips all discovery for reproducible headless runs.


## multiAgent
Four mechanisms, all local-process. (1) Subagents via the Agent tool: own context window and system prompt, summary returns to the caller; foreground blocks the turn, background runs concurrently with a reduced tool set (default in interactive sessions since 2.1.232); limits 20 concurrent (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`), nesting depth 3; transcripts persist per `agentId` and a finished subagent can be resumed with `SendMessage(to: name|id)` keeping its full history; forks (`subagent_type: fork`, `/subtask`, `/btw` then `f`) inherit the whole conversation and the parent's cache; since 2.1.210 subagent reports are scanned and marked when they contain instruction-shaped text. (2) Agent teams (experimental, `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`): the lead session spawns teammates that are full Claude Code sessions; they communicate through JSON mailbox files under `~/.claude/teams/<name>/inboxes/`, share a task list under `~/.claude/tasks/<name>/` claimed with file locking, and support plan-approval gating and quality-gate hooks (TeammateIdle/TaskCreated/TaskCompleted exit 2 sends feedback and keeps them working); display in-process or as tmux/iTerm2 panes; teammate permission prompts bubble to the lead; messages between agents are marked as not-from-user and cannot approve anything; costs roughly 7x a single session in plan mode; `/resume` and `/rewind` do not restore in-process teammates; a named subagent silently becomes a teammate while the flag is on. (3) Dynamic workflows: a script holds the plan and intermediate results, agents run in the background, results are cached for resume, progress and per-agent tokens are shown in `/workflows`. (4) Cross-session messaging (v2.1.224+): `ListAgents`/`SendMessage` between independent sessions over a per-session Unix socket (`CLAUDE_CODE_MESSAGING_SOCKET`), with inbound `accept|hold|refuse`, loop throttling, and a 'notify when idle' one-shot. Observability: `claude agents --json` lists sessions with `state`/`waitingFor`; headless `stream-json` tags subagent messages with `parent_tool_use_id` (and `--forward-subagent-text` includes their text) so a consumer can rebuild the nesting tree; hooks receive `agent_id`/`agent_type`. Token accounting per agent exists in `/usage` attribution and the workflow view, not in a single per-step budget control.


## forkTimeTravel
- supported: partial: linear rewind + copy-forks. Rewind moves the active leaf back inside one session; `/branch`/`--fork-session`/`/fork` copy the transcript to a new session ID. There is no tree view and no command that navigates a prompt tree; abandoned tails stay on disk but are unreachable from the UI (issue #55347, closed not planned).
- ux: `/rewind` or Esc Esc (empty input) opens a menu listing every user prompt of the session. Pick a prompt, then one of: Restore code and conversation, Restore conversation, Restore code, Summarize from here, Summarize up to here, Never mind. Code-restore rows appear only when that checkpoint has tracked file changes. After Restore conversation or Summarize from here, the original prompt text is put back into the input box so you edit and re-send (this is the 'edit an earlier prompt' flow; there is no separate keybinding). Summarize rows accept optional guidance text. Rewind truncates to a prefix that is already in the prompt cache, so the next turn is cheap. Rewind past `/clear` shows a `/resume <id> (previous session)` row (v2.1.191+). Branching: `/branch [name]` copies the conversation so far into a new session ID and switches the running process to it (permission grants, background subagents and Remote Control follow you); `claude --continue|--resume <x> --fork-session` does the same from the shell in a new process (grants do not carry); `/fork` (v2.1.212+) copies the conversation into a new background session while the original keeps running; `/subtask <prompt>` and `subagent_type: fork` start a subagent that inherits the whole conversation and reads the parent's prompt cache. `/resume` picker: Up/Down, Space previews, Ctrl+R renames, Ctrl+A all projects, Ctrl+W all worktrees, Ctrl+B current branch; forks appear as separate rows and duplicate entries for one session are grouped under one row (Right expands). Limits: checkpoints only track edits made by Claude's file-editing tools (not Bash `rm/mv/cp`, not most subagent edits, not your editor), skip symlinked/hard-linked paths, keep the 100 most recent checkpoints, and are deleted with the session after `cleanupPeriodDays` (30). `/rewind` does not restore in-process teammates.
- dataModel: Observed directly via local inspection (v2.1.247) plus docs. Transcript: `~/.claude/projects/<cwd with non-alnum→'-'>/<sessionId>.jsonl`, append-only, one JSON object per line, described by Anthropic as 'internal to Claude Code and changes between versions'. Message records: `uuid`, `parentUuid` (null = root), `isSidechain`, `sessionId`, `timestamp`, `cwd`, `gitBranch`, `version`, `entrypoint`, `userType`, `slug`, `promptId` (user), `requestId`/`effort`/`advisorModel` (assistant), `message{role, content[], id, model, usage}`, `toolUseResult` + `sourceToolAssistantUUID` on tool-result records, `isMeta`. A multi-block assistant reply is written as one record per content block; siblings share `message.id` (many such records within one large transcript). Rewind is in-file: the next human prompt's `parentUuid` points at an earlier uuid, so the file is a DAG (observed several human prompts whose parent was not the previous record; many uuids with more than one child), and metadata records with no uuid track the head: `{type:'last-prompt', leafUuid, sessionId}` plus `ai-title`, `custom-title`, `agent-name`, `agent-color`, `mode`, `permission-mode`, `queue-operation`, `frame-link`. No `summary` record type was present in current files (older schema writeups list one). Compaction: a `system` record `subtype:'compact_boundary'` with `logicalParentUuid` and `compactMetadata{trigger:'auto'|'manual', preTokens, postTokens, durationMs, preservedSegment{headUuid, anchorUuid, tailUuid}, preservedMessages{uuids}}`, followed by a `user` record `isCompactSummary:true, isVisibleInTranscriptOnly:true` carrying the summary. Checkpoints: `file-history-snapshot{messageId, snapshot{trackedFileBackups{path→...}}, isSnapshotUpdate}` and `file-history-delta{messageId, snapshotMessageId, trackingPath, backup{backupFileName, version, backupTime}}` records inside the transcript; file contents live at `~/.claude/file-history/<sessionId>/<16-hex>@v<N>` (many files locally). Forks: `/branch`/`--fork-session` copy the transcript to a new `<newUuid>.jsonl` (a VS Code bug report describes the copy as 'truncated at the chosen message, full history intact', and notes a copy without `custom-title`/`ai-title`/`last-prompt` rows is invisible to the picker); no parent-session link is written into the copy. Subagents: `<project>/<sessionId>/subagents/agent-<id>.jsonl`, every line `isSidechain:true` with `agentId` and the parent `sessionId`, but no parent `tool_use_id` (issue #32175). Big tool outputs spill to `<sessionId>/tool-results/<id>.txt`; workflow runs to `<sessionId>/workflows/wf_*.json`. Teams: `~/.claude/teams/session-<8 chars>/config.json` + `inboxes/<agent>.json`; tasks: `~/.claude/tasks/<name>/`. Prompt recall: `~/.claude/history.jsonl` `{display, pastedContents, timestamp, project, sessionId}`. Each running session also writes a small liveness file in `~/.claude/sessions/`.


## steal
- **Append-only JSONL per session where every record has `uuid` + `parentUuid`, a tiny `last-prompt {leafUuid}` head pointer, and checkpoint records (`file-history-snapshot`/`file-history-delta`) interleaved in the same log; file contents stored content-addressed under `file-history/<session>/<hash>@v<N>`. Rewind = move the head pointer; branch = copy the file to a new id.** — Crash-safe, greppable, and cheap: daisugi's prompt tree, gate decisions and envelope snapshots can be one log with parent links, and 'rewind' never rewrites history, which also keeps the prompt-cache prefix valid. [https://code.claude.com/docs/en/how-claude-code-works#work-with-sessions (format observed directly in ~/.claude/projects)]
- **The rewind menu separates code from conversation and offers five actions (restore both / conversation only / code only / summarize from here / summarize up to here), shows code-restore rows only when that checkpoint has tracked edits, and drops the original prompt back into the input box so the operator edits and re-sends.** — For a gate cockpit the equivalent split is 'rewind the envelope/world state' vs 'rewind the dialogue'; the edit-and-resend affordance is the whole 'edit an earlier prompt' feature with zero new UI. [https://code.claude.com/docs/en/checkpointing]
- **Never mutate the cached prefix: keep every tool in every request (mode changes are tools, e.g. EnterPlanMode), send deferred tool stubs instead of removing tools, inject skills/plans as user messages, announce world changes as an appended `<\system-reminder>`, and alert on cache-miss rate as an incident.** — daisugi's per-step gate verdicts and envelope updates should be appended to the tail (a reminder block), never spliced into the system prompt, or every gated step pays a full re-read. [https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything and https://code.claude.com/docs/en/prompt-caching]
- **Fork subagents that inherit the exact parent prefix so their first request is a cache read, and a fan-out stagger: hold sibling agents (≤5 s) until the first sibling's response starts so all read one cached prefix.** — Directly cuts multi-agent orchestration token overhead; a gate that spawns N verifiers or explorers from the same context should stagger them the same way. [https://code.claude.com/docs/en/workflows#prompt-caching-in-a-fan-out and https://code.claude.com/docs/en/sub-agents#fork-the-current-conversation]
- **Enforcement lives in hooks, not prompts: PreToolUse exit 2 blocks and feeds stderr back to the model; JSON `permissionDecision` allow/deny/ask with `permissionDecisionReason` and `updatedInput` can rewrite the call; every payload carries `session_id`, `transcript_path`, `tool_use_id`, `agent_id`, `agent_type`, and hooks fire inside subagents too.** — This is the exact contract daisugi's Z3 gate already plugs into; the reason string is what the cockpit should display as 'deny + why', and `agent_id` is the join key for a many-agent view. [https://code.claude.com/docs/en/hooks]
- **Agent view groups sessions by what the operator must do (Needs input / Working / Completed), exposes a `waitingFor` enum in `--json` (`permission prompt`, `input needed`, `sandbox request`...), and a peek panel that shows only the pending question with an inline reply box instead of the full transcript.** — A cockpit for many gated agents should lead with 'what is blocked on me and why', not with transcripts; the enum makes it scriptable. [https://code.claude.com/docs/en/agent-view]
- **Workflow progress view: phases with agent counts, token totals and elapsed time; per-agent drill-down to prompt, recent tool calls and result; `Large workflow` advisory at 25 agents or 1.5M projected tokens; stop/resume that replays cached agent results.** — Gives the garden/observability lens a concrete layout for 'tokens per phase' and 'tokens saved by reuse', and the advisory threshold is a cheap per-step budget signal. [https://code.claude.com/docs/en/workflows#watch-the-run]

## avoid
- **Calling an in-place rewind a 'fork'. `/rewind` moves the head pointer inside one file; the abandoned tail stays on disk but disappears from `/resume`, while the UI text says 'The conversation will be forked'. Issue closed as not planned.** — Operators lose branches they believed were preserved; a prompt tree must make every leaf addressable or must not promise forks. [https://github.com/anthropics/claude-code/issues/55347]
- **An undocumented, version-unstable transcript schema. Anthropic says the JSONL 'is internal to Claude Code and changes between versions'; upgrades have broken `parentUuid` chains so resumed sessions showed only the last message; forked copies without title/last-prompt rows are invisible to the picker; subagent files carry no parent `tool_use_id`, so tracing tools must guess by timestamp.** — daisugi's gate log is a record of evidence; it needs a published, versioned schema with explicit parent-session and parent-tool-call links from day one. [https://github.com/anthropics/claude-code/issues/24304 , https://github.com/anthropics/claude-code/issues/85008 , https://github.com/anthropics/claude-code/issues/32175]
- **Partial undo presented as undo: checkpoints cover only edits made through Claude's file tools, not Bash `rm/mv/cp`, not background-subagent edits, not symlinked paths; capped at 100 checkpoints and 30 days.** — A fail-closed gate cannot rely on a snapshot layer that silently skips whole classes of actions; either snapshot at the gate (every allowed effect) or say plainly what is not covered. [https://code.claude.com/docs/en/checkpointing#limitations]
- **Agent teams as separate full sessions coordinating through JSON mailbox files and tmux panes: ~7x tokens, teams that form unasked when a subagent is merely named, no resume of in-process teammates, task status that lags, and a flag that is an env var rather than a setting.** — Coordination overhead and token cost scale with the number of full contexts; daisugi should keep supervisors thin (shared prefix, forks) and treat 'team' as a view over gated agents, not a second process model. [https://code.claude.com/docs/en/agent-teams#limitations and https://code.claude.com/docs/en/costs#agent-team-token-costs]
- **Lossy auto-compaction as the default context strategy: the docs admit 'detailed instructions from early in the conversation may be lost', users describe post-compact Claude as having 'forgotten everything', and a thrash guard had to be added when one big output refills context after every summary.** — In a safety layer the envelope and standing constraints must never be subject to summarization; keep them in the stable prefix or re-inject them structurally after every compaction boundary. [https://code.claude.com/docs/en/how-claude-code-works#when-context-fills-up and https://bytebell.ai/blog/claude-code-compacting-losing-work/]

## loadBearingClaims
- Rewind is in-place inside one append-only JSONL: the new prompt's parentUuid points to an earlier uuid, no new session ID is created, and the abandoned tail becomes unreachable from /resume; the only fork mechanisms (/branch, --fork-session, /fork) copy the transcript to a new session ID and show up as separate picker rows. There is no tree-navigation command. [https://code.claude.com/docs/en/sessions#branch-a-session (behavior of rewind confirmed by https://github.com/anthropics/claude-code/issues/55347 and local transcript inspection)]
- A PreToolUse hook can block a tool call fail-closed by exiting 2 (stderr fed to the model) or by returning JSON {hookSpecificOutput:{permissionDecision:'deny'|'allow'|'ask', permissionDecisionReason, updatedInput}}, and the same hooks run inside subagents with agent_id/agent_type in the payload. [https://code.claude.com/docs/en/hooks]
- Claude Code re-sends the full context every turn and relies purely on prefix caching (order: system prompt+tools → project context → conversation); all tools stay in every request, MCP tools are deferred stubs, changes are appended as <\system-reminder>, /rewind hits the earlier cache entry, forks reuse the parent's cache, and fan-out siblings are staggered up to 5 s to share a prefix. [https://code.claude.com/docs/en/prompt-caching]
- Checkpoints snapshot only files written by Claude's own editing tools (not Bash, not most subagent edits), are stored as file-history-snapshot/delta records in the transcript plus content files in ~/.claude/file-history/<session>/, keep the 100 most recent checkpoints, and survive resume but not the 30-day sweep. [https://code.claude.com/docs/en/checkpointing]

Fail-closed behaviour must be engineered inside the hook (exit 2 on any internal error, an internal deadline well under the hook timeout).
