# k9s + lazygit + lazydocker (TUI cockpits). Versions as of 2026-08: k9s v0.51.0 (2026-06-06), lazygit v0.64.1 (2026-08-12; maintainer Stefan Haller since 2025-06), lazydocker v0.25.2 (2026-04-19).


## interactionModel
k9s: one full-screen table per resource type. Header (hide with ui.headless) shows context, cluster, user, K9s rev, K8s rev, CPU%, MEM%, the logo, and a mnemonic menu of the hotkeys valid in the current view; breadcrumbs ("crumbs") sit at the bottom (ui.crumbsless). Prompt surface: ':' command mode (:pod, :pod ns-x, :pod @ctx1 to view another context without switching, :ctx, :ns, :xray RESOURCE [NS], :pulses/:pu, :popeye, :screendump/:sd, :q); '/' filter mode (regex, '/!' inverse, '/-l' label selector, '/-f' fuzzy). Enter drills in (pods -> containers -> logs), Esc returns, '[' / ']' walk command history, '-' jumps to the last command (like cd -), ctrl-a lists aliases, '?' opens full help. Per-view keys: d describe, v view, e edit, l logs, y yaml, s shell, shift-f port-forward. Gating: ctrl-d delete opens a confirm dialog that needs TAB then ENTER; ctrl-k force-kills without confirmation; --readonly / readOnly (global or per context) disables every mutating command; plugins declare confirm (show the command before running) and dangerous (disabled in read-only). UI redraw is a poll at refreshRate (default 2, minimum 2.0 s); liveViewAutoRefresh is off by default. v0.50.16 (2025-10) added 'w' namespace warp; v0.50.17 (2026-01) column sorting in all views; v0.50.18 (2026-01) multi-select clipboard.
lazygit: multi-panel. Left column status/files/branches/commits/stash (tabs inside a panel, '[' / ']'), main panel on the right, command log panel below (@ for its options; showCommandLog/commandLogSize). Bottom bar (showBottomLine) shows the keys for the focused panel; '?' opens the full keybinding menu; '1-5' jump to panels; '+' / '_' cycle screen modes normal/half/full; '/' searches (commits: highlight + n/N) or filters (files: hide non-matching); ctrl+s filters commits by path; z undo, Z redo; ':' runs a shell command; Esc pops the context stack (pkg/gui/context.go). Destructive git actions get built-in confirmations; custom commands can add typed prompts.
lazydocker: same shell as lazygit. Left panels project/services/containers/images/volumes/networks (jump with 1-6), main panel tabs logs/stats/config/top/env. Bottom bar + '?' menu. b opens a bulk-commands menu, c runs a custom command, E exec shell, a attach, m logs, '/' filters lists, '+' / '_' screen modes, mouse supported. Config opened from the project panel with o or e.


## caching
No LLM prefix caching applies. The analog is avoiding re-fetch and re-render. k9s: the site says it 'continually watches Kubernetes for changes' (informers), and v0.51.0 (2026-06) added 'skip reconcile cycle when informer data is unchanged', 'batch Hydrate workers to eliminate per-item goroutine overhead', raised default client QPS from 5 to 50, paginated metrics API calls on large clusters, and cut redundant API calls on context switch. The screen itself still repaints on a refreshRate poll (min 2 s); liveViewAutoRefresh stays off so detail views do not churn. lazygit: git is the cache. After each action a scoped refresh (pkg/gui/controllers/helpers/refresh_helper.go) reloads only the affected models; refresher.refreshInterval 10 s (files) and fetchInterval 60 s (remote); v0.63.0 (2026-07) added background polling to detect external repo changes; v0.64.0 (2026-08) rebuilt the concurrency model to remove data races and the 'spinner freeze' after checkout. lazydocker: no refresh-interval key appears in the default config; load is bounded by logs.since '60m' and allLogs --tail=300. Not documented beyond that.


## extensions
k9s: six YAML surfaces under $XDG_CONFIG_HOME/k9s/. plugins.yaml (also plugins/ dirs, $XDG_DATA_DIRS, and per-context plugins.yaml) with fields shortCut, description, scopes (list or 'all'), command, args, background, confirm, dangerous, override, overwriteOutput, inputs (max 5; string, number, bool, dropdown; v0.51.0). Env in args: $NAME $NAMESPACE $CONTEXT $CLUSTER $CONTAINER $POD $FILTER $KUBECONFIG $USER $GROUPS $RESOURCE_NAME/_GROUP/_VERSION $COL-<COLUMN>. Plugins show in the header hotkey menu only for in-scope views. aliases.yaml (short names for GVRs), hotkeys.yaml (key -> command, hot-reloads, shows under '?'), views.yaml (custom columns 'NAME<:jsonpath>|T N W S H L R'), jumps.yaml (CRD -> CRD drill links with fieldSelector/labelSelector Go templates), skins. Built-in integrations: Popeye sanitizer, hey benchmarks, node shell, image scans.
lazygit: customCommands in config.yml: key, context (status, files, worktrees, submodules, localBranches, remotes, remoteBranches, tags, commits, reflogCommits, subCommits, commitFiles, stash, global; comma-joined), command as Go template, prompts of type input (initialValue, suggestions presets authors/branches/files/refs/remotes/tags or a command), confirm, menu, menuFromCommand (regex with named groups, valueFormat, labelFormat), loadingText, output none|terminal|log|logWithPty|popup, outputTitle, after.checkForConflicts, and nested commandMenu. Template objects SelectedCommit, SelectedCommitRange(.From/.To), SelectedFile, SelectedLocalBranch, CheckedOutBranch, SelectedWorktree; functions quote and runCommand. Debug trick: wrap in echo with output: popup. Custom pager renamed 'diff renderer' in v0.64.0. Stated policy: 'if something is already configurable in git, we don't add the same option again in lazygit'.
lazydocker: customCommands per context (containers/services/images/volumes/networks) with name, attach, command, serviceNames, internalFunction; commandTemplates override every compose call; bulkCommands; stats.graphs (caption, statPath, color, min, max, height); replacements; oS.openCommand.


## multiAgent
None of the three coordinates agents, so orchestration token overhead is not applicable. k9s is the closest cockpit for 'many things at once': one table over all pods across namespaces, ':pod @ctx1' to look at another context without switching, per-context config and plugins, '/-l' label filtering, :pulses for a cluster-wide grid (v0.51.0 lets you cycle the pulse grid forward and back), :xray for a dependency tree over po/svc/dp/rs/sts/ds, multi-select copy (v0.50.18), and metrics pagination for large clusters (v0.51.0). Scale complaints on record: 100% CPU with 50+ endpoints (#2681, closed stale), CPU pegged rendering long strings (#1980, stale), high CPU/disk with imageScans (#3478). lazygit models parallel lines of work as worktrees and, since v0.64.0, shows a GitHub PR's combined checks state per branch. lazydocker offers bulk commands (b) and project-level up/down.


## forkTimeTravel
- supported: no for conversation forking (none of the three has a prompt tree). partial: lazygit has reflog-driven undo/redo plus worktrees; k9s has command history and screendumps.
- ux: lazygit: z undoes and Z redoes the last git-state change by reading the reflog, so it also undoes actions done outside lazygit. It refuses mid-rebase ('the reflog doesn't contain enough information') and cannot undo working-tree edits, stash changes, pushes, or branch creation. The reflogCommits context lists prior HEAD states to inspect or check out. Worktrees ('w' in branches view; worktrees tab n/space/d) run parallel branches without stashing. k9s: '[' and ']' step through command history, '-' returns to the last command, :screendump lists saved resource snapshots, and each context remembers its active namespace and view. lazydocker: nothing.
- dataModel: lazygit keeps no shadow state file for undo. It re-parses git's own reflog (.git/logs/HEAD: old-sha, new-sha, author, timestamp, message per line) and classifies entries as checkout, commit, or rebase; undo checks out or resets to the previous entry's SHA, redo walks forward. Worktrees are git's .git/worktrees/<name> metadata. k9s: per-context config lives in $XDG_DATA_HOME/k9s/clusters/<cluster>/<context>/config.yaml (namespace.active, namespace.favorites, view.active, readOnly, skin) with a plugins.yaml beside it; screendumps are files in a configured directory; whether command history persists across sessions is not documented. No parent pointers, ids, or tree snapshots exist in any of the three.


## steal
- **Header mnemonic menu scoped to the current view, plus '?' for the full list. Plugins and hotkeys appear in the same menu when in scope.** — This is the on-screen ramp: the operator sees only the keys valid for the selected thing (agent, proposal, pathway). Reviewers on HN and bwplotka name '?' contextual help as the reason the tool is learnable without a manual. [https://github.com/derailed/k9s]
- **Two prompt grammars: ':' for commands (with history '[' ']' and '-' for last) and '/' for filters (regex, '/!' inverse, '/-l' labels, '/-f' fuzzy).** — Daisugi needs ':agent 12', ':garden', ':pathway X' style jumps and '/denied', '/!allowed', '/-l skill=foo' filters over a live list of proposals. A tiny grammar beats menus for many gated agents. [https://k9scli.io/topics/commands/]
- **A command log panel showing the exact underlying commands, added in v0.28 (2021) after a user survey; toggle size with '@'.** — It became one of lazygit's most valued features because it answers 'what did the tool just do to my repo'. Daisugi's version: show the envelope predicate, the SMT query, and the verdict for every gated action. [https://github.com/jesseduffield/lazygit/releases/tag/v0.28]
- **Read-only mode (global flag and per-context config) plus plugin flags confirm (show command before run) and dangerous (disabled under read-only); delete needs TAB then ENTER.** — This is a fail-closed cockpit contract in config, not policy. Daisugi can mark skills 'dangerous' so they are refused when an operator watches in read-only, and require a two-step key for 'allow'. [https://github.com/derailed/k9s]
- **Undo/redo by re-reading the substrate's own append-only log (git reflog) rather than a shadow state; explicit refusal when the log lacks detail (mid-rebase).** — Time-travel over daisugi's journal should be derived from the journal, not a parallel store, so it also covers steps taken outside the TUI. Copy the honesty: say what cannot be rewound. [https://github.com/jesseduffield/lazygit/blob/master/docs/Undoing.md]
- **Declarative custom commands with a context, typed prompts (input with suggestions, confirm, menu, menuFromCommand), output modes, and an echo+popup debug trick.** — Garden skills could be exposed the same way: a YAML entry binds a key in one context, asks typed questions, streams output to the log. The debug trick lets an operator preview what a skill would run. [https://github.com/jesseduffield/lazygit/blob/master/docs/Custom_Command_Keybindings.md]
- **jumps.yaml: declarative drill links between related resource types using field or label selectors in Go templates.** — Agent -> proposal -> verdict -> pathway -> reuse count is a chain of related records. A jump table gives Enter-to-drill and Esc-to-return over it without hand-written screens per pair. [https://github.com/derailed/k9s]

## avoid
- **Timed full repaint (refreshRate, minimum 2 s) on top of watches; large tables or long strings peg the CPU.** — Issues #2681 (50+ endpoints -> 100% CPU) and #1980 (long strings) went stale unresolved; v0.51.0 had to add 'skip reconcile when informer data unchanged'. Daisugi should redraw on journal events and diff, not on a timer. [https://github.com/derailed/k9s/issues?q=is%3Aissue+%22high+cpu%22+OR+%22cpu+usage%22]
- **Moving a habitual confirmation key. k9s changed dialog acceptance from TAB+ENTER to ENTER and reverted it in v0.50.15 (#3591).** — A gate key is muscle memory. If 'allow' ever changes binding, operators will approve by accident. Fix the allow/deny keys early and never move them. [https://github.com/derailed/k9s/releases/tag/v0.50.15]
- **Growing the core with side features (hey benchmarks, Popeye, image scans, node shell). Image scans caused high CPU and disk (#3478) and the maintainer's release notes warn the project is 'in the red'.** — Every extra subsystem is a refresh loop and a support surface. Daisugi's cockpit should stay gate + garden and push extras into plugins. [https://github.com/derailed/k9s/releases/tag/v0.51.0]
- **Text in the TUI that cannot be selected and copied (mouse capture), so operators cannot grab a branch name or a diff line.** — The single complaint in bwplotka's 2025 review and a repeated one on HN. Verdict text, SMT counterexamples, and pathway ids must be copyable; k9s added an OSC52 clipboard backend in v0.51.0 for this reason. [https://www.bwplotka.dev/2025/lazygit/]
- **Undo that only covers what the log records, with silent gaps (working tree, stash, push, mid-rebase).** — Users learn the gaps by being burned. If daisugi's journal misses any step (a skill's side effect, a hook), the cockpit must show it as un-rewindable rather than pretend. [https://github.com/jesseduffield/lazygit/blob/master/docs/Undoing.md]

## loadBearingClaims
- k9s shows a per-view mnemonic hotkey menu in its header next to context/cluster/user/CPU%/MEM%, with '?' for full help, and in-scope plugins appear in that menu; --readonly disables all mutating commands and plugins can be marked confirm/dangerous. [https://github.com/derailed/k9s]
- lazygit's z/Z undo and redo work by parsing git's reflog, cover actions done outside lazygit, refuse mid-rebase, and cannot undo working-tree, stash, push, or branch-creation changes. [https://github.com/jesseduffield/lazygit/blob/master/docs/Undoing.md]
- k9s v0.51.0 (2026-06-06) added 'skip reconcile cycle when informer data is unchanged', raised client QPS 5 to 50, batched Hydrate workers, and paginated metrics calls for large clusters; the UI poll refreshRate has a 2.0 s minimum. [https://github.com/derailed/k9s/releases/tag/v0.51.0]
- lazygit custom commands bind a key in a named context, support typed prompts (input, confirm, menu, menuFromCommand with regex filter), and route output to none/terminal/log/logWithPty/popup. [https://github.com/jesseduffield/lazygit/blob/master/docs/Custom_Command_Keybindings.md]

Source internal/view/app.go buildHeader(): header.AddItem(a.clusterInfo(), clWidth,...); header.AddItem(a.Menu(), 0,...); header.AddItem(a.Logo(), 26,...). internal/view/cluster_info.go layout(): sections {"Context","Cluster","User","K9s Rev","K8s Rev","CPU","MEM"}. internal/ui/menu.go: HydrateMenu(c.Hints()) on StackPushed/StackPopped. internal/view/actions.go pluginActions(): `if !inScope(pp.Plugins[k].Scopes, aliases) || (ro && pp.Plugins[k].Dangerous) { continue }` — i.e. readonly skips only Dangerous plugins. internal/config/plugin.go: `Confirm *bool`, ShouldConfirm() returns len(p.Inputs)>0 when unset. internal/config/k9s.go IsReadOnly(): global → context.ReadOnly → manualReadOnly (flag) precedence; cmd/root.go defines both `--readonly` and `--write`. v0.51.0 notes include '#4026 fix(xray): disable edit/delete actions in XRay view when readonly mode is enabled'. In-scope plugins are added to the view's key actions and their Description is printed next to the shortcut in the menu. `--readonly` (overridable by `--write`; CLI flag beats the context-level `readOnly` config) disables built-in modification commands (delete/kill/edit), but it disables plugins ONLY when they set `dangerous: true`; plugins without that flag still run in read-only mode, and read-only coverage is enforced per view (v0.51.0 itself had to fix the XRay view ignoring readonly, #4026). `confirm` is a tri-state: unset defaults to true when the plugin declares inputs (#3872).
- [confirmed] lazygit's z/Z undo and redo work by parsing git's reflog, cover actions done outside lazygit, refuse mid-rebase, and cannot undo working-tree, stash, push, or branch-creation changes. — docs/Undoing.md (master, last touched 2026-05-26 'Update docs and schema for release'; current release v0.64.1 published 2026-08-12 by stefanhaller): 'You can undo the last action by pressing 'z' and redo with 'Z' (shift+z)'; 'Undo uses the reflog which is specific to commits and branches so we can't undo changes to the working tree or stash'; 'Lazygit can read through your reflog for you and walk back action by action'; 'it doesn't matter whether you're trying to undo something you did in lazygit or directly on the command line. You can open lazygit for the first time and start undoing thing in your repo'; Limitations: 'lazygit can only undo things that are recorded in the reflog. That means changes to your working tree or stash aren't covered. Secondly, anything permanent you do like pushing to a remote can't be undone. Thirdly, actions like creating a branch won't be undone, because they're not stored in the reflog.'; 'If you are mid-rebase, undo/redo is not supported ... it's best to abort the rebase'. Source pkg/gui/controllers/undo_controller.go corroborates and slightly widens: the guard is `if self.c.Git().Status.WorkingTreeState().Any() { return errors.New(self.c.Tr.CantUndoWhileRebasing) }` where Any() = Rebasing||Merging||CherryPicking||Reverting, so undo is refused during any in-progress rebase/merge/cherry-pick/revert (error text 'Can't undo while rebasing'). Undo always asks for confirmation: commit undo = soft reset ('Are you sure you want to soft reset to '%s'?'), rebase undo/redo = hard reset with auto-stash ('An auto-stash will be performed if necessary'), checkout undo = checkout. Tooltip: 'This does not include changes to the working tree; only commits are taken into consideration.' Minor staleness: the doc still says 'Undo/Redo is a new feature'.
- [confirmed] k9s v0.51.0 (2026-06-06) added 'skip reconcile cycle when informer data is unchanged', raised client QPS 5 to 50, batched Hydrate workers, and paginated metrics calls for large clusters; the UI poll refreshRate has a 2.0 s minimum. — GitHub API: tag v0.51.0 published_at 2026-06-06T14:13:12Z; it is still the latest release as of 2026-08-27 (prior: v0.50.18 on 2026-01-11).
