## interactionModel
The operator lives in tmux. Every role (Mayor, Deacon, Witness, Refinery, Dogs, Crew, Polecats) is a separate Claude Code process (or Gemini/Codex/Cursor/Auggie/AMP/OpenCode/Copilot via JSON presets) in a tmux pane, launched with `--settings` pointing at a generated role settings.json. The prompt surface is conversational: `gt mayor attach` opens the Mayor and you "tell the Mayor what to build"; it creates a convoy (a town-level bead `hq-cv-*` with `tracks` edges to work beads), slings beads onto worker hooks (`gt sling <bead> <rig>`), and summarizes results. Yegge's v1.0 framing: "visibility without reading. The Mayor reads all that crap that the workers are printing." The Emergency User Manual's operator loop: reset crew, hand one task per agent, read completions when they finish, "don't watch your agents work", `gt handoff` after every task. Keys: `C-b g` agent-switcher popup (`gt agents menu`), `C-b a` activity-feed window, `C-b n/p` cycle windows. Supervision: `gt feed` is a three-panel TUI (agent hierarchy / in-progress work / chronological events; j/k, Tab, 1/2/3, `--since 1h`, `--plain`, `--window`); `gt feed --problems` groups agents by health state (GUPP Violation = hooked work with no progress; Stalled; Zombie = dead tmux session; Working; Idle) with intervention keys `n` = nudge, `h` = handoff; `gt dashboard` is an htmx web page on :8080 (agents, convoys, hooks, queues, issues, escalations; SSE updates and a command palette per CHANGELOG 0.7/0.8); `gt convoy list` is called "the primary attention dashboard"; `gt costs` per session/role/rig. Messaging to agents: `gt nudge <agent> "msg"` injects a `<\system-reminder>` via tmux keystrokes (literal mode + debounce + separate Enter; "never use raw tmux send-keys"); `gt mail send` writes a durable bead; `gt escalate` with CRITICAL/HIGH/MEDIUM. Approval/gating UX: there is essentially none per action. The Propulsion Principle (GUPP) is the opposite of a gate: "If you find something on your hook, YOU RUN IT", agents must not seek confirmation; users run in YOLO/bypass-permissions mode (Welcome post: "requires trusting agents with broad permissions"). The only gates are Beads gate beads (human `bd gate resolve`, timer, gh:run, gh:pr) that block downstream workflow steps, the Refinery's merge-queue verification (batch-then-bisect, Bors style), and `gt handoff` prompting before restart (0.9.0). Runtimes without executable hooks (Codex, Auggie, AMP) lose tool guards entirely: "No tool guards, cannot intercept tool calls for validation."


## caching
Prompt-prefix stability and cache-aware routing are not documented anywhere in Gas Town or Beads; neither README, CHANGELOG, nor the proxy-server doc mentions prompt caching. What exists: (a) small, stable context injection: `bd setup claude` installs only a SessionStart hook running `bd prime --hook-json`, which the docs size at "~1-2k tokens of workflow context, 10-50x less overhead" than MCP tool schemas (10-50k), and which re-fires after context compaction so no PreCompact hook is needed; Gas Town keeps one minimal `~/gt/CLAUDE.md` identity anchor and injects full role context ephemerally via `gt prime` (role template + town/rig directives + formula overlays), so each role's prefix differs and cross-agent prefix sharing is not a design goal. (b) Context discipline instead of caching: Beads' founding post argues for killing agents after each task "keeping them at the start of their context window"; polecat sessions cycle after each molecule step, on compaction, or on crash, while identity and sandbox persist; root-only molecules keep formula steps inline rather than materialized as rows. (c) Measurement: `gt costs` parses Claude Code transcripts in `$CLAUDE_CONFIG_DIR/projects/*.jsonl`, sums input, cache_creation_input, cache_read_input and output tokens per assistant message, prices cache reads at a 90% discount and creation at a 25% premium, breaks down per session/role/rig, records via Stop hook to `~/.gt/costs.jsonl`, and digests daily into Cost Report beads; OTel `agent.usage` records carry the same four token fields per turn; Beads exposes bd_ai_input/output_tokens_total. (d) Routing: model-aware molecules pick a model per step with no LLM in the loop (score = +40 active subscription, up to 30 MMLU, 20 SWE, 10 cost savings; OpenRouter prices cached 24h; usage logged to `~/.gt/usage.jsonl`), preferring subscription seats because "cost is already paid; zero incremental cost". (e) Orchestration overhead is high by construction: every supervisory role is a full agent, patrols loop continuously, and the 0.9.0 changelog removed a Boot "decision engine that consumed unbounded tokens on failed installs"; 1.2.0 added tmux inspection for Claude usage-limit signatures before restarting agents. Cross-agent context is not re-sent per step; state is pulled from Dolt via `bd` commands on demand and pushed via nudges (ephemeral, no commit) or mail (a wisp bead per message), with nudge-first cutting patrol commit volume ~80%.


## extensions
Layered, mostly file-based, no marketplace shipped. Formulas: TOML workflow templates (fields formula, description, version, type workflow|expansion|aspect, vars with required/default/pattern/enum, steps with id/title/type/needs/gate) resolved project `.beads/formulas/` > town `~/gt/.beads/formulas/` > embedded in the gt binary, versioned as `name@4.0.0`; `bd cook` compiles to a proto, `bd mol pour` instantiates beads. Overlays: per-formula TOML step edits (replace/append/skip) at town and rig level (rig wins outright). Directives: operator markdown per role injected by `gt prime` with an authority marker overriding formula text. Plugins: a `plugin.md` with TOML frontmatter in `~/gt/plugins/` or `<rig>/plugins/`, discovered on Deacon patrol, fired by gates (cooldown/cron/condition/event/manual) and executed by Dog workers; explicitly not Claude hooks/skills/MCP. Hooks: `gt hooks sync|diff|base|override|scan|registry|install` composes `~/.gt/hooks-base.json` + `~/.gt/hooks-overrides/<target>.json` into generated `.claude/settings.json` per role (additive base > role > rig+role; a registry is "a catalog, not the source of truth"); CHANGELOG notes `gt handoff` "migrated to skills" and a docs/skills/convoy folder exists. Runtimes: JSON presets in `~/gt/settings/agents.json` (hooks, resume flag/style, non-interactive flag, supports_fork_session, session_id_env, process_names) for Claude, Gemini, Codex, Cursor, Auggie, AMP, OpenCode, Copilot, Kiro; also an ACP implementation (0.12.1) and a mutually-authenticated proxy server so sandboxed containers can call gt/bd and git over HTTPS. Beads side: `bd setup claude|codex|factory`, integration docs for 18 editors/agents, a `beads-mcp` PyPI server, `bd remember` memories injected by `bd prime`, gates, molecules, events journal HTTP/SSE (`/v0/beads/events`), OTLP telemetry. Community: bdui, beads_viewer, beads_rust, gt-telegram, beadhub. Planned/unbuilt: Mol Mall registry ("npm for molecules", only Phase 1 local formulas exist), Wasteland federation over DoltHub (Phase 1 "wild-west mode", trust tiers not enforced), capability-based routing, Kilo's hosted "Gas Town by Kilo" (waitlist marketing page, no pricing).


## multiAgent
Fixed role taxonomy, supervisor-tree style (Klabnik: "supervisor trees, mailboxes... from Erlang"). Town level: Mayor (singleton coordinator), Deacon (daemon beacon running patrol cycles), Boot (a Dog that checks the Deacon every 5 minutes), Dogs (maintenance: Reaper, Compactor, Doctor, checkpoint dog, stuck-agent dog). Rig level: Witness (detects stuck/zombie polecats, respawns crashed sessions, does not gate completion), Refinery (merge queue, batch-then-bisect, fast-forward on green), Polecats (persistent identity, per-assignment reusable git-worktree sandbox, ephemeral session), Crew (long-lived, human-managed full clones). Coordination substrate: one Dolt SQL server per town on :3307, all agents write to `main` under transaction discipline; work assignment via hooks (a pinned bead per agent) and `gt sling`; atomic claims `bd update --claim` (first wins, idempotent) and `bd merge-slot acquire/release`; convoys track batches with 5s event poll + 30s stranded scan and auto-close. Back-pressure: scheduler in the daemon heartbeat (every 3 min) dispatches min(capacity, batch_size, ready) where capacity = max_polecats minus active polecats counted by scanning tmux, with spawn_delay and a circuit breaker after 3 failed dispatches. Liveness: three heartbeat stores (Deacon heartbeat.json, per-session state store, `heartbeat:<EPOCH>` bead label) with 5 min stale / 20 min very-stale thresholds, cross-checked against tmux activity to avoid false escalations. Messaging: nudge (ephemeral tmux inject) vs mail (bead) plus groups/queues/channels as bead prefixes. Scale claims: Yegge ran 12-30 workers in Jan 2026 and needed a second Claude account; Kilo markets "elastic scaling for agent swarms". Token overhead is the dominant cost: every supervisor is an LLM session, patrols run continuously, and a shipped default release formula made users' Mayors work upstream issues on their own credits (issue #3649). Reliability history: "serial killer sprees" (Witness cleanup killing live workers) and "the 22-nose Clown Show" of Mayor data loss before the Dolt migration; 50+ race/Dolt fixes in 1.0.0; Dolt 2.3.0 (2026-08-13) regressed hard-reset in ~5% of databases.


## forkTimeTravel
- supported: partial: no prompt-tree fork/rewind/replay of its own (a literal scan of docs/reference.md finds no `gt fork`, `gt tree`, `gt resume`); it leans on Claude Code's session store for forking, on Dolt for data-level time travel, and on checkpoints/handoff mail for resume.
- ux: (1) `gt seance` lists discoverable predecessor sessions (filters `--role`, `--rig`, `--recent N`, `--json`); `gt seance --talk <id>` spawns `claude --fork-session --resume <id>` so you converse with a forked copy of a past session without mutating it; `gt seance --talk <id> -p "Where is X?"` is one-shot. Only Claude has Fork=Yes in the runtime capability matrix; Gemini/Codex/Cursor/Auggie/AMP/OpenCode are No. (2) `gt handoff`: agent notices context filling, mails itself, manager kills and restarts the session, new session reads the handoff mail and runs `gt prime`; `!gt handoff` is the zero-cost mechanical variant; `h` in the feed's problems view triggers it. (3) `gt checkpoint write|read|clear` for polecats/crew (crash recovery, not branching). (4) Data time travel is SQL: Dolt `AS OF` queries, `dolt_history_*` tables, `dolt_diff()`; `bd events tail --since <seq> [--follow]`. Nothing lets the operator branch a conversation at an earlier prompt, compare branches, or replay a prompt tree.
- dataModel: Session discovery: `~/.gt/.events.jsonl` session_start events carrying session_id, actor/role, timestamp, topic; fallback to Claude's own `~/.claude/projects/*/sessions-index.json` plus per-session `.jsonl` transcripts (symlinked across accounts). Checkpoint: `.polecat-checkpoint.json` in the polecat dir with current molecule and step, hooked bead, modified-files list, git branch and last commit, timestamp, session id, optional note (restore logic not visible in the command file). Work state: every bead is a row in one Dolt `issues` table (Gas Town schema v6; tasks, messages, agents, gates, wisps all beads), with `dependencies` (blocks, parent-child, tracks, thread...), labels, comments/events, `compaction_snapshots`; every `bd create/update/close` is a Dolt commit, all agents write to `main` (BEGIN, UPDATE, CALL DOLT_COMMIT, COMMIT). Ids: Beads default is hash of title + timestamp + salt, adaptive length 4 chars (0-500 issues) to 5 (501-1500) to 6 (1501+), configurable prefix, hierarchical dotted children `bd-a3f8.1.1` up to 3 levels, collision disambiguator on import; Gas Town uses prefix + 5 chars (`gt-abc12`), routed by `routes.jsonl` prefix-to-rig map. Issue fields (JSON schema doc): id, title, status (open/in_progress/closed/deferred), priority 0-4, issue_type (bug/feature/task/epic/chore), created_at, description, owner, updated_at, closed_at, labels, dependencies, parent, acceptance_criteria, revision (optimistic-concurrency token), comments. JSONL export lines carry `_type` issue|memory and `_schema` beads-jsonl/1; `.beads/issues.jsonl` is "not the source of truth or a backup". Sync: Dolt data pushed to `refs/dolt/data` on the git remote. Events journal: Dolt tables `bd_events_journal`/`bd_events_seq` (dolt_ignore'd, per-clone), fields seq (gapless), ts, op, issue_id, actor, full issue snapshot after mutation, dep, comment; retention 7 days / 100k rows; truncated reads fail loudly. Agent identity: an agent bead per polecat with a CV chain and `heartbeat:<EPOCH>` labels; attribution via `BD_ACTOR` paths like `gastown/polecats/toast` in git author, bead created_by/updated_by, and event logs.


## steal
- **Problems view with one-key intervention: group agents by health state (GUPP Violation, Stalled, Zombie, Working, Idle) derived from work-state data, and bind `n` = nudge and `h` = handoff on the selected agent.** — At 20-50 agents a flat event stream hides the stuck ones; daisugi's gate cockpit should default to a by-state grouping (proposing / awaiting-verdict / denied / over-budget / dead) with the verdict and the intervention on the same key row. [https://raw.githubusercontent.com/steveyegge/gastown/main/README.md]
- **Seance: fork a predecessor conversation read-only with `claude --fork-session --resume <id>` and ask it a one-shot question (`-p`), discovering sessions from an append-only session_start log plus the harness's own session index.** — Gives conversation time-travel without inventing a new transcript format: daisugi can fork at any past session id in the harness's store, keep the original immutable, and only add its own parent-pointer index; it also proves the harness supports the fork primitive daisugi's prompt tree needs. [https://raw.githubusercontent.com/steveyegge/gastown/main/internal/cmd/seance.go]
- **Events journal as a binlog: gapless per-clone seq, full post-mutation snapshot per record, `bd events tail --since <seq> --follow`, an SSE watch endpoint, bounded retention that fails loudly (`events_journal_truncated`) instead of silently losing history.** — The garden-over-time view (pathways growing, reuse, tokens saved) should be a fold over an append-only journal, not a poll of snapshots that misses intermediate states; the loud-truncation rule keeps the view honest. [https://raw.githubusercontent.com/steveyegge/beads/main/docs/reference/events-journal.md]
- **Cost accounting from the harness's own transcripts: sum input / cache_creation / cache_read / output tokens per assistant turn, price cache reads at a discount, break down per session, role and rig, record via a Stop hook, digest daily into durable records.** — Daisugi's per-step budget and 'tokens saved' figures can come from the same transcript files with zero instrumentation in the agent, and cache-read share per role is the direct metric for prefix-reuse health. [https://raw.githubusercontent.com/steveyegge/gastown/main/internal/cmd/costs.go]
- **Tiny stable primer instead of tool schemas: a SessionStart hook injects ~1-2k tokens of workflow context (which also fires after compaction), while the rest is pulled on demand through a CLI.** — Keeps the cacheable prefix short and identical across sessions and avoids 10-50k tokens of MCP schema per agent; daisugi's gate can expose itself the same way (one primer, `daisugi` CLI on demand) rather than as a fat MCP surface. [https://raw.githubusercontent.com/steveyegge/beads/main/docs/integrations/claude-code.md]
- **Gates as typed dependency edges: human, timer, gh:run, gh:pr gate beads that keep steps out of the ready frontier and release them the instant the gate closes; cycles rejected at write time.** — Daisugi's verdicts are wait conditions too; modelling allow/deny/needs-human as edges on the pathway graph makes 'what is blocked and why' a query, and the ready frontier becomes the cockpit's default list. [https://raw.githubusercontent.com/steveyegge/beads/main/docs/workflows/gates.md]
- **Three-layer split of identity (permanent), sandbox (per assignment, reusable), session (ephemeral, cycled after every step, on compaction, on crash) with `gt prime` restoring state from beads + git rather than from transcript.** — Makes session death a non-event and keeps every LLM call near the start of its context window; daisugi's supervised agents should be resumable from envelope + pathway state so a denied or crashed step never needs the transcript re-sent. [https://raw.githubusercontent.com/steveyegge/gastown/main/docs/concepts/polecat-lifecycle.md]

## avoid
- **Metaphor tax: Mayor, polecat, witness, deacon, dog, boot, refinery, convoy, molecule, protomolecule, wisp, formula, seance, GUPP, MEOW, guzzoline, wasteland. Third parties had to publish decoder rings before people could evaluate the design.** — Brinker: the fiction makes 'the underlying concepts harder to grasp despite their architectural merit'; Abrahms built a decoder table; Appleton: it 'fits the shape of Yegge's brain and no one else's'. A supervision cockpit is read under stress; name things by function. [https://www.alilleybrinker.com/blog/gas-town-decoded/]
- **Every supervisor is an LLM in a loop: Deacon patrols, Witness patrols, Boot pings, Dogs, Refinery, Mayor, all on the user's subscription, plus an early Boot 'decision engine that consumed unbounded tokens on failed installs'.** — Yegge: 'expensive as hell... You won't like Gas Town if you ever have to think, even for a moment, about where money comes from'; needed a second Claude account; HN: 'a silly way to burn all your tokens in a day'. Watchdogs and gates should be deterministic code (as daisugi's Z3 gate already is), never model calls. [https://raw.githubusercontent.com/steveyegge/gastown/main/CHANGELOG.md]
- **Shipping unattended default work the operator did not opt into: bundled release formulas and the Mayor template routed upstream gastown/beads issues to users' agents, which opened PRs against the maintainer's repo on the users' credits and git credentials.** — Issue #3649 (253 HN points): 'no disclosure that installing GasTown may result in your AI credits and GitHub account being used'; a maintainer conceded accidental triggering was possible. Anything that runs without a prompt must be visible in the cockpit and opt-in. [https://github.com/gastownhall/gastown/issues/3649]
- **Commit-per-write versioned database as the hot path, on a vibe-coded, unreviewed codebase (189k LOC Go in 12 days; 'I've never seen the code'): Dolt history bloat needing Reaper/Compactor/Doctor dogs, 'database is read only' under concurrent DOLT_COMMIT, 20+ minute remote rebuilds, a Dolt 2.3.0 hard-reset regression, and an accidental untested Beads release.** — HN users left Beads because 'every release made it slower' and its daemon synced 'the wrong things at the wrong times'; Gas Town needed 50+ race fixes for 1.0. Daisugi's journal should be a plain append-only log with explicit snapshots, and the assurance core stays small and reviewed. [https://raw.githubusercontent.com/steveyegge/gastown/main/docs/design/dolt-storage.md]
- **'Visibility without reading' via a single chatty Mayor, with the guidance 'don't watch your agents work'.** — Users report the opposite of assurance: Hartcher gets 'almost no visibility of what's going on other than work was completed'; Abrahms calls it 'plate spinning'; the Mayor is a serial bottleneck. A runtime-assurance cockpit must show each proposed action and its verdict directly, not a summary written by another model. [https://simonhartcher.com/posts/2026-01-19-my-thoughts-on-gas-town-after-10000-hours-of-claude-code/]
