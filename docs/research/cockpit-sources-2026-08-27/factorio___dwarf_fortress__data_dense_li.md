# Factorio + Dwarf Fortress (data-dense living views)


## interactionModel
Two opposite operator stances, both indirect at scale. FACTORIO: one avatar, but the factory is run by thousands of autonomous units (inserters, robots, trains) driven by declarative structures. The operator's live surface is (1) the Production statistics screen (P, or a button above the minimap): tabs Items+fluids / Buildings / Pollution / Kills, production and consumption side by side, timescales 5s, 1m, 10m, 1h, 10h, 50h, 250h, 1000h, all time; 2.0 adds per-surface vs 'Global statistics' toggle, quality-tier filter, a net Science graph and an accumulator-charge graph (FFF-408, 2024-04-26); the wiki warns 'At low timescales, the rate shown can be inaccurate because of the small number of items sampled'. (2) Alerts: 'small triangle icons on the right of the quickbar', aggregated per class with counts ('X objects are missing the material for construction'), each with a fixed lifetime (5-30 s), 'Alerts can be clicked to show the position of the entity which caused the alert on the map'; per-type '/alerts <enable/disable/mute/unmute> <alert>'; 2.0.7 added 'an interactive list of recent alerts', disabled turret-fire alerts by default, and made ammo warnings sound once. (3) Remote view (2.0, FFF-380, 2023-10-13): from the map the operator can 'remotely open' any entity, configure a ghost before robots build it, rotate instantly, mark for deconstruction; planets/platforms are selected inside the map itself. (4) Factoriopedia (FFF-397, 2024-02-09): 'ALT + Left click practically anything' jumps to a page merging item, recipe and entity with ingredients, uses, unlock tech. (5) Undo/redo (FFF-412, 2024-05-24): CTRL+Z / CTRL+Y, redo button 'lights up when there's something to redo', flying text says what was undone. Gating/approval UX: there is no approval step; intent is expressed as ghosts (blue-tinted shader; 'Ghost tint also indicates robot assignment status') that robots fulfil when materials exist, and as circuit conditions. Multiplayer '/permissions' groups restrict which input actions a player may perform (add-player, create-group, edit-group...). DWARF FORTRESS: the operator never controls a dwarf; you designate (m mine, b build, p stockpile, z zones, U burrows, o work orders) and dwarves pick jobs. Supervision surfaces: Creatures screen (u): tabs Citizens / Pets-Livestock / Others / Dead-Missing, each row = image, name+profession (colour-coded), location and sheet buttons, current task, stress, work details; 'sortable by name, profession category, profession, current performed task and stress level'. Stocks (k or top bar): categories left, items right, string filter; counts are maintained by the bookkeeper at 5 precision levels and 'If a number has been rounded, it will appear with a trailing question mark, for example, "20?" instead of "17"'; colour/bracket codes mark restricted, forbidden, not-dwarf-made, worn. Announcements (N): three tiers - minor 'flicker through the announcements window very quickly', major 'may be paused and zoom to the location', game-changing 'pause the game, zoom to the location, and present a message box'. Per-event policy lives in announcements.txt / the Settings screen with columns Popup, Pause, Recenter, Alert. v50 (2022-12-06) added mouse support, 'new alert and report system', 'info readout where mouse is', 'view multiple elevations at once', tooltips and tutorial; z-levels via mouse wheel or e/c. Classic keeps the keyboard-menu UI where every CP437 glyph is state and status icons 'alternate with the ☺ tile'.


## caching
Not documented as caching in either game, but Factorio's architecture is the closest analog to 'stable prefix, ship deltas': 'All instances of the game run full simulations of the entire world and only player actions are transferred across the network' (deterministic lockstep); a joining peer downloads the map once, then receives only inputs; 'latency hiding' simulates some of the local player's actions ahead of confirmation (not for driving or shooting); mod checksums are compared on join and 'Players automatically quit game after 3 desyncs'. Replays reuse the same idea: store the input log, re-simulate from tick 0 (hence no skip/rewind). Staleness is rendered instead of refetched: outside continuous radar coverage 'The last known state of the chunk will be visible on the player's map as a dim image that cannot be zoomed into'; inside coverage the map updates 'a single pulse, approximately every second'. Dwarf Fortress has no network or context reuse; its analog is a declared precision budget: stock counts are rounded per the bookkeeper's precision level and displayed with a trailing '?'. Token-relevant secondary finding: the Factorio Learning Environment authors found dense ASCII world dumps 'problematic due to tokenization issues' and moved to 'sparse encoding' for the agent's observation (agents observe only stdout/stderr of their last program). Transferable lesson for daisugi: the per-step message to a gated agent should be a delta over a stable, verified prefix, and the cockpit should draw stale or sampled numbers as stale.


## extensions
FACTORIO: (1) Lua mod portal (mods.factorio.com); e.g. Bottleneck (author trold, MIT, 318K downloads, 0.13-2.0, last update ~1y9m ago) paints lights on assemblers/furnaces/drills/pumpjacks/chem plants: 'Green: currently doing stuff', 'Yellow: ... limited by the output', 'Red: ... limited by the input', updating 40 machines per tick so lights refresh less often beyond ~10k machines. (2) Blueprints as shareable text strings plus a per-player library that survives saves and is shared in multiplayer; blueprint books; upgrade and deconstruction planners. (3) Parametrised blueprints (2.0.7; FFF-392, 2024-01-05): 'Nearly everything in the game that can be configured can also be parameterised within a blueprint'; parameters are 'special IDs ... for items, recipes, fluids, and entities'; a placement dialog fills them; 'Parameters can be configured to be an ingredient of another parameter automatically'; 'Each parametrised number can be assigned a variable, and its value can be used in math formulas in all of the subsequent dependent numbers'. (4) Circuit network as in-world scripting: signals are (channel, signed 32-bit int) pairs, red and green wires are separate networks that each sum their signals, 177 (241 in Space Age) virtual signals, wildcards Everything/Anything/Each, four combinators (constant up to 20 values, arithmetic, decider, 2.0 selector), 40+ controllable entities; 2.0.7 put all radars on a surface on one wireless network. (5) Programmable speaker: circuit condition -> sound + optional GUI alert with icon and 'up to 150 characters'. (6) Console: /alerts, /editor, /permissions, /toggle-action-logging, /c Lua (disables achievements). DWARF FORTRESS: (1) raws (text data files) and, since v50, Steam Workshop mods; 'separate graphics being controlled by mods'. (2) DFHack: 'a memory editing library for Dwarf Fortress that provides a unified, cross-platform environment where tools can be developed to extend the game', Lua API, overlays, bugfixes, automation. (3) Dwarf Therapist: external Qt app, 'a spreadsheet of dwarves, their skill levels and currently assigned labors', sortable by profession, migration wave, happiness, job count, with a 'labor optimizer'; reads DF memory via version-specific layouts that DFHack regenerates ('devel/export-dt-ini'); 'fully compatible with v50+ premium and classic'. (4) Config-as-text: announcements.txt (defaults in data/init, user copy in prefs) with flags BOX/DO_MEGA, PAUSE/P, RECENTER/R, A_DISPLAY, D_DISPLAY, UNIT_COMBAT_REPORT, UCR_A, ALERT, e.g. '[CITIZEN_DEATH:A_D:D_D:UCR_A:ALERT]'. (5) gamelog.txt and Legends XML export as machine-readable outputs for third-party tools.


## multiAgent
Both games are 'many autonomous units, one operator', which is daisugi's fleet shape. FACTORIO: construction robots fulfil ghosts, logistic robots fulfil requests, trains follow schedules, inserters obey circuit conditions; the operator never addresses a unit. Supervision is by exception: alerts per class with counts and click-to-zoom, and by aggregate: production/consumption over time, per surface or global. 2.0's remote view removes the need to be physically near a unit to inspect or reconfigure it. Human co-op is deterministic lockstep; 2.0's online players GUI (FFF-423, 2024-08-09) is a compact top-right list 'inspired by Minecraft's tab menu': hover shows a player's location, click follows them, they can be pinned to the side menu; permission groups limit which input actions a player may issue. Secondary: the Factorio Learning Environment runs LLM agents through a Python REPL (v0.2.0 adds multi-agent coordination); HN commenters from the project report agents 'get down into the weeds of fixing minor issues rather than coming up with a master plan first' and show 'target fixation' (GPT-4o retrying a known-bad action ~100 times), and progress is scored as total production times item price because science-per-minute 'zeroes out in the early stages'. DWARF FORTRESS: up to ~200 dwarves choose jobs from designations, work details, and manager work orders whose item conditions ('At Least', 'At Most', 'Exactly', material, adjective) are ANDed and checked daily/monthly/seasonally/yearly; the Creatures screen gives one row per unit with task and stress; status icons over every unit (hungry/thirsty/drowsy/stressed ↓, sleeping Z, moods and tantrums !, no job ?, migrant X, on fire flashing red/yellow); professions colour the unit glyph by highest skill; burrows (U) and forbid marks constrain where and with what units may act. The classic community verdict (HN 2017): job management 'becomes unusable once your fortress reaches a certain size' without Dwarf Therapist, i.e. the per-unit matrix view was so necessary that it was built outside the game.


## forkTimeTravel
- supported: partial: neither game has an in-game branch tree; Factorio = undo/redo stack for build actions + full-snapshot saves + forward-only deterministic replay + tick-stepping in the editor; Dwarf Fortress = named 'timelines' of full-snapshot save folders, no rewind, no undo
- ux: FACTORIO: CTRL+Z / CTRL+Y (⌘Z / ⌘⇧Z) undo/redo build, deconstruct, upgrade orders, wire connections, entity settings, blueprint placements and rotations; a redo shortcut 'lights up when there's something to redo, and is disabled when there's nothing'; 'a flying text notification that pops up when you use the undo hotkey'; 'when trying to undo an action that is more than a few minutes old, there is a confirmation dialog pop-up' with a preview of affected entities; the button tooltip 'describes exactly what you're about to undo and on which planet or space platform' (FFF-412). Time travel proper = load a save. Replay: only if 'Record replay' was checked at new game; controls are pause/play, slow down, speed up, viewpoint-player dropdown in MP; 'There is no way to skip ahead, the entire replay must be watched up until the point of interest'; 'Re-winding ... is not possible'; 'Playback view is locked to the character in singleplayer'. Editor time mode (/editor, CTRL+SHIFT+F11): 'pause and unpause the game, make it run only for a single tick/a custom interval or to speed up/slow down the game'; '/c game.speed=X'; script commands permanently disable achievements. DWARF FORTRESS: Esc menu offers 'Save to this timeline' (replace active save), 'Save to new timeline' (a separate grouped save = the only branch primitive), 'Save to new folder (same timeline)', and 'Save and continue playing' (a 'Manual save' grouped with the active save). Autosave 1, 2 or 4 times per year into folders 'autosave 1', incrementing. Retrospective time view = Legends mode: read-only 'list of all historical events in chronological order', hyperlinked figures/sites/artifacts, XML export; plus gamelog.txt, an append-only text log of 'every announcement and report available to the player, sorted by oldest to newest'.
- dataModel: FACTORIO: saves live in ./saves (user data dir); the wiki page fetched does not document the zip internals. Replay = 'a file stored within the game save, containing any information needed to repeat (replay) a game from start'; breaks if the world was created in an older version or mods are added/removed. Blueprint library persists across saves in blueprint-storage-2.dat(.zstd). Blueprint string = version byte '0' + base64(zlib deflate level 9(JSON)); JSON: {blueprint:{item, label, label_color, entities:[{entity_number (1-based), name, position{x,y}, direction (doubled in 2.x), connections, recipe, filters...}], tiles, icons, schedules, version}}; books: {blueprint_book:{blueprints:[{index, blueprint}], active_index (0-based), item:'blueprint-book', label, icons, version}}; 'As of 2.0 the game can also import the uncompressed JSON blueprint string directly'. Undo history is in-memory per save; no documented on-disk format. DWARF FORTRESS: save/ contains current/ (active world, deletable when closed) and region#/ per world; timeline members are sub-folders named region#-year-month-day; files: world.sav (fortress mode) or world.dat, art_image-#.dat, feature-#-#.dat, region_snapshot-#.dat ('historical maps not currently available in Legends mode'), site-#.dat (retired forts), unit-#.dat; sizes 'from just a few megabytes ... to several hundred megabytes ... even a gigabyte or two'. Parent linkage is only the folder grouping; ids are folder names. Backup = copy region# folder; restore = 'always delete the old folder first', never overwrite.


## steal
- **Three-tier interrupt taxonomy with per-event policy: minor (log only, scrolls past), major (sound, optional pause + recenter), game-changing (pause + zoom + modal box); each event class carries its own BOX / PAUSE / RECENTER / ALERT / log flags in a text file the operator can edit, and a Settings grid with Popup, Pause, Recenter, Alert columns.** — A fleet of gated agents produces thousands of allow/deny events. Only a small class (e.g. a denied destructive action, a budget breach) should stop the operator; most should scroll in a log. Put the pause/zoom/modal policy on the event class, not on the event, and make it a file so it is versionable. [https://dwarffortresswiki.org/index.php/Announcements.txt]
- **Alerts aggregated by class with a count and a fixed lifetime, drawn as small glyphs at a fixed screen position, each clickable to zoom the map to the causing entity; per-type enable/mute; a recent-alerts list; noisy classes (turret fire) off by default.** — Ten agents blocked on the same missing permission is one alert 'X proposals denied: <reason>' with a click that lands on the offending proposal, not ten toasts. Lifetime + count keep the strip readable at scale; Factorio learned in 2.0.7 to default the chatty class off. [https://wiki.factorio.com/Alerts]
- **Render staleness and imprecision honestly: chunks outside radar coverage are drawn as 'a dim image that cannot be zoomed into' (last known state), and DF stock counts that were rounded show a trailing '?' ('20?' instead of '17') with a documented precision ladder.** — A garden view built from sampled journals, cached prefixes or lagging telemetry must show which numbers are live, which are last-known, and which are estimates. A dim tile and a '?' suffix are cheap, legible conventions that keep the operator's trust. [https://wiki.factorio.com/Radar]
- **Production-statistics screen shape: production vs consumption side by side per item, one timescale selector (5s to 1000h and all-time), per-surface vs global toggle, click an icon to filter the graph, plus derived graphs (net Science after productivity, accumulator charge) added because the raw series did not answer the real question.** — The garden's 'tokens saved / pathways reused' view is the same problem: per-agent vs fleet, a timescale ladder, filter by pathway, and derived series (net tokens after cache hits, denials per 1k steps) rather than only raw counters. [https://www.factorio.com/blog/post/fff-408]
- **Ghost-first execution with visible assignment state: a placed blueprint is a ghost (distinct shader tint, blue-shifted shadow) until a robot builds it; the ghost tint changes when a robot is assigned; the operator can open and configure a ghost before it is built; from remote view any entity can be opened. Third-party Bottleneck adds per-machine lights (green working / yellow output-blocked / red input-starved, throttled to 40 machines per tick).** — This is daisugi's gate rendered spatially: a proposal is a ghost until the verifier proves it; tints for proposed / proving / allowed-running / denied, an 'open the ghost' affordance to edit the proposal before approval, and a per-agent status light (working / blocked on gate / starved of budget) whose refresh is throttled under load. [https://www.factorio.com/blog/post/fff-380]
- **Undo with disclosure: the undo/redo tooltip 'describes exactly what you're about to undo and on which planet or space platform'; a flying text confirms what was undone; undoing an action 'more than a few minutes old' raises a confirmation dialog with a preview of affected entities.** — Rewind and branch in a prompt tree discard state. Preview what will be dropped, name the scope (which agent, which branch), and scale the confirmation to the age of the checkpoint instead of asking 'Are you sure?' every time. [https://www.factorio.com/blog/post/fff-412]
- **Parametrised blueprints: a reusable pattern declares typed holes (item, recipe, fluid, entity, number), a placement dialog fills them per instance, holes can be auto-derived ('an ingredient of another parameter') and numbers can be formulas over other parameters.** — Garden pathways should be stored as templates with declared parameters and derived fields, instantiated at reuse time, so reuse is a fill-in step the operator can see rather than a copy the agent silently rewrites. The blueprint string (version byte + base64 zlib JSON) is also a proven shareable text format. [https://www.factorio.com/blog/post/fff-392]

## avoid
- **Per-screen key vocabularies with no discoverability (classic DF): placing beds and workshops use 'completely unrelated keys'; 'Discoverability is next to nil'; experts defend it because 'once you know exactly what to do, the interface becomes invisible', yet the same thread notes third-party tools proved 'a reasonable interface can be made'.** — An expert instrument may be terse, but the same verb must mean the same thing on every panel of the cockpit (fleet, tree, garden). Inconsistency is not expertise; it forced the DF community to build Dwarf Therapist and DFHack outside the game. [https://news.ycombinator.com/item?id=13592114]
- **Alert floods and over-interrupting: the DF wiki warns 'don't get ambitious and change all the combat events to Alert, you'll regret it!'; Factorio shipped turret-fire alerts on by default for years and turned them off in 2.0.7 while making ammo warnings sound once.** — If every gate decision pauses or pings, the operator mutes the channel and misses the real denial. Default chatty classes to log-only and reserve pause/modal for a short, curated list. [https://dwarffortresswiki.org/index.php/Announcement]
- **Forward-only history: Factorio replays re-simulate from the input log, so 'There is no way to skip ahead, the entire replay must be watched', 'Re-winding ... is not possible', the view is 'locked to the character', and the replay 'cannot be played' after a version change or mod add/remove.** — A prompt tree that can only be reconstructed by re-running from the root is unusable for time travel and fragile across tool versions. Store checkpoints (snapshots) with parent ids, not just an event tape. [https://wiki.factorio.com/Replay_system]
- **The best fleet view lives in a memory-scraping third party: Dwarf Therapist reads DF memory through version-specific layouts and needs a regenerated therapist.ini (DFHack devel/export-dt-ini) after each DF release; users must click 'Allow labor changes' then 'Commit Changes'.** — If daisugi's operator surface omits the many-agents matrix, someone will build it by scraping journals, and it will break on every schema change. Ship the matrix in-product over a stable, documented store. [https://dwarffortresswiki.org/index.php/Dwarf_Therapist]
- **Feeding the model the human's dense view: FLE authors found dense ASCII world representations 'problematic due to tokenization issues' and fell back to 'sparse encoding'; agents observe only stdout/stderr of their last program.** — 'Every glyph is state' is a human-legibility principle. Sending the cockpit's dense render into the agent's context burns tokens and confuses the model; the agent should get a sparse delta over a stable prefix, the operator gets the glyphs. [https://news.ycombinator.com/item?id=43331582]

## loadBearingClaims
- Dwarf Fortress lets each announcement class be configured independently to show a modal BOX, PAUSE the game, RECENTER the view, appear under the ALERT button, or only be listed (D_DISPLAY), via text flags like [CITIZEN_DEATH:A_D:D_D:UCR_A:ALERT] in announcements.txt. [https://dwarffortresswiki.org/index.php/Announcements.txt]
- Factorio 2.0 undo/redo tooltips describe exactly what will be undone and on which planet or platform, a flying text confirms the undone action, and undoing an action more than a few minutes old triggers a confirmation dialog with a preview. [https://www.factorio.com/blog/post/fff-412]
- Factorio renders chunks outside continuous radar coverage as the last known state, 'a dim image that cannot be zoomed into', while covered chunks update about once per second. [https://wiki.factorio.com/Radar]
- Factorio multiplayer is deterministic lockstep: every peer runs the full simulation and only player actions cross the network; peers quit after 3 desyncs. [https://wiki.factorio.com/Multiplayer]

## verification
- [confirmed] Dwarf Fortress lets each announcement class be configured independently to show a modal BOX, PAUSE the game, RECENTER the view, appear under the ALERT button, or only be listed (D_DISPLAY), via text flags like [CITIZEN_DEATH:A_D:D_D:UCR_A:ALERT] in announcements.txt. — The cited page (documents the current Steam/Premium line, v53.16) defines each flag per announcement type: BOX/DO_MEGA "Causes a box to appear in the middle of the screen, requiring a click on the Okay button to close it"; P/PAUSE "Pauses the game when the announcement occurs"; R/RECENTER "Recenters the game to the location of the announcement when the announcement occurs"; ALERT "Causes the announcement to appear under the alert button at the left side of the screen in fortress mode"; D_D/D_DISPLAY "Causes the announcement to appear under one of the categories at the left side of the screen in fortress mode"; UCR_A "Nearly identical to UNIT_COMBAT_REPORT, but does not create a new report if none are active". The example line [CITIZEN_DEATH:A_D:D_D:UCR_A:ALERT] appears verbatim (message "Lòr Eralamug, Weaponsmith has been found dead."). Each announcement type is its own line in prefs/announcements.txt (defaults in data/init/announcements.txt), so flags are set per class. Two caveats that do not contradict the claim: (1) the classic 0.47.05 page (DF2014 namespace) has NO ALERT flag, its example is [CITIZEN_DEATH:A_D:D_D:UCR_A], D_D there means "displayed at the bottom of the screen in fortress mode", and BOX is closed with Enter, so the ALERT/category-list behaviour is v50+ only; (2) known bug 13034: removing a flag from prefs/announcements.txt does not disable it if it is still enabled in data/init/announcements.txt, both files must be edited. The page also warns that RECENTER without PAUSE "is not recommended, since your screen will recenter without warning."
- [qualified] Factorio 2.0 undo/redo tooltips describe exactly what will be undone and on which planet or platform, a flying text confirms the undone action, and undoing an action more than a few minutes old triggers a confirmation dialog with a preview. — FFF-412 ("Undo/Redo improvements & Car Latency driving", 2024-05-24) supports every element as written: "we added a preview tooltip to the undo and redo shortcut buttons that describes exactly what you're about to undo and on which planet or space platform"; "we added a flying text notification that pops up when you use the undo hotkey"; "when trying to undo an action that is more than a few minutes old, there is a confirmation dialog pop-up"; "Genhis added an awesome visual preview that reveals the entities to be affected, highlights entities to be deconstructed, and shows ghosts of entities to be built." But FFF-412 is a pre-release dev blog. The shipped changelog (wube/factorio-data changelog.txt, Version 2.0.7, Date 20.10.2024, the first public 2.0 build; there is no 2.0.0 entry) says: "Undo improvements. Undo actions older than 1 minute require confirmation +flying text notification of what was undone." and "Added redo." and "Allow undoing of copy-pasting entity settings ... (https://factorio.com/blog/post/fff-412)". So the threshold is 1 minute, not 'a few minutes'. Later fix notes confirm the surface-aware tooltip and confirmation GUI exist in released builds: 2.0.22 "Fixed that undo tooltips could show the wrong surface." and 2.1.15 "Fixed a soft-lock when dying while the undo-confirmation GUI is open." The release changelog does not itself enumerate the visual preview inside the dialog; that detail rests on FFF-412 only. The wiki has no Undo page (404) and the Shortcut bar page only says the bar has icons for "Initiating Undo, Redo, Cut, Copy and Paste blueprint operations". → corrected: Factorio 2.0 undo/redo shortcut tooltips preview what will be undone and on which surface (planet or space platform); a flying text confirms what was undone; and undoing an action older than 1 minute (per the shipped 2.0.7 release changelog; the pre-release FFF-412 said 'a few minutes') opens a confirmation dialog, which FFF-412 describes as including a visual preview that highlights entities to be deconstructed and ghosts to be built.
- [confirmed] Factorio renders chunks outside continuous radar coverage as the last known state, 'a dim image that cannot be zoomed into', while covered chunks update about once per second. — The cited page says verbatim: "The last known state of the chunk will be visible on the player's map as a dim image that cannot be zoomed into." and, for the continuous 7x7-chunk (224x224 tile) area, "This nearby area is updated as a single pulse, approximately every second if the radar is fully powered." Exploration scanning is separate: "Radars also periodically scan chunks in a much bigger range of 29x29. The radar charts one distant chunk every time the sector scanning progress bar fills. This takes 33.333 seconds if the radar is receiving full power", and "Once a chunk is scanned, it is revealed for 10 seconds" before dropping to last-known-state. Currency check: the page history shows edits on 17 Aug 2026 (Bilka), 8 Aug 2026 ("2.1.7 changes"), and a 6 Jun 2026 rewrite to "correct outdated info, add some info about quality"; the 2.1.7 change is only "Added 'universe' mode of operation to radar circuit connections for transfer of cross-surface signals", so the update-rate and dim-image statements are current for 2.1.x. Minor precision notes: live coverage is not only from radars ("Players, roboports, and spidertrons similarly chart an area of 5x5 chunks (160x160 tiles) around them"), and in Space Age higher-quality radars reveal larger continuous and exploration areas.
- [qualified] Factorio multiplayer is deterministic lockstep: every peer runs the full simulation and only player actions cross the network; peers quit after 3 desyncs. — Lockstep + full simulation + actions-only is supported. Cited Multiplayer page: "Because of the potentially immense amount of activity on a map, the game engine utilizes a lock step architecture. All instances of the game run full simulations of the entire world and only player actions are transferred across the network." and, on the client-server model since 0.13, "all clients send their network traffic to the server and the server forwards the traffic to the other clients". The word "deterministic" does not appear on the Multiplayer page, but the wiki Desynchronization page says "Factorio multiplayer code uses deterministic lockstep to synchronize clients. This is a method of synchronizing a game from one computer to another by sending only the user inputs that control that game" and "all players' games need to simulate every single tick of the game identically"; FFF-302 (2019-07-05) says "all clients simulate the game state and they only receive and send the player input (called Input Actions)". The '3 desyncs' part is stale: on the Multiplayer page the sentence "Players automatically quit game after 3 desyncs." sits only in the Version History list under the 0.14.0 entry, not in the descriptive body. The official changelog (wube/factorio-data changelog.txt) has 0.14.0 (26.08.2016): "Players automatically quit game after 3 desyncs.", 0.14.4: "Fixed crash related to reconnecting to a game after 3 desyncs", and then 0.16.0 (13.12.2017): "After desynching in multiplayer, the game will not automatically connect back, instead a dialog with more information will be shown." The current Desynchronization page describes that behaviour: "When a client detects a desync, it disconnects the player and starts to download files from the server (map and game state information)" and "the player is offered the options to view the report, quit or reconnect to continue playing", with no mention of a desync count. → corrected: Factorio multiplayer is deterministic lockstep: every client runs the full simulation and only player input actions cross the network (relayed through the server since 0.13). The 'automatically quit after 3 desyncs' rule was 0.14.0 (Aug 2016) behaviour and was superseded in 0.16.0 (Dec 2017): any detected desync disconnects the client immediately, it re-downloads the map from the server, and is offered view-report / quit / reconnect; there is no three-strike rule in current versions.
