# Speech to text for the voice bridge (research, 2026-10-01)

A deep-research run: five search angles, sources fetched, each claim checked by three adversarial votes. Every source was read on 2026-10-01.

## Question

Speech-to-text (STT/ASR) models and runtimes for openDaisugi's voice bridge, as of late 2026, including models released in the past year and the past few weeks. Context: a local-first, privacy-first FLOSS tool for AI coding agents; push-to-talk dictation into a terminal agent pane; today it uses faster-whisper tiny.en (CPU int8) with optional whisper.cpp and Parakeet-TDT via sherpa-onnx. The voice bridge is being ported to Go and Rust, so the engine should run as an external binary or small native runtime without Python. Hard constraints: (1) open weights under a permissive license (MIT/Apache/BSD style; flag any non-commercial or custom restrictive clause); (2) provenance: who built the model, who built the runtime, where weights are hosted; EXCLUDE China-based developers or runtimes and say so explicitly per candidate (also check whether k2-fsa/sherpa-onnx is China/Xiaomi-linked); (3) runs fully locally on a Linux desktop CPU (GPU optional; the GPU here is a GTX 1060 6GB) AND on a phone (Android at least; iOS noted), e.g. via whisper.cpp/GGUF, ONNX Runtime, ExecuTorch, LiteRT, Core ML; (4) quality and speed: published WER (English, e.g. Open ASR Leaderboard) and real-time factor versus Whisper tiny.en/base.en/large-v3-turbo and distil-whisper; streaming support for push-to-talk; model size. Candidates to check include but are not limited to: Whisper large-v3-turbo, distil-whisper, Moonshine (Useful Sensors), NVIDIA Parakeet/Canary, Kyutai STT, Mistral Voxtral, IBM Granite Speech, Microsoft Phi-4-multimodal, Google Gemma/USM-based, Meta MMS/Omnilingual ASR, and any notable new open STT models from 2026. Also survey wrappers and apps and what engines they use: Handy (open-source, cjpais/Handy), Wispr Flow (commercial dictation), superwhisper, MacWhisper, Buzz, and others; note their privacy model. Cloud options as opt-in only: Fireworks AI (their ASR/streaming transcription offering), ElevenLabs Scribe, Deepgram, AssemblyAI, OpenAI gpt-4o-transcribe: data retention and training-use terms. End with a ranked recommendation: default local engine for desktop, default for phone, an upgrade option, and an opt-in cloud option, with sources for every claim.

## Summary

(Update, later on 2026-10-01: with the engine resident, Parakeet-TDT-0.6B v2 on CrispASR's Parakeet code became the desktop default, Moonshine small the fallback, and faster-whisper tiny.en the tiny tier; see "Measured again with the resident engines" and rulings VO-16 and VO-17. The ranking below is the run's own.)

Moonshine v2 from Moonshine AI (formerly Useful Sensors, US) is the best fit for the default engine on both desktop and phone. Its streaming models are MIT-licensed. It runs CPU-only on Linux, Android and iOS through a C++ core with a C API, so Go (cgo) and Rust (FFI) can call it without Python. Its compute scales with clip length, which suits push-to-talk. Moonshine v2 Medium (245M) reports 6.65% average English WER on the Open ASR Leaderboard, against 7.44% for Whisper large-v3. Small (123M) reports 7.84% and Tiny (34M) 12.01%. The vendor reports 50 to 258 ms latency on an M3 CPU. NVIDIA Parakeet-TDT-0.6B v2 (US, CC-BY-4.0) is the accuracy upgrade at 6.05% WER, but it needs a non-NeMo runtime. Meta's ExecuTorch demo runs it on Android at INT4 without sherpa-onnx. sherpa-onnx (k2-fsa) is Xiaomi/Beijing-linked, so the China-exclusion rule removes it. The current Parakeet path in the voice bridge uses sherpa-onnx, so it needs replacing. Handy is desktop-only, so it answers nothing for phones. No cloud option (Fireworks, ElevenLabs, Deepgram, AssemblyAI, OpenAI) survived verification, so the opt-in cloud recommendation is still open. Ranked recommendation: (1) desktop default is Moonshine v2 Small streaming, with Medium as an option; (2) phone default is Moonshine v2 Tiny or Small streaming through the same C API; (3) the upgrade is Parakeet-TDT-0.6B v2 through ExecuTorch on Android, or a non-sherpa ONNX export on desktop, with whisper.cpp kept as the existing fallback; (4) cloud is not decided because nothing survived verification.

## Measured on this box (real speech, 2026-10-01)

Everything in this section was measured here, on the box of the synthetic table above (Intel Core i5-7300HQ, 4 cores, CPU only with `CUDA_VISIBLE_DEVICES=""`, each run alone under a 4 GB memory cap). Every number in the table was measured here. The few vendor or leaderboard figures quoted in the notes under it are marked as such; those figures, and the ones in the findings below and in the second pass, are not comparable with these: they are batched GPU throughput or full test sets.

**Speech.** LibriSpeech test-clean and test-other from openslr.org (resource 12, CC-BY-4.0). openslr publishes MD5 only; both archives matched its `md5sum.txt` (test-clean 32fa31d2..., test-other fb5a5037...). Their SHA-256: test-clean 39fde525e59672dc6d1551919b1478f724438a95aa55f874b576be21967e6c23, test-other d09c181bba5cf717b3dee7d4d592af11a3ee3a09e08ae025c5506f6ebe961c29. test-clean came from www.openslr.org; test-other from the openslr.trmal.net mirror, because the main host was slow; its MD5 is the one openslr lists. From each set, 100 utterances were chosen with `random.Random(20261001).sample` over the sorted utterance IDs (100 of 2,620 and 100 of 2,939), and converted with ffmpeg to 16 kHz mono 16-bit WAV. The archives were then deleted. test-clean has 800 s of speech and 2,190 reference words; test-other 710 s and 1,930 words. 23 and 26 of the clips are 4 to 6 s long. `scripts/stt_bench.py` does the selection, the runs and the scoring. The C program on CrispASR's Parakeet API and the converter check of the second pass were scratch tools of this run and are not in the repo.

**WER.** The Open ASR Leaderboard's normalizer: Whisper's `EnglishTextNormalizer` (transformers 5.16.1) on both the reference and the hypothesis, then word edits over reference words, summed over all 100 clips. The leaderboard also maps British to American spelling; no copy of that map is on this box, so the map was empty here. With about 2,000 words a set, one word is 0.05 points, so differences under about 0.5 points are noise (Parakeet Q4_K against Q8_0 is one of those).

**Engines.**

- faster-whisper 1.2.1 (CTranslate2 4.8.2), int8, 4 threads, beam 5 (its default, as the voice server runs it). The model loads once; the time is one `transcribe` call.
- Moonshine small: `moonshine-cli` as VO-13 builds it, one process per clip, greedy decoding.
- Parakeet-TDT-0.6B v2 and Phonon-2 on CrispASR: a small C program on CrispASR's Parakeet API (`parakeet_init_from_file`, `parakeet_transcribe`), built from five CrispASR files and the ggml CPU backend at the commit in the provenance section of the second pass. zig 0.16 clang, Release, AVX2, FMA, F16C and BMI2 (x86-64-v3 class), no OpenMP, no BLAS, flash attention on, 4 threads, greedy TDT decoding. One process per clip (as a voice engine would run), and also one resident process that loads once. Parakeet Q4_K is the one this box made from the verified F16 (the Q4_K the GGUF repo recommends); Q8_0 is the published file, which this box reproduced byte for byte. Phonon-2 Q8_0 is the published file, the quant its GGUF repo recommends.
- Kyutai stt-1b-en_fr: not run. See the ruling below the table.

- Parakeet v2 and Phonon-2 are far more accurate than every engine the voice bridge has now, on both sets: Parakeet v2 makes about 2.4 to 3.5 times fewer errors than tiny.en. - None of them meets the latency bar the brief sets (a 5 s utterance under about 1.0 s, median) in the shape a voice engine would run, one process per clip: Parakeet v2 takes 1.22 to 1.30 s, Phonon-2 1.12 s. ## Verified findings

- **high** (3-0 (merged from claims 3, 5)): Moonshine v2 matches or beats Whisper large-v3 on English WER at a much smaller size. Tiny is about 34M parameters (12.01% average WER), Small about 123M (7.84%) and Medium about 245M (6.65%). Whisper large-v3 is 1.5B parameters at 7.44%.
  - Evidence: Moonshine v2 paper (Feb 2026) Tables 1 and 3; the developer's announcement post; the HF card moonshine-streaming-medium shows 6.65 (summary line 6.66). The Whisper large-v3 figure of 7.44 comes from the independent Open ASR Leaderboard paper. The Moonshine numbers are self-reported on the leaderboard datasets. Newer models such as Parakeet still score lower WER.
  - Sources: https://arxiv.org/html/2602.12241v1, https://petewarden.com/2026/02/13/announcing-moonshine-voice/, https://arxiv.org/html/2510.06961v3

- **medium** (3-0 (merged from claims 2, 4, 16)): For push-to-talk, Moonshine v2 has far lower latency than Whisper on CPU, because it streams and its compute scales with audio length. Whisper pads every input to 30 s. Vendor-measured latency on an Apple M3 CPU: Tiny 50 ms (5.8x faster than Whisper Tiny), Small 148 ms (13.1x faster than Whisper Small), Medium 258 ms (43.7x faster than Whisper large-v3). Moonshine Tiny (v1 family) has 27.1M parameters and needs 0.7x the FLOPs of Whisper Tiny.
  - Evidence: Moonshine v2 Table 2; Flavors of Moonshine Table 2 and section 2.1; the README says models are 'optimized for live streaming, with low latency by doing work while the user is still talking'. Latency is measured from end of speech. Only the vendor measured it, with no independent reproduction. Whisper ran under faster-whisper and Moonshine under ONNX Runtime. The baseline was large-v3, not large-v3-turbo or distil-whisper. The README cites a different Medium figure (107 ms). A broader '5x-15x faster' claim was refuted 1-2.
  - Sources: https://arxiv.org/html/2602.12241v1, https://arxiv.org/pdf/2509.02523, https://github.com/moonshine-ai/moonshine

- **high** (3-0 (merged from claims 1, 6, 14)): Moonshine code and models are MIT by default in every language and size. The streaming models are MIT. The only exception is the legacy non-streaming models for languages other than English, which stay under the non-commercial Moonshine Community License. The 'Flavors of Moonshine' paper calls its non-English models 'permissive', but those are exactly the legacy models, so the paper's own models fail the permissive-only constraint.
  - Evidence: The README states the MIT default and the Community License exception. Warden's post says 'code and streaming models are released under an MIT License'. The HF card moonshine-tiny-ar shows only 'license: other'. Downstream fixes (cstr/moonshine-base-ja-GGUF, pipecat PR #5745) agree. Older pages describe an earlier, stricter split. Before shipping, check the LICENSE on each HF model card.
  - Sources: https://github.com/moonshine-ai/moonshine, https://petewarden.com/2026/02/13/announcing-moonshine-voice/, https://arxiv.org/pdf/2509.02523

- **high** (3-0 (merged from claims 7, 15)): Moonshine Voice runs fully on-device and CPU-only, with no NPU or GPU needed, on Android, iOS, Linux, macOS, Windows, Raspberry Pi, JS/WASM and Python, behind one API. Its core is C++ on ONNX Runtime and exposes a C API (moonshine-c-api.h). Go and Rust can wrap that API without Python. There are no official Go or Rust bindings yet.
  - Evidence: The README says 'Everything runs on-device — fast, private, and with no account or API keys'. The repo /core has the C API and its tests, plus ort-utils. The announcement lists the same platforms and says 'no NPU or GPU dependencies'. Provenance: Moonshine AI / Useful Sensors (US). The runtime is ONNX Runtime (Microsoft, US).
  - Sources: https://github.com/moonshine-ai/moonshine, https://petewarden.com/2026/02/13/announcing-moonshine-voice/

- **high** (3-0 (merged from claims 0, 17, 18)): NVIDIA Parakeet-TDT-0.6B v2 is the most accurate small open English model in the verified set. It scores 6.05% average WER (LibriSpeech clean 1.69%, other 3.19%). v3 (multilingual) scores 6.32%. Both run at about 3,300x RTFx, about 23x the throughput of Whisper large-v3 (7.44%, 145 RTFx) in the same harness. The v2 weights are CC-BY-4.0: attribution is required, there is no non-commercial clause, and there is no patent grant. NVIDIA (US) develops it. The RTFx figure is batched A100 throughput (batch 64 to 128), not single-stream speed on a CPU or phone.
  - Evidence: Open ASR Leaderboard paper (Hugging Face authors, Dec 2025) Table 3; the NVIDIA model card's WER table and license line ('ready for commercial/non-commercial use'). Distil-Whisper large-v3.5 is 7.21 WER / 202 RTFx. Large-v3-turbo is not in Table 3. The v3 license was not checked separately.
  - Sources: https://arxiv.org/html/2510.06961v3, https://huggingface.co/nvidia/parakeet-tdt-0.6b-v2

- **medium** (3-0 (merged from claims 8, 19)): Parakeet's reference runtime is NeMo (Python) on Volta, Ampere, Hopper and Blackwell GPUs. The GTX 1060 (Pascal) is not listed. A Python-free CPU or phone deployment needs a third-party export. Meta's ExecuTorch examples include an Android app that runs Parakeet TDT 0.6B at INT4 as a .pte program, with no sherpa-onnx. That gives an Android path that avoids the China-linked runtime.
  - Evidence: The model card lists 'Runtime: NeMo 2.2' and the supported GPU families. The ExecuTorch README says the app downloads 'Parakeet TDT 0.6B (INT4)' plus tokenizer.model from HuggingFace. It is a demo only: no latency, WER, device requirements or license for the INT4 weights are given. Parakeet TDT is non-streaming in most exports.
  - Sources: https://huggingface.co/nvidia/parakeet-tdt-0.6b-v2, https://github.com/meta-pytorch/executorch-examples/tree/main/parakeet/android/ParakeetApp

- **high** (3-0 (merged from claims 9, 10, 11, 12, 13)): sherpa-onnx is technically a good fit: ONNX Runtime underneath; Linux, Windows, macOS, iOS, Android and WASM; C, C++, Go, Kotlin, Swift and other APIs; streaming and non-streaming ASR plus TTS. But it fails the provenance constraint. k2-fsa / Next-gen Kaldi (k2, icefall, sherpa) is developed at Xiaomi AI Lab in Beijing under Daniel Povey. So it is excluded, and openDaisugi's current Parakeet-via-sherpa-onnx path needs a replacement.
  - Evidence: The sherpa docs give the platform and feature table but credit only the 'sherpa development team'. Core developer Wei Kang's homepage says 'I work at Xiaomi AI lab as a senior engineer now, developing the Next-gen Kaldi under the leadership of Daniel Povey'. Wikipedia, Synced Review and a 2023 Xiaomi X post back up Povey's Xiaomi role. The code is Apache-2.0. A claim that sherpa was started in June 2022 by this team was refuted 0-3, though the Xiaomi link itself stands.
  - Sources: https://k2-fsa.github.io/sherpa/intro.html, https://pkufool.github.io/

- **high** (3-0 (claim 20)): Handy (cjpais/Handy, open source) runs only on Windows, macOS and Linux. It has no Android or iOS app, so it gives no phone path. Its exact engine list (Whisper sizes plus Parakeet V3) was not confirmed.
  - Evidence: The README says 'Works on Windows, macOS, and Linux'. Third parties (getvoibe.com, portableapps.com) agree there is no mobile app. A claim about Handy's local engines was refuted 0-3. The user's 'Handy.ai' probably means this project; that was not verified.
  - Sources: https://github.com/cjpais/Handy

## Caveats

Most of the Moonshine performance numbers come from Moonshine AI itself, and nobody has reproduced them independently. The license facts come from primary sources and are solid. The latency comparisons favour Moonshine because they compare a streaming model with batch Whisper on CPU and use large-v3 rather than large-v3-turbo. Parakeet's RTFx is batched datacenter throughput and says nothing about phone or GTX 1060 speed. CC-BY-4.0 is a content license with no patent grant. It is permissive, but it is not MIT or Apache, and it requires attribution. Much of the requested scope did not survive verification or was never checked: Kyutai STT, Mistral Voxtral, IBM Granite Speech, Phi-4-multimodal, Gemma/USM, Meta Omnilingual ASR, distil-whisper and large-v3-turbo on CPU, Canary (a leaderboard-ranking claim for Canary-Qwen and Granite was refuted 0-3), Wispr Flow, superwhisper, MacWhisper, Buzz, and every cloud provider's retention and training terms. So the recommendations rest on a narrow verified base, and the cloud opt-in pick has no evidence behind it. All sources were read on 2026-10-01. Moonshine v2 is from Feb 2026 and the leaderboard paper from Dec 2025, so models released in the last few weeks may be missing.

## Open questions

- Which opt-in cloud STT has acceptable terms? This means zero retention and no training on user audio. Candidates are Fireworks AI streaming ASR, ElevenLabs Scribe, Deepgram, AssemblyAI and OpenAI gpt-4o-transcribe, and none were verified.
- Is there a non-China, Python-free way to run Parakeet-TDT on desktop CPU? Options include a direct ONNX export run on plain ONNX Runtime from Go or Rust, or ExecuTorch on Linux. What single-stream latency does it reach on this box's CPU and on a mid-range Android phone?
- Do newer 2026 open models beat Moonshine v2 for on-device push-to-talk while staying permissively licensed and non-China? Candidates are Kyutai STT, Voxtral Mini, Granite Speech and Omnilingual ASR.
- What engines and privacy model does Wispr Flow use (it is believed to be cloud-processed), and does Handy's Parakeet option depend on sherpa-onnx or another China-linked runtime?

## Refuted claims

- (0-3) On the Open ASR Leaderboard's English average, NVIDIA Canary-Qwen-2.5B ranks first at 5.63% WER (RTFx 418). IBM Granite Speech 3.3 8B follows at 5.74% and Granite Speech 3.3 2B at 6.00%. All three beat OpenAI Whisper large-v3 at 7.44% WER. (https://arxiv.org/html/2510.06961v3)
- (1-2) In on-device use, the Moonshine models run 5x to 15x faster than Whisper. (https://arxiv.org/pdf/2509.02523)
- (0-3) The sherpa, sherpa-onnx and sherpa-ncnn runtime projects were started in June 2022 by this Xiaomi-based team. (https://pkufool.github.io/)
- (0-3) Handy's local engines are Whisper models (Small/Medium/Turbo/Large) with GPU acceleration when available, plus a CPU-optimized Parakeet V3 model with automatic language detection. (https://github.com/cjpais/Handy)
