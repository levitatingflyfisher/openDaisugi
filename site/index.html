The check

An allowed action runs, and a refused one is told its rule.

The envelope is a short file of rules for one task. A model drafts it, you can read it and tighten it, and Z3, a solver, does the checking. After a refusal the agent gets the rule and proposes another action; a robot takes its next plan.

A refusal names its rule.

The rule, in the envelope

permissions:
  file_read:
    - ".../workspace/**"

The action, refused

DENIED Read '.../infra/deploy_region.txt'
  reason: permissions: Step 's0' file_read path
  '.../infra/deploy_region.txt' not permitted
  by file_read ['.../workspace/**']

From a recorded run: an agent tried to read a file outside its workspace, and the read never happened. The full transcript.

Robots

A robot’s plan is checked the same way.

Simulation: a scripted planner drives, and the simulator gives the person’s position. What is proved and what is judged.

A planner offers several plans, and each one is checked before the robot moves. Refused plans are drawn in red and the accepted plan in green.

Formal methods you can use

It checks the actions an agent takes.

Most formal tools prove that a program is correct. openDaisugi proves that each action stays inside the envelope, whatever model made the plan.

A JIT compiler for agent work

Repeated work moves down to code.

The first time, a large model does the task. When the same task has come back three times, its steps become a checked script that runs with no model call.

New work is planned by a model, and a repeat is reused.

Both paths go through the same check against your envelope.

What it does today.

  • Checks every tool call of an agent against an envelope, and records each call and verdict.
  • Proves that an agent started by another agent can only have tighter rules than its parent.
  • Turns repeated tasks into signed scripts that run with no model call.
  • Checks robot motion plans in simulation.

Roadmap

Questions

Questions people ask.

My agent already has a sandbox and permission prompts. Why add this?

A sandbox limits where code runs, and a prompt asks you each time. This checks each action against rules written for the one task, with a solver, the same way for every agent.

Isn’t this just file access control?

No. The rules also cover shell commands, network hosts, token budgets and which agent may start which. In simulation they cover robot limits such as workspace bounds and speed.

Who writes the envelope?

A model drafts it from the task, or you write it. Z3 only checks, so a wrong draft can refuse too much or allow too much, and you can read it to see which.

What does the proof not cover?

It covers actions, not what the model understood, and it trusts what the sensors report. The whitepaper says exactly what is proved.

Why the name?

Daisugi (台杉) is a Japanese forestry technique: straight new timber grows from the trunk of an existing tree.

Install

Install openDaisugi on Linux.

Six steps on Linux. The first build compiles Z3, which happens once.

You need git, a C toolchain, Go, curl and Python. The script asks before it writes to any agent’s settings, and the checker starts by watching: it logs what it would refuse and blocks nothing. What it touches, and how to make it block.

  1. Install the packages for your system.

    Omarchy and Arch

    sudo pacman -S --needed git base-devel pkgconf go curl python

    Fedora

    sudo dnf install git gcc gcc-c++ make pkgconf-pkg-config golang curl python3 binutils

    Debian 13 and Ubuntu 24.04 or later

    sudo apt install git build-essential pkg-config golang-go curl python3 binutils xz-utils

    Older Debian and Ubuntu ship a Go below 1.21. Install a newer Go from go.dev/dl first.

  2. Get the code.

    git clone https://github.com/levitatingflyfisher/openDaisugi.git
cd openDaisugi

  3. Build and install.

    scripts/install.sh

    Make sure ~/.local/bin is on your PATH.

  4. Connect the checker, called the warden, to your agent.

    daisugi install

    It lists its writes for each agent it finds and asks first.

  5. In your project directory, write a starter envelope.

    daisugi warden init

  6. After a session, see what it would refuse.

    daisugi warden report

Undo it

daisugi install --uninstall
rm ~/.local/bin/coppice ~/.local/bin/sprig ~/.local/bin/daisugi
